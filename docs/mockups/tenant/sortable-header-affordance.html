並び替えできる列を分かるようにする — モック3案

テナント管理 /tenant/area-buildings（周辺ビル調査）の表で確認。
並び替えの挙動（3 状態・「—」は末尾・フィルタ共存）は docs/superpowers/specs/2026-08-25-tenant-list-sorting-design.md のまま変えない。 ここで選ぶのは見た目だけ。

並び替えできる列＝総階数 / 営業 / 空き / 不明 / 入居率 / 空室率 / 最終調査 の 7 列。 ビル名 / 位置 / 操作 は並び替え不可。各表の見出しは実際に押せます（既定 → 降順 ▼ → 昇順 ▲ → 既定 の 3 巡）。

現状今の見た目（＝分かりにくいと言われている状態）

未使用の列の ⇅ は #D1D5DB（gray-300）で、見出しの背景 #F9FAFB との コントラスト比は 約 1.4:1。UI 部品に必要な 3:1 を大きく下回り、実質見えていない。 手掛かりは「ホバーすると背景が薄く変わる」だけなので、マウスを乗せるまで押せると気づけない。

  • ⇅ が薄すぎて見えない（1.4:1）
  • ホバーするまで分からない
  • 既定順のときは、どう並んでいるか画面のどこにも出ない

A案A: アイコンを濃くする ＋ ラベルに点線の下線

⇅ を #D1D5DB → #6B7280（gray-500・4.8:1）にして、 ラベルに薄い点線の下線を敷く。「押せる文字」だと分かる最小の合図。 ホバーで下線が濃くなり、並び替え中の列は下線ごと緑になる。 変更は sortable-th.blade.php の色 2 箇所＋text-decoration だけ。

  • 既存の見た目をほぼ保つ・行の高さが変わらない
  • 実装が最小（共通コンポーネント 1 ファイル）
  • 10 列の表でも密度が上がらない
  • 3 案の中では一番おとなしい

B案B: 見出しを「チップ（ボタン）」の形にする

ラベルと ⇅ を枠線つきの小さなチップで囲む。押せることが色ではなく「形」で分かるので、 並び替え不可の素の見出し（ビル名・位置・操作）との差が一目でつく。並び替え中は緑のチップになる。 当たり判定はセル全体のまま（チップは見た目だけで、リンクはセルいっぱいに広がる）。

  • 押せる／押せないの差が最もはっきりする
  • 現在の並び順（緑のチップ）が遠目でも分かる
  • 見出し行がやや賑やかになる（10 列中 7 列がチップ）
  • テストヘルパ sortLinkFor() の正規表現を 1 行広げる必要がある

C案C: 見出しセルを塗り分ける ＋ 表の上に「現在の並び順」バー

並び替えできる列の見出しだけ白背景＋下辺 2px のグレーの線にして、 できない列（従来のグレー背景）と塗り分ける。さらに表の上に今の並び順を文で出すので、 横スクロールで見出しが視界から外れても、また既定順のままでも「今どう並んでいるか」が分かる。 並び替え中は見出しが薄緑＋下辺が緑になり、バーに解除ボタンが出る。

  • 既定順（空室率が高い順）も画面に出る＝現状で唯一どこにも出ていない情報が見える
  • 解除が 1 クリック（3 巡させなくてよい）
  • 横スクロール中でも並び順が分かる
  • 要素が 1 つ増える（表の上のバー）
  • 見出し行が 2 色に割れるので、好みが分かれる

採用案A ＋ 案C（合成）

ご指定の組み合わせです。 案A（濃い ⇅ ＋ 点線下線）の上に、案C の 2 要素 ——見出しの塗り分けと表の上のバー——を重ねています。
案C の「塗り分け」だけは下のスイッチで外せます。外すと 案A ＋ 案C のバーだけ（見出しは従来のグレーのまま・現在の並び順は文で出る）になります。 どちらにするか決めてください。
