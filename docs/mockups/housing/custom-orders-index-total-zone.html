黄色い 2 行 — 積み上げ方式で「片側だけ未入力」だとこう出ます（先行 2 画面と同一挙動）

  • ルールは 先行 2 画面と 1 文字も変えない: ($b !== null || $l !== null) ? ($b ?? 0) + ($l ?? 0) : null。 片方が未入力なら 0 円として合算されます。
  • 北条E様邸（建物原価だけ未入力）… 合計原価が土地ぶんだけの 9,800,000円 になり、 合計粗利 33,200,000円 が過大に出ます（建物粗利は「—」なのに合計だけ緑）。
  • 新居浜G様邸（土地販売金額だけ未入力）… 合計販売が建物ぶんだけの 29,000,000円 になり、 合計粗利 -1,500,000円 が過小に出ます （建物 +7,000,000円（緑）と 合計 -1,500,000円（赤）が同じ行に並びます）。
  • ⚠ お客様所有土地は「未入力」ではありません（見奈良B様邸）。isCompanyLand() が false の行は土地 4 セルが「—」で、建物だけで合計が成立します。 生カラムに land_cost が残っていても合算しません — ここは積み上げ方式が正しく効く部分です。
  • ⚠ 4 つの金額カラムはすべて nullable（CustomOrderController::validateOrder で実測）＝ この 2 行は実際に保存できる状態です。ローカル DB は注文住宅 0 件のため、 本番での発生件数は未確認（Bug #22/#25/#27 と同じ「実データが特定の形の時だけ出る」型）。

#項目内容
1レイアウト2 段ヘッダーで「合計」「建物」「土地」をグループ化。全 14 列（現行 11 列 + 3）
2グループ順合計 → 建物 → 土地（先行 2 画面と同じ）

5未入力時の合計先行 2 画面と完全に同じ積み上げ式を使う — ($b !== null || $l !== null) ? ($b ?? 0) + ($l ?? 0) : null。
片側だけ未入力なら 0 円扱いで合算される（黄色い 2 行）。3 画面で挙動を揃えることを優先
6消費税合計・建物の販売金額に税込サブ行。土地は非課税なので税は建物ぶんだけ
7合計ゾーンの配色レッド（契約管理と同じ）。見出し #fee2e2 / 文字 #991b1b / 地色 #fef2f2

9列の順序現行どおり 進捗 → 案件名（最小差分。建売物件一覧は 物件名 → 進捗 で逆だが揃えない）
