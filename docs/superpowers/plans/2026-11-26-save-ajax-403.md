# 保存の Ajax の 403 に日本語の理由を出す・一般担当にランクを押させない 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans（推薦。Native）か superpowers:subagent-driven-development。手順は `- [ ]` で追う。

**Goal:** 番号だけを出していた保存の Ajax 8 か所が、403 のときに「{動作}できませんでした。」＋サーバーの日本語の理由を出す。買主一覧のランクのバッジは、経営層・管理者にだけ押せる形で出す。

**Architecture:** 新しい Blade 部品 `_partials/_ajax_save_failure` に JS の関数 `ajaxSaveFailureMessage(status, body, failed, fallback)` を 1 つ置き、6 つの画面ファイルと XHR の部品がそれを呼ぶ（取得の部品 `_partials/_ajax_get_failure` と同じ形）。サーバーの応答は変えない。

**Tech Stack:** Laravel 12 Blade・素の JS（Alpine の x-data 関数と XMLHttpRequest）・PHPUnit＋node の vm（`Tests\Concerns\DrivesAlpineFetch::driveAlpine()`）。

**Spec:** `docs/superpowers/specs/2026-11-26-save-ajax-403-design.md`（作業場所 `.claude/worktrees/save-ajax-403`・ブランチ `save-ajax-403`・`35813117`）

## Context

Bug #137 の直しで保存の Ajax の 419・401 は日本語の理由を出すようになった。一方 8 か所は、403 のときに「ランクを変更できませんでした（403）」のように番号だけを出す。サーバーは日本語の理由つきの JSON を返している（`CheckRole`「このページへのアクセス権限がありません。」／`CheckDepartmentAccess`「この部門のデータへのアクセス権限がありません。」／`RestrictApprovalOnlyUsers`「決裁以外の画面は使えません。」）。

買主一覧（`resources/views/buyers/index.blade.php`。住宅事業・不動産で共用）のランクのバッジは一般担当にも押せる形で出ている。一覧は一般担当も開けるが、`PATCH api/customers/{buyer}/rank` は `role:executive,manager` なので、普段の操作で必ず 403 になる（Bug #96 と同じ形）。利用者の決定（2026-11-26）: バッジは案 A（一般担当は見るだけ）・作り方は 1（共通の部品）。

## Global Constraints

- 403 の文の決まり: 419・401 で本文の `message` が空でない文字 → その `message` だけ（今と同じ）／403 で `message` に ASCII 以外の文字（`/[^\x00-\x7f]/`）がある → `failed`＋`message`／ほか → `fallback`
- 8 か所の `failed`（403 のときの前半）と `fallback`（今の番号つきの文。変えない）:

| # | 呼ぶ所 | failed | fallback |
|---|---|---|---|
| 1 | `realestate/procurements/index` `realestateStatusCell` | `ステータスを更新できませんでした。` | `ステータスの更新に失敗しました（N）` |
| 2 | `realestate/projects/index` `projectStatusCell` | 同上 | 同上 |
| 3 | `housing/properties/index` `housingPropertyStatusCell` | `進捗ステータスを更新できませんでした。` | `進捗ステータスの更新に失敗しました（N）` |
| 4 | `housing/contracts/_buyer-select` `checkDup` | `重複を確認できませんでした。` | `重複チェックに失敗しました（N）` |
| 5 | 同 `submitModal`（422 の分岐は今のまま先） | `登録できませんでした。` | `登録に失敗しました（N）` |
| 6 | `realestate/_partials/supplier-picker` 簡易登録（419 の独自の文は今のまま先） | `登録できませんでした。` | `登録に失敗しました（N）` |
| 7 | `buyers/index` `selectRank`（XHR） | `ランクを変更できませんでした。` | `ランクを変更できませんでした（N）` |
| 8 | `buyers/_form` `addToDepartment`（XHR） | `この部署に取り込めませんでした。` | `この部署に取り込めませんでした（N）` |

- 仕入れ案件の小窓の 422（Bug #139）は今のまま先に見る。
- サーバーの応答・ルート・DB は変えない。新しい PHP クラスは無い（本番反映は `./deploy.sh` だけ）。
- 部品の script の中に「fetch」に丸括弧を続けた字・アットマークで始まる語・`<x-` を書かない（説明は Blade コメントへ。Bug #30・Ajax の走査）。
- テストの流し方は CLAUDE.md の形（`APP_KEY=… /opt/homebrew/opt/php@8.3/bin/php -d opcache.enable_cli=1 -d opcache.memory_consumption=256 vendor/bin/phpunit --display-phpunit-deprecations`）。作業場所の cwd で、scratchpad のスクリプトから起動する。

## Review Focus

1. 403 でも本文が HTML（サーバーの手前で断られた・本文が JSON でない）→ 番号つきの今の文。→ 各画面の `…answered_with_html…`／`…not_json…` テストに 403 を足す（Task 2〜4）
2. 403 の `message` が英語（`This action is unauthorized.`）か空 → 番号つきの今の文。→ Task 1 の決まりのテスト
3. 部署を外された（`この部門の…`）と役割が変わった（`このページへの…`）の両方の文が、組み立てで崩れない。→ Task 2（部署）・Task 3〜4（役割）で両方を本物の応答で見る
4. 一般担当が開いた買主一覧に、ランクの小窓の要素と script が描かれない（押しても何も起きない形にしない）。→ Task 4 の役割ごとのテスト
5. 部品を読み込まない画面（ブラウザでは関数が無くて止まる）。→ Task 5 の走査
