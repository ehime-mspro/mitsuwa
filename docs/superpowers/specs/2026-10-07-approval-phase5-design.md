## 1. 目的と範囲

**目的**: 住宅事業部とミツワ不動産が契約のときに使う紙の様式（金額の明細表）をシステムの申請で書けるようにし、紙の決裁台帳（年度ごとの .xls）を取り込んで、過去の決裁もシステムの台帳から探せるようにする。

**できたと言える状態**（利用者と確かめた）
- ⑨ で住宅の契約用の種類（要件 5.5.7）を設定でき、申請の画面 → 詳細・変更点 → PDF → 台帳・Excel まで明細表と追加の欄が通る
- 08 年度の台帳を ⑪ で取り込み、台帳で年度・部門・日付・申請者・件名から探せる
- 段階6（本番への先行公開と受け入れ確認）に入れる

### 1.1 作り方（D1）

段階4 と同じく、**設計書はこの 1 本、作るのは 2 回**に分ける。それぞれ、できたら本番へ出す。

| 回 | 中身 | 節 |
|---|---|---|
| **5a** | 種類ごとの作り込み: ⑨ の種類の設定 → ② 申請の画面 → ③ 詳細・変更点・コピー → PDF → 台帳と Excel の列 | §5.3〜§5.8 |
| **5b** | 過去の取り込み: ⑪ の取り込みと確認の画面 → 1 件ずつの登録・直し・削除 → 台帳に「紙」 → 関連する決裁No | §5.9〜§5.15 |

- 作り込みを先にする理由: 使い始めるのに必ず要り、種類の一覧（要件 16.3 の 2）の登録もこれでできるようになる。台帳の列（工事原価など）も 5a で最後の形になり、5b の紙の決裁はそこに入る
- 5a の計画が大きくなりすぎたら、計画の段でもう一度利用者に相談する

### 1.2 段階5 でやらないこと（§9 に詳細）

- スキャンした PDF の一括の紐づけ（要件 11.5。D8）
- 台帳の画面に工事原価などの列を出すこと・明細表の行の名前での検索
- 出力の記録を見る画面

## 2. 決定事項（2026-10-07 の対話で確定）

D1〜D10 は選択式で個別に決めた（D2 以外はすべて推奨の案。D2 は推奨より 1 段強い案）。D11〜D25 は設計の各節の中で示し、利用者が節ごとに承認した。

| # | 論点 | 決定 |
|---|---|---|
| D1 | 分け方 | 2 回に分け、**作り込み（5a）が先**、過去の取り込み（5b）が後 |
| D2 | 明細表の種類の提出の条件 | **合計金額の販売金額が 0 円より大きい・契約予定日・担当者**（種類で使う欄のとき）が必須。坪数・坪単価は空でもよい。名前のない行に金額を入れたら項目名も要る。下書きは形が合っていれば空でも保存できる |
| D3 | 明細表の数の範囲 | 販売金額・工事原価は**マイナスも入れられる**（値引きの行など）。提出には D2 の合計の条件が要る |
| D4 | 本文の形の切り替え | **申請（下書きを含む）が 1 件でもある種類は、本文の形を切り替えられない**。変えたいときは新しい種類を作り、古い種類を停止する（書きかけの中身が消えることが無い） |
| D5 | 明細表の持ち方 | **明細表の行は申請の中にまとめて持つ**（JSON の 1 列。今の「関連する決裁No」と同じ）。坪数・坪単価・担当者・契約予定日は申請の列、使える部門は表。要件 15.5 の `approval_type_rows`・`approval_request_rows` は作らない。理由: 台帳は申請者以外に最後に提出した控え（JSON）から中身を出すので、保存・控え・変更点・台帳・PDF が同じ 1 つの形を読み、読み違いが起きにくい。行ごとの検索は苦手（要件に無い） |
| D6 | 同じ年度の取り込み直し | **足すだけ**。すでにある番号は中身を変えない（金額が空の記録にだけ金額の控えから補う）。Excel と中身が違う番号は確認の画面に「違いあり」と出し、直すなら 1 件ずつ。手で直したものが消えない |
| D7 | 紙の番号とシステムの番号 | 今年度の紙の番号を取り込む（手で 1 件登録する）と、その部門の**次の番号を「紙のいちばん大きい番号＋1」まで自動で進める**（戻しはしない）。確認の画面に進んだあとの次の番号を出す。⑧ の開始番号は紙の番号以下を断る。システムの申請がすでに持っている番号と同じ紙の番号はエラーにして取り込まない |
| D8 | スキャンした PDF の一括の紐づけ | **今回は作らない**（スキャンすると決まってから。大きさと枚数が分かってから上限を決められる）。紙の記録の表と詳細の画面は、あとで PDF を付けられる形にしておく |
| D9 | 紙の記録を消す | 決裁の管理者が **1 件ずつ消せる**。取り込みを間違えたときは、**取り込み 1 回分をまとめて取り消せる**（そのあと手で直した記録も含めて消えることを、取り消す前に件数で見せる）。進めた次の番号は自動では戻らない（⑧ の開始番号で戻す）。消したことは設定の記録に残す |
| D10 | 紙の決裁の持ち方 | **専用の表**に持ち、台帳で申請と合わせて並べる（要件どおり）。申請の表に混ぜると、ホーム・自分の申請・⑩・お知らせ・催促など申請の表を読むすべての所で紙を除く必要があり、漏れると事故になる |
| D11 | 使い始める前 | ⑨ の新しい設定と ⑪ は、⑧ ⑨ と同じく**使い始める前から決裁の管理者が使える**（種類の登録と過去の取り込みを、使い始める日までに済ませられる）。申請の画面・PDF・台帳・紙の決裁の詳細は、今と同じく使い始めるまで誰にも見えない |
| D12 | 両方の本文の形で使える設定 | 件名の決まり文句・追加の入力欄・定型文・使える部門は、5W2H の種類でも明細表の種類でも使える（要件 5.5.1 は形を限っていない）。見出しは 5W2H の種類だけ、明細表の行と「計」の行は明細表の種類だけ |
| D13 | 使える部門の効き方 | 申請の画面の種類の選択肢は、自分の所属部門のどれかで使える種類だけ。提出のときに、選んだ申請部門でその種類を使えるかを確かめる。**差戻し中の申請は、種類と申請部門を前の提出から変えていなければそのまま出し直せる**（停止した種類と同じ考え。回っている途中の申請を行き止まりにしない） |
| D14 | 種類の設定をあとから変えたとき | 行の名前・定型文・件名の決まり文句を変えても、変わるのはこれから作る申請と、まだ出していない下書き（次に保存したとき）だけ。提出済みの申請は提出したときのまま（行の名前は申請の明細表に、定型文は申請の列に、件名は組み立てた文字列で持つ） |
| D15 | 明細表の種類の金額 | 保存のときに**サーバーで計算し直す**（合計金額の行の販売金額。画面から送られた数は使わない）。金額の列に入れるので、台帳・検索・PDF の金額は今の仕組みのまま |
| D16 | 書いたものを黙って消さない | 種類を選び直したときは、今の「入れ替える／本文はそのまま」と同じく確かめてから変える。⑨ で行の名前が変わった下書き（差戻し中を含む）を開いたときは、金額の入った古い行を自由行として残す |
| D17 | 実施時期 | どちらの本文の形でも今までどおり出す（任意）。明細表の種類は契約予定日も持つ（要件 5.5.5 のとおり両方） |
| D18 | 台帳の画面 | **列は今のまま**（決裁No・決裁日・判断・件名・申請部門・申請者・金額・状態）。工事原価などは Excel で見る（PC で 11 列になると件名が細くなる）。キーワードは件名と本文（明細表の種類では補足）で当て、行の名前では当てない |
| D19 | Excel の粗利率 | Excel の数（12.3% と出る書式）。販売金額が 0 のときは空欄（「—」の文字を入れると並べ替えや計算ができない） |
| D20 | 取り込みのエラーの行 | **飛ばして、ほかの行は取り込む**（CSV の取り込みは 1 行でもエラーがあると全部を断るが、こちらは D6 で「足すだけ」なので、Excel を直して取り込み直せば直した行だけ足される。紙の台帳は今も使っているファイルなので、取り込みのためだけに直させない） |
| D21 | 紙の決裁の詳細 | 見られる人が開ける詳細の画面を作る（台帳の行・関連する決裁No のリンクの先）。決裁の管理者には「直す」の入口。あとでスキャン PDF を付けるときもこの画面に足す |
| D22 | 台帳の絞り込みの足し | 判断に「**不明**」（紙だけが当たる）、新しく「**区分**」（すべて〈既定〉／システム／紙） |
| D23 | Excel の紙の行 | 区分「紙」・判断「不明」・状態は空欄。金額＝契約金額、粗利益金額＝取り込んだ粗利益、粗利率は計算 |
| D24 | 取り込みのテスト | **本物の台帳はリポジトリに入れない**（実在の人の名字と案件が入っている）。テストの中で同じ形の小さな .xls を作る。本物は計画の段に手元で読む・メモリを測る・確認の画面を見るのにだけ使う |
| D25 | ⑦ の検索 | 利用者の管理の検索も、登録名の空白を無視して当てる（4b の台帳の申請者と同じ直し。段階5 のファイルではないが小さいので 5a の最初に入れる） |

## 4. 調べて分かった事実（2026-10-07 に実物で確認。13.x `3d5cad69`）

### 4.1 今あるもの・無いもの

- **5.5 の部品はまだ何も無い**。`approval_types` は `name`・`headings`・`review_department_id`・`sort_order`・`is_active` だけ（モデルと ⑨ の注記に「段階5 で足す」）。`approval_requests` に明細表・坪数などの列は無い。紙の決裁の表も無い
- 段階2 の設計（§5.5・§5.11）は、控え（`approval_revisions.snapshot`）に「段階5 で明細表の行と追加の入力欄を足す」としている。`RequestSnapshot` の注記も同じ
- 申請の画面で種類を選び直すと、本文を書いていれば「入れ替える／本文はそのまま」を聞く（`form.blade.php` の `typeChanged`）。見出しのままの判定は `BodyTemplate::isBlank()` の 1 か所
- 台帳（`Ledger`）は申請の表だけを読み、並びは id の並びとして PHP で作る（`sortedIds`）。中身は申請者本人には今の中身、ほかの人には最後に提出した控え（`LedgerRow::for`）
- 採番（`ApprovalNumber`）は部門・年度ごとの行（`next_number`・`last_issued`）。⑧ の開始番号（`setNext`）は `last_issued` 以下を断る。今年度だけを扱う
- 和暦（`ApprovalFiscalYear::eraLabel`）は平成にも対応済み（2019-05-01 より前に始まる期は H。注記に「段階5 の過去分の取り込みで使う」）
- 関連する決裁No は形だけを確かめ（`RelatedNumbers::PATTERN` は R・H の両方）、候補（`RelatedNumberController`）は見られる申請の番号の付いたものだけ
- 取り込みの前例: 社員の CSV 一括登録（`UserImportController`）。アップロード → 確認の画面（中身を base64 で hidden に載せ、1 回限りの鍵 `OneTimeAction`）→ 確定でサーバーが読み直して確かめる。断るときの戻り先は取り込みの画面に固定（Bug #64）
- 本番の Web の `post_max_size`・`upload_max_filesize` は 512M の可能性が高い（2026-09-27 の読み取り。BACKLOG）。`memory_limit` は 128M

### 4.2 紙の様式と台帳

- 住宅の様式（`~/Desktop/住宅・不動産決裁申請書.xls`）: 粗利益金額・合計の工事原価はマイナスを赤で出す書式。粗利率は小数第 2 位の書式（要件では小数第 1 位と決めている）。坪単価は `#,##0`（円の整数）。実際の数の入った控えは無い
- 9/17 に利用者が見た申請の画面の見本（Artifact「住宅契約の申請画面」）: 基本の欄 → 金額の明細（凡例・表・「建物側に行を足す」「土地側に行を足す」・坪数と坪単価・定型文・補足）→ 関連と添付。スマホは 1 行 1 枚のカード。その場で計算する
- 過去の台帳（`~/Desktop/08年度・決裁申請書契約状況.xls`。手元にあるのはこの 1 冊）の形は @docs/決裁申請_過去台帳の調査.md のとおり（15 シート・受付簿 12 枚は左右 2 段・見出しの行が繰り返す・ＮＯは空の行にも印字・日付は和暦のドット・金額の控え 3 枚）。**日付のセルが文字か数か、読むメモリと時間は未確認**（計画の段で測る）

## 5. 設計

### 5.1 全体の構成

```
⑨ 種類の設定 ──（本文の形・明細表の行・決まり文句・追加の欄・定型文・使える部門）
   │
② 申請の画面 ── 明細表（その場の計算）→ 保存（金額をサーバーで計算）→ 提出（D2 の条件）
   │                                         └→ 控え（明細表・追加の欄・定型文も）
③ 詳細・変更点・PDF ── 今の中身（申請者）／控え（ほかの人）
台帳（⑤）・Excel ── 申請 ＋ 紙の決裁（見られる範囲は 1 か所）
⑪ 取り込み ── .xls → 確認の画面 → 確定 → 紙の決裁の表 ＋ 次の番号を進める
   └ 1 件ずつの登録・直し・削除・1 回分の取り消し
紙の決裁の詳細 ←── 台帳の行・関連する決裁No のリンク
```

- 名前は仮（計画で決める）: 明細表の計算と形を確かめる部品（画面・保存・控え・PDF・Excel が共有）・台帳の紙の行・紙の見られる範囲・台帳の読み取りの部品・取り込みの結果

### 5.2 使い始めるまで（D11）

- ⑨ の新しい欄と ⑪ は使い始める前から決裁の管理者が使える（入口も出す）

### 5.4 ⑨ 申請の種類の設定（5a）

登録・編集の小窓に次を足す。

|---|---|---|
| 本文の形 | 5W2H の見出し／金額の明細表 | 申請（下書きを含む）がある種類では切り替えられない（D4）。小窓に「この種類の申請が N 件あるため変えられません」 |
| 見出し | 今のまま | 5W2H の種類だけ（明細表の種類では出さない・要らない） |
| 明細表の行 | 前半・後半それぞれ、行の名前と並び。名前が空の行は自由行 | 明細表の種類だけ。前半は 1 行以上。「足す・消す・上へ・下へ」。名前は 30 文字まで・各 20 行まで |
| 「計」の行 | 使う／使わない | 明細表の種類だけ |
| 件名の決まり文句 | 件名の後ろに付く文字 | 50 文字まで。空なら件名は 1 行で書く |
| 追加の入力欄 | 坪数・坪単価・担当者・契約予定日のそれぞれ「使う」 | 契約予定日・担当者は、使う種類では提出に必須（D2） |
| 定型文 | 本文の下に出す固定の文 | 500 文字まで。空なら出さない |
| 使える部門 | 部門のチェック（複数） | 1 つも選ばなければ全部門 |

- 変えた内容は今と同じく設定の記録（`SettingLogger`）に前と後を残す（使える部門も）
- 要件 5.5.7 の 2 つの設定例（請負新築工事契約・追加・少額工事契約）がこの欄で組めること

### 5.5 ② 申請の画面（5a）

- 明細表の種類を選ぶと、重点ポイント（5W2H）と金額の欄の代わりに: 明細表・「行を足す」（前半・後半）・坪数と坪単価・担当者と契約予定日（種類で使う欄だけ）・定型文・補足（自由記入・任意・今の本文の列に入れる）。実施時期はどちらの形でも出す（D17）
- 明細表: 項目・販売金額・工事原価・粗利益金額（自動）・粗利率（自動・小数第 1 位・販売金額 0 の行は「—」）。「計」（前半の合計。使う種類だけ）と「合計金額」（計＋後半）の行も自動。入力に合わせてその場で計算する（画面の見本のとおり）
- 名前を設定した行は消せない・自由行は消せる。種類に設定した自由行は最初から空欄で出す。名前も金額も無い自由行は、保存しても画面には残す（要件 5.5.4）
- 金額は保存のときにサーバーで計算し直す（D15）
- 件名の決まり文句: 「前半の入力欄＋決まり文句」と組み立てた件名の見本。「件名を直接書く」で 1 行の入力に切り替える。保存するのは組み立てた件名（100 文字まで）。開き直したときは、件名が決まり文句で終わっていれば分けて出し、そうでなければ「直接書く」で出す
- スマホ（およそ 720px 未満）は明細表を 1 行 1 枚のカードにする（横スクロールなし。要件 5.5.6）
- 入れられる数: 販売金額・工事原価は −999,999,999,999〜999,999,999,999（マイナス可。D3）・坪数は小数第 2 位まで・坪単価は 0 以上の円（12 桁まで）・担当者は 50 文字まで・契約予定日は日付
- 保存（下書き）は形だけを確かめる。提出は D2 の条件と D13 の使える部門を `SubmitChecker` で確かめ、理由をまとめて出す
- 種類を選び直したとき・名前の変わった行（D16）: 書いたものを黙って消さない
- 種類の選択肢は、自分の所属部門のどれかで使える有効な種類（D13。今の種類が外れていても、その申請の種類は出す＝今の扱いと同じ）
- 種類で使わない追加の欄の値は、保存のときに空にする（画面から送られても入れない）

### 5.6 ③ 詳細・変更点・コピー（5a）

- 詳細: 明細表（名前も金額も無い自由行は出さない）・計・合計金額・坪数・坪単価・担当者・契約予定日・定型文・補足。スマホはカード。申請者以外には最後に提出した控えから出す（`RequestContent` の出し分けのまま）
- 変更点（出し直した申請。要件 4.4）: 明細表は行ごとに、項目・販売金額・工事原価の変わった欄に色を付け、増えた行・消えた行も分かるようにする。坪数・坪単価・担当者・契約予定日は件名や金額と同じ並び。補足は本文と同じく行ごと（`LineDiff`）
- コピーして作成（要件 5.4）: 明細表（金額の入った行）・追加の欄・補足も写す。添付は今までどおり写さない。写した先の種類の今の行の設定に合わせて並べ直し、合わない行は自由行として残す（D16）

### 5.7 PDF（5a）

- 明細表の種類では、重点ポイントの欄の代わりに、紙の住宅の様式の「（記）」の並び: 明細表（項目・販売金額・工事原価・粗利益金額・粗利率、計・合計金額）→ 坪数・坪単価 → 定型文 → 担当者・契約予定日 → 補足
- 名前も金額も無い自由行は載せない。行が多いときは行の切れ目で次のページへ
- 金額の欄（金額・実施時期・関連する決裁No の行）は今の形のまま（金額は合計金額の販売金額）
- 5W2H の種類で定型文や追加の欄を使う場合は、本文の下に載せる
- **4a の落とし穴 4 つを戻さない**（`pdf.blade.php` の先頭の注記・BACKLOG の 4a の節）: ①判断の欄の小さな表を印・コメントと同じセルに入れ子にしない ②人が打つ文字の入る表には `class="wrap"` ③朱の枠は `td.mark.on` ④SVG は viewBox を描く大きさに。表の 1 行＝罫線の 1 行（`PdfSheet::bodyRows()` の考え）
- 計画の段で紙面を描いて pdftoppm の画像で確かめる（HTML だけで判断しない）

### 5.8 台帳と Excel の列（5a）

- 台帳の画面: 列は今のまま（D18）。明細表の種類の金額は合計金額の販売金額（金額の列）
- Excel: 要件 10 の並び。5a で 4 列を足して 19 列（区分は 5b で足して 20 列）

  決裁No／決裁日／判断／件名／申請の種類／申請部門／申請者／金額（税抜）／**工事原価／粗利益金額／粗利率**／実施時期／**契約予定日**／関連する決裁No／提出日／審査の意見／審査のコメント／条件／状態

- 工事原価・粗利益金額は合計金額の行の数（数として入れる）。粗利率は D19。契約予定日は Excel の日付。5W2H の種類の行では 4 列とも空欄

- **列を 1 つの定義から作る形に直してから列を足す**（BACKLOG の 4b の節「段階5 で Excel の列を足すときの注意」。今は見出し・`write()`・`DATE_COLUMNS`・`AMOUNT_COLUMN`・`WRAPPED_COLUMNS` の 5 か所が別々）
- 件数の上限（今は 1,000 件）でメモリが足りるかを、列を足した形で計画の段に測り直す

### 5.9 ⑪ 過去の決裁の取り込み（5b）

- 決裁の管理者だけ・使い始める前から使える（D11）。入口は決裁の管理のメニュー（サイドバー・ホームのリンクの行の、⑦〜⑫ と同じ所）
- 流れ（社員の CSV 一括登録と同じ形）: ファイル（.xls・.xlsx・10MB まで）と年度を選ぶ（ファイル名の「08年度」から先に選んでおく）→ 確認の画面（何も書かない）→ 「取り込む」で確定（サーバーで読み直して確かめる・1 回限りの鍵で二度押しは 1 回だけ効く・断るときの戻り先は ⑪ に固定）
- 読み方（要件 11.1 の注意を守る）
  - シート名の先頭の記号（全角は半角にそろえる。Ｊ・ＪＢ）を ⑧ の部門のアルファベットに当てる
  - 受付簿は左右 2 段を両方読む。繰り返す見出しの行は飛ばす。**日付のある行だけ**を記録にする（ＮＯだけの行は使っていない行）
  - 日付「8.05.07」は選んだ年度の元号（令和・平成）で西暦に直す（年度をまたぐ月は次の年）
  - 決裁No は「年度の和暦-部門の記号-ＮＯ」（`ApprovalNumber::format`。例 R8-J-021）
  - 名前に「金額」を含むシートは金額の控え（1 段）。**日付と件名**（空白・全角半角の違いは無視）で受付簿の行に結び付け、契約金額・工事原価・粗利益を補う。日付・件名・申請者の無い行（「門田契約 金額」のような計算の跡）は読まない
- 確認の画面
  - 部門ごとの件数（新しく足す／すでにある／エラー）
  - 取り込むと進む次の番号（今年度の部門だけ。「J の次の番号は R8-J-035 になります」）
  - エラーの行（取り込まない。D20）: ⑧ に無い部門・ＮＯが数でない・日付が読めない・システムの申請がすでに同じ番号を持つ・同じファイルの中で同じ番号が 2 回
  - 注意（取り込む）: 日付がその年度の期間の外・すでにある番号で Excel と中身が違う（D6）
  - 結び付かなかった金額の行: 行ごとに結び付ける先（同じ日付の記録を先に並べる）か「結び付けない」を選ぶ欄。選んだものは確定のフォームで送り、確定のときにも確かめ直す
- 確定: 新しい番号を足し、すでにある番号は金額が空のときだけ補う（D6）。取り込み 1 回分を `approval_paper_imports` に残し、設定の記録にも残す。次の番号を進める（§5.11）

### 5.10 1 件ずつの登録・直し・削除と取り消し（5b）

- ⑪ に紙の決裁の一覧（年度・部門で絞る）と、登録・直し・削除
- 欄: 年度・部門・ＮＯ・決裁日・申請者・件名・金額・工事原価・粗利益・備考。決裁No は年度・部門・ＮＯから組み立てる（紙の番号どうし・システムの番号と重なれば断る）
- 削除と取り込み 1 回分の取り消し（D9）: 件数を見せて確かめる。取り消しは、その回に足した記録を、そのあと手で直したものも含めて消す（金額を補っただけの既存の記録は消さない＝その回に足したものではない）。設定の記録に残す

### 5.11 次の番号（5b・D7）

- 今年度の紙の番号を足したとき（取り込み・1 件の登録・番号の直し）、その部門の次の番号が「紙のいちばん大きい番号＋1」より小さければそこまで進める。戻さない
- ⑧ の開始番号（`ApprovalNumber::setNext`）は、システムで使った番号に加えて、今年度の紙の番号以下も断る
- 過去の年度の紙の番号は採番に関わらない（採番は判断した日の年度だけ。要件 6.5 の判断し直しも元の番号を使う）

### 5.12 紙の決裁の見られる範囲（5b）

- その部門に所属する人・その部門の部門長・全件閲覧者・決裁の管理者（要件 7 章）。社長は全件閲覧者に指定されていれば見られる

### 5.13 台帳に紙の決裁を並べる（5b）

- 紙の行: 判断「不明」・状態の列に灰色の「紙」・申請者は台帳の文字。行から紙の決裁の詳細へ
- 絞り込み

| 絞り込み | 紙の決裁 |

### 5.14 Excel の紙の行（5b）

- 「区分」の列（システム／紙）を状態の前に足して 20 列（要件 10）。紙の行は D23

### 5.15 関連する決裁No と紙の決裁の詳細（5b）

5. 利用者の Chrome で見るだけ（使い始める前なので、5a は ⑨ の新しい欄、5b は ⑪ が見える。フォームは送らない）

## 10. 実装計画で決めること

1. 明細表の JSON の形（種類の行の設定・申請の行）と、計算と検査の部品（画面・保存・控え・PDF・Excel が共有）
2. 入力の上限の細部（行の数・坪数の範囲・契約予定日の範囲・紙の件名の長さ）
3. 変更点の行の合わせ方（前半・後半ごとに行の位置で合わせるか、など）
4. PDF の明細表の列の幅・ページの切れ方（描いて確かめる）
5. 台帳で申請と紙を合わせる組み方（`sortedIds` の鍵・行の作り方・見られる範囲の SQL）
6. 取り込みの確認から確定へ中身を渡す形（社員の CSV と同じ hidden の base64 か、一時ファイルか）と、結び付けの選択の送り方
7. 08 年度の台帳の実物の読み取り（日付のセルの型・メモリと時間。本番は 128MB）
8. 次の番号の進め方（`approval_number_sequences` の `next_number` を進める・`setNext` の検査に紙の番号を入れる）
9. Excel の件数の上限の測り直し
10. ルートの名前・入口・走査テストの登録（§4.3）
11. 作業場所: WT `approval-phase3` を 13.x（`3d5cad69`）へ早送りして始める（2026-10-07 に早送り済み）。manage の会話の変更（`Controller.php` の `ignoreMalformedQuery()`・`lang/ja/validation.php`・入力の項目名の走査の拡大）を前提にする

## 11. 実装の順番（案）

**5a**: ⑦ の検索（D25）→ 表（種類・申請・使える部門）→ 明細表の計算と検査の部品 → ⑨ → ② の保存と提出の条件 → ② の画面（明細表・件名・カード）→ ③・控え・変更点・コピー → PDF → Excel の列の定義の直しと 4 列 → 全件・変異・ブラウザ → ドキュメント（要件定義書 v1.14 の 5a の分を含む）→ 本番反映

**5b**: 表（紙の決裁・取り込み）→ 紙の見られる範囲 → 取り込みの読み取り（作った .xls）→ ⑪ の確認と確定・次の番号 → 1 件ずつ・削除・取り消し → 台帳と Excel に紙・絞り込み → 紙の決裁の詳細と関連する決裁No → 全件・変異・ブラウザ → ドキュメント（v1.14 の残り）→ 本番反映
