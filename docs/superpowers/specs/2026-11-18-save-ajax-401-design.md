# 保存の Ajax でログインが切れた（401）ときに日本語の理由を出す（短い設計メモ）

日付: 2026-11-18 ／ 利用者の選択: 案 A（2026-11-18「Aで進めてください」）
元: docs/superpowers/specs/2026-11-17-get-ajax-failure-design.md の範囲外「保存の Ajax が 401 で出す英語の `Unauthenticated.`」

## なぜ

ログイン中に、ほかの画面や端末でパスワードを変えた・管理者がパスワードを再発行した・利用者が消された、のあとに最初に保存すると、
Laravel がその場でログアウトし（`AuthenticateSession`・認証の確かめ）、英語の `Unauthenticated.` で 401 を返す。
画面には「保存に失敗しました: Unauthenticated.」や「ステータスの更新に失敗しました（401）」と出て、何をすればよいか分からない。
時間がたっただけのときは、先に鍵の確かめで断られて 419（日本語。Bug #137）になるので、401 になるのは上の場面だけ（まれ）。

## 今（2026-11-18 に `resources/views` を数えた。決裁を除く保存〈GET 以外〉の Ajax 40 か所）

| 表示 | か所 |
|---|---|
| サーバーの文をそのまま出す（「保存に失敗しました: Unauthenticated.」など） | 26（マスタ 5 つの並び替え・添付の部品・分譲地の区画・工程・注文住宅と建売の詳細・ZEAL の店舗とトレーナー・周辺ビルの地図 など） |
| 番号だけ（「ステータスの更新に失敗しました（401）」など） | 8（仕入れ案件・分譲地・建売の一覧のステータスの小窓・契約の画面の買主の小窓〈重複の確認・登録〉・仕入れ先の簡易登録・買主のランク変更と「この部署に取り込む」〈XHR〉） |
| もう日本語（原価のカード `realEstateCostAccessError`） | 4 |
| 何も出さない・決まった文（買主の重複の確認・ZEAL 試算表の項目の並び替え） | 2（Bug #137 でこのままと決めた） |

## 案（Approaches）

| 案 | 中身 | 選んだか |
|---|---|---|
| **A** | サーバーが基幹の保存（GET 以外）の JSON の 401 にも、決裁と同じ日本語の文を返す。番号だけの 8 か所は 401 でもサーバーの文を出す | **選んだ**（26 か所はサーバー 1 か所の直しで済み、これから作る画面にも効く・漏れにくい） |
| B | サーバーは変えず、34 か所すべてを画面の JS の共通の関数に通す（GET の直しと同じ形） | 採らない（直す画面が 20 本ほど・新しい画面は走査で強制し続ける） |
| C | サーバーの 401 をすべて（GET も）日本語にする | 採らない（昨日の GET の直しの文が変わり、「入力中の内容があれば控えて」の案内が消える） |

## やること（案 A）

1. **サーバー**（`bootstrap/app.php` の `AuthenticationException` の render）
   - 返す条件を「決裁の URL か、GET 以外」かつ JSON を求める要求、に広げる。文は決裁と同じ
     「ログインが切れました。ログインし直してから、もう一度やり直してください。」
   - 文は定数 `AuthController::SIGNED_OUT_MESSAGE` に移す（今は bootstrap/app.php の直書き。`EXPIRED_PAGE_MESSAGE` と同じ置き場所）
   - **GET の 401 は今のまま英語**（昨日の GET の部品 `ajaxGetFailureMessage` が英語の 401 で「ログインが切れた」を見分け、
     「入力中の内容があれば控えて」の案内を出している）
   - 無効にされた人の 401（`EnsureUserIsActive`。日本語の HttpException）とふつうのフォームの送信（ログイン画面へ転送）は変わらない
2. **番号だけの 8 か所**は、419 と同じく 401 でもサーバーの文を出す
   - fetch の 5 か所（3 つの一覧のステータスの小窓・買主の小窓の 2 つ）: `status === 419 && body && body.message` → `(status === 419 || status === 401) && …`
   - 仕入れ先の簡易登録: 401 で本文に文があればそれを出す（419 の今の文「セッションが切れました。ページを再読込してください。」は変えない）
   - XHR の 2 か所: 部品 `xhrFailureMessage` が 401 の本文も読む
   - 無効にされた人の 401 も、番号ではなく「このアカウントは無効になっています。管理者にお問い合わせください。」が出るようになる
3. **原価のカード**（`realEstateCostAccessError`）は**出す文を変えない**
   - 今は「英語の 401 → ログインが切れた（控えてから開き直して）」「日本語の 401・403 → その理由＋何もしていない」で見分けている。
     サーバーの 401 が日本語になるので、「日本語でも `SIGNED_OUT_MESSAGE` と同じ文なら、ログインが切れた側」とする
     （定数を画面へ `@json` で渡す。文を JS に書き写さない）
4. **26 か所**（サーバーの文をそのまま出す画面）は画面を変えない。サーバーの直しで「保存に失敗しました: ログインが切れました。…」になる
5. 注記を直す: `bootstrap/app.php`・`_partials/_ajax_get_failure`（「401 を日本語にするのは決裁の URL だけ」）・`ApprovalJsonExpiredSessionTest` の docblock

## 範囲外

- 番号だけの 8 か所で、403（権限が無い）の日本語の理由を出すこと（今どおり番号）
- 仕入れ先の簡易登録・建売の詳細のファイルの、419 の独自の文（「セッションが切れました。…」）
- 初回のパスワード変更を強制されている人（`ForcePasswordChange`）・決裁の画面

## 検証

- サーバー: 本物の `AuthenticateSession` の道（セッションのパスワードの控えを食い違わせる）で、基幹の POST・PUT・DELETE の JSON が日本語の 401、
  GET の JSON は英語の 401 のまま、JSON を求めない送信は今どおり、決裁は今どおり
- 番号だけの 8 か所と代表の画面（マスタの並び替え・ZEAL の店舗）: 画面の JS が組んだ要求を、ログインが切れた・無効にされた状態で本当に送り、
  応答を JS に戻して出る文を全文で見る（Bug #137 の 419 のテストと同じ形。419 と、ほかの断りは今の文のまま、の対も保つ）
- 原価のカード: `CostCardAccessErrorTest` の「ログインが無い」が今と同じ文のまま通ること＋パスワードを変えられた場合を足す
- 新しいテストは直す前に赤を確かめる・全件・変異（落ちたテストの組と理由まで）・コンパイル済みビューの lint・
  実ブラウザ（使い捨ての環境で、ほかのタブでパスワードを変えてから保存する）
- `ApprovalJsonExpiredSessionTest` は「社内決裁申請」の会話の担当なので、触る前に ListAgents で確かめる（Bug #137 と同じ）
