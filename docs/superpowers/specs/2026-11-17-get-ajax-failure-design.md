# GET の Ajax でログインが切れたときに理由を出す（短い設計メモ）

日付: 2026-11-17 ／ 利用者の承認: 未
元: docs/BACKLOG.md の「ログインが切れたとき（419）に日本語の理由を出す（Bug #137）」の節の範囲外
「GET の Ajax でログインが切れたときの「データの取得に失敗しました（401）」」

## なぜ

フォームを開いたまま時間がたってから物件や分譲地を選ぶと、裏で走る GET の Ajax が 401 になり、
画面には「空き区画の取得に失敗しました（401）」のように番号だけが出る。住所→〒は「該当する郵便番号が見つかりませんでした」と、
理由と違う文が出る。利用者は何をすればよいか分からない。

GET は送信の鍵を確かめないので、ログインが切れたときは 419 ではなく 401（本文は英語の `Unauthenticated.`）になる。
保存の Ajax は鍵の確かめが先に断る（419）ので、Bug #137 で直した。GET はその外に残っていた。

## 今（2026-11-17 に `resources/views` を数えた）

基幹の画面で自社へ GET する Ajax は 24 か所・失敗を扱う分岐は 23（決裁の申請書の 1 か所と、工程表の `send()`〈保存に使う。GET では呼ばない〉を除く）。

| 出し方 | か所 | 401 のとき画面に出るもの |
|---|---|---|
| alert に番号 | 16（分岐は 15。建売・注文住宅の区画と仕入れ案件の情報 4、賃貸マンションの空き部屋・空き駐車場 2〈並んだ 2 本で 1 つの alert〉と空き駐車場 1、仕入れ先の検索 1、不動産の契約の登録・編集 6、テナントの契約の登録の空き区画・問合せ 2） | 「空き区画の取得に失敗しました（401）」 |
| 欄の下に番号（顧客の検索） | 5（注文住宅・テナントの契約の登録と編集・問合せの登録と編集） | 「顧客の検索に失敗しました（401）」 |
| throw して画面の欄に出す（ZEAL 試算表の実績の確認） | 1 | 「プレビューの取得に失敗しました（HTTP 401）」 |
| XMLHttpRequest（住所→〒。買主・賃貸マンションの物件） | 2 | 「該当する郵便番号が見つかりませんでした」 |

どの失敗の分岐も、今はテストで一度も通っていない。

## やること（案 A・利用者の選択 2026-11-17）

画面の JS だけで直す。サーバーの応答は変えない（Bug #137 で決めた「401 は決裁の URL だけ日本語」を保つ）。

- 新しい部品 `resources/views/_partials/_ajax_get_failure.blade.php`（`<script>`・`@once`）に関数を 2 つ置く
  - `ajaxGetFailureMessage(status, body, what, fallback)`（同期）の決まり
    1. 401・403 で本文の `message` に日本語（ASCII 以外の文字）がある → `what + 'できませんでした。' + message`
       （無効にされた人の 401・権限の無い人の 403。判定は原価のカードの `realEstateCostAccessError` と同じ）
    2. 401 → `'画面を開いてから時間がたったか、ほかの画面でログアウトしたため、' + what + 'できませんでした。入力中の内容があれば控えてから、画面を開き直してください。'`
    3. ほか → `fallback`（今の番号つきの文のまま）
  - `ajaxGetFailure(res, what, fallback)` … fetch の応答の本文を JSON として読み（読めなければ本文なし）、上の文を Promise で返す
- 23 の分岐が使う
  - alert の 15 の分岐（賃貸マンションの契約の登録を除く 14）・欄の下の 5 か所 … `if (!res.ok) { …; return ajaxGetFailure(res, '空き区画を取得', 今の文).then(function (message) { alert(message); return null; }); }`
    （null 返しの形と `if (!data) return;` との対は崩さない。`AjaxErrorFeedbackTest` の決まりのまま）
  - 賃貸マンションの契約の登録（async/await）… `alert(await ajaxGetFailure(…))`
  - ZEAL 試算表の確認（throw）… `.then(function (message) { throw new Error(message); })`
  - 住所→〒の 2 か所 … 本文を try で読み、`ajaxGetFailureMessage(xhr.status, body, '郵便番号を取得', null)` が文を返したらそれを出す（ほかは今どおり）
- `what` は「〇〇を取得」「〇〇を検索」の形（例: 空き区画を取得・区画を取得・仕入れ案件の情報を取得・仕入れ案件の原価を取得・
  分譲地の区画を取得・分譲地の原価を取得・空き駐車場を取得・空き部屋・空き駐車場を取得・仕入れ先を検索・顧客を検索・プレビューを取得・郵便番号を取得）。
  今「データの取得」と書いてある 7 か所は、何を取りに行っているかの言い方にする（私の判断）
- 部品は関数を使う画面が `@include` する（部品の中で使うもの〈仕入れ先の選択〉は、その部品が読み込む）

出る文の例:

- ログインが切れた: 「画面を開いてから時間がたったか、ほかの画面でログアウトしたため、空き区画を取得できませんでした。入力中の内容があれば控えてから、画面を開き直してください。」
- 権限が無い（住宅事業だけの人が注文住宅の画面で顧客を検索したとき＝今もある）: 「顧客を検索できませんでした。この部門のデータへのアクセス権限がありません。」
- 404・500 など: 今と同じ「空き区画の取得に失敗しました（500）」

## 採らなかった案

- B（サーバーの 401 を基幹も日本語にする）… 保存の Ajax の英語の 401 も直るが、原価のカードが英語の 401 で「ログインが切れた」を見分けているので作り直しが要り、Bug #137 の決めを変える
- C（番号だけで見分ける）… 無効にされた人・権限が無い人にも「ログインが切れた」と出る
- 部品を `resources/js/app.js` に置く … 画面の JS を node で動かすテストが読まない（前回の設計メモと同じ理由）
- `realEstateCostAccessError` と 1 つにまとめる … 言い方（保存・取込・削除と「何も…していません」）が違う。同じ判定を 2 か所に持つ

## 範囲外

- 保存の Ajax が 401 で出す英語の `Unauthenticated.`（ほかの画面でパスワードを変えたときなど、まれ）
- 不動産の契約の登録・編集で分譲地を選ぶと GET が 2 本並んで走るので、失敗すると alert が 2 回出る（今も 2 回）
- 決裁の画面（サーバーが日本語の 401 を返す。担当は「社内決裁申請」の会話）・工程表の `send()`
- 初回のパスワード変更を強制されている人（`ForcePasswordChange` は GET を転送するので、Ajax は HTML を受け取り「通信エラー」になる。まれ）

## 検証

- 部品の分かれ目を node で動かす
- 走査（全件分類）: 自社へ GET する fetch の `.ok` の分岐と住所→〒の XMLHttpRequest は部品の関数を通すこと（除くものは理由つきで分類）・
  部品の関数を呼ぶ画面には部品の script が描かれていること（呼び出し側と定義側の対。Bug #28）
- 代表の画面で、本物の応答（ログインしていない GET の 401・無効にされた人の 401・権限の無い人の 403）を画面の JS に戻し、出る文を全文で見る
- 新しいテストは直す前に赤を確かめる・全件・変異（落ちたテストの組と理由まで）・コンパイル済みビューの lint・
  実ブラウザ（使い捨ての環境で cookie を消して 401 を起こす）
