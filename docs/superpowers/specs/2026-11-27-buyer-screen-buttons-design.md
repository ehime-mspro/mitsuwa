# 買主の画面で押せないボタンを出さない（設計メモ・短）

2026-11-27。利用者の依頼は「買主の画面で一般担当に出ている「新規登録」「編集」「削除」「アンケートを追加」などのボタンを、押せる人にだけ出す直しを、ここで進めて」。
会話で決めたこと: アンケートの行の「詳細」は案 A（一般担当には出さない）。

## なぜ

買主の画面（`resources/views/buyers/index.blade.php`・`show.blade.php`。住宅事業・不動産で共用）は、どのボタンも役割を見ずに全員へ出している。
ルートは役割で断るので、押せない人が押すと日本語の 403 の画面になる（Bug #96 と同じ形。2026-11-26 にランクのバッジだけ直した）。

| 画面 | ボタン | 送り先のルートの役割 | いま出ている人 |
|---|---|---|---|
| 一覧 | 新規登録 | 経営層・管理者 | 全員 |
| 詳細 | 編集 | 経営層・管理者 | 全員 |
| 詳細 | 削除 | 経営層だけ | 全員 |
| 詳細 | アンケートを追加 | 経営層・管理者 | 全員 |
| 詳細のアンケートの行 | 詳細・編集（どちらも編集画面へ行く） | 経営層・管理者 | 全員 |
| 詳細のアンケートの行 | 削除 | 経営層だけ | 全員 |
| 一覧（不動産・有効な設問が無いとき） | 案内の「アンケート設問管理」のリンク | 経営層だけ（`admin` の門） | 全員 |

一般担当はアンケートの中身をどこからも見られない（「詳細」も編集画面へのリンクで、今も 403）。

## 決まり（ルートと同じ判定）

- 経営層・管理者（`isManagerOrAbove()`）にだけ出す: 一覧の「新規登録」・詳細の「編集」「アンケートを追加」・アンケートの行の「詳細」「編集」
- 経営層（`isExecutive()`）にだけ出す: 詳細の「削除」・アンケートの行の「削除」・不動産の案内の「アンケート設問管理」のリンク
- 経営層でない人の案内は、リンクの代わりに文だけ出す:
  「ℹ️ 不動産事業のアンケートは現在未設定です。経営層がマスタ管理 &gt; アンケート設問管理から設問を追加すると、顧客登録時にアンケートが利用可能になります。」
- 出すボタンが 1 つも無いアンケートの行は、右側が空になる（日付・分譲地・担当は今のまま）
- 「顧客一覧に戻る」・ランクのバッジ（2026-11-26 の直し）・アンケートの行の日付・分譲地・担当は変えない

## 作り方

| 作り方 | 中身 | 引き換え |
|---|---|---|
| **1（選ぶ）** ビューの先頭の `@php` で判定を 1 回作り、`@if` で出し分ける | `show` に `$canManage`（`isManagerOrAbove()`）・`$canDelete`（`isExecutive()`）、`index` は今の `$canChangeRank` と同じ判定で新規登録も出し分ける | 買主一覧の今の形（`$canChangeRank`）と同じ。差分はビューだけ |
| 2 コントローラで判定してビューへ渡す | `CustomerController::show()`・`index()` が渡す | ビューを部品として使う別の画面が無いので利点が無く、コントローラも変わる |
| 3 ポリシーと `@can` | 新しいポリシーを作る | アプリはこの判定にポリシーを使っていない（新しい流儀を持ち込む） |

一般担当の「詳細」（案 A・会話で決めた）: 出さない。退けた案 B（見るだけの詳細画面を足す）は、回答（予算など）を一般担当に見せるかを決める別の機能。

## やらないこと

- ルート・ミドルウェア・コントローラは変えない（今も押せない人は断られる）
- テナントの顧客の画面（もう出し分けている）・ほかの画面のボタンの全件の洗い出し
- 見るだけのアンケートの詳細画面（案 B）

## テストで見ること（作る人へ）

- 住宅事業・不動産の両方で、経営層・管理者・一般担当の 3 役割（`#[DataProvider]`）ごとに、描いた HTML にボタン（送り先の URL まで）があるか・無いか
- 押せる人に出たリンクは、描いた href をたどると 200（Bug #47）。削除は描いたフォームを送ると消える
- 管理者には「編集」があり「削除」が無い（片方だけの誤りを止める）
- 不動産の案内: 経営層にはリンク、ほかの人にはリンクが無く文が出る
