# 区画のある土地の仕入れ案件のステータスは区画で決める（短い設計）

- 日付: 2026-11-21
- 依頼: 利用者（「直していないこと」の 1 つ目を直す・案 ア）
- 前提: 土地の区画を複数にした変更（`docs/superpowers/specs/2026-11-20-realestate-land-multi-lot-design.md`・2026-11-21 本番反映）と Bug #139

## なぜ

区画が 2 つ以上ある土地で、1 区画にだけ契約があるとき、仕入れ案件を一覧の小窓か編集画面で手で「販売済」にすると、
「販売中」に戻せなくなる。Bug #139 の歯止め（契約のある案件は「販売済」から戻させない）が効くため。
そのあいだは、空いている区画があっても契約の登録画面の選択肢に土地が出ない（選択肢は「販売中」の案件だけ）。
抜け道は区画を 1 つ保存し直すこと（区画からの集約が「販売中」に戻す）だけで、利用者には分からない。

本番は 2026-11-21 の時点で区画のある土地が #9（決済完了）・#18（査定・検討）の 2 件だけで、どちらも販売済ではない＝今戻せなくなっている案件は 0 件。

## 目標・目標でないこと

- 目標: 区画のある土地では、「販売済」かどうかを区画で決める。手で付けた値と区画が食い違わない
- 目標: 区画の無い案件（ほかの物件種別・区画の無い土地）の動きは変えない（Bug #139 のまま）
- 目標でない: 分譲地の手でのステータス変更（今も歯止めが無い。変えない）・画面の選択肢を隠すこと・#21 の形の最初の区画が「成約」で作られること

## 案（利用者が ア を選んだ・2026-11-21）

| 案 | 中身 | 選ばなかった理由 |
|---|---|---|
| **ア（選んだ）** | 区画を正とする。「販売済」にできるのは全区画が成約のときだけ。全区画が成約のあいだは「販売済」から動かせない | — |
| イ | 分譲地と同じく、区画のある土地には歯止めを効かせない | #21 の形（紐付けの無い「成約」の区画）で、手で「販売中」に戻すと同じ土地にもう 1 件の契約を登録できてしまう |

## 決まり（区画が 1 つ以上ある仕入れ案件だけ）

| 場面 | 手での変更 |
|---|---|
| 今と同じステータス | 通す（ほかの欄だけ直す編集画面の保存を断らない。Bug #130 の形） |
| 全区画が成約 | 「販売済」にしかできない（ほかへは断る） |
| 成約でない区画がある | 「販売済」にはできない（ほかへは通す） |

- 区画のある土地には Bug #139 の契約の歯止めを使わない。2 件目の契約は区画ごとの決まり（`ProcurementLotClaims`・`re_contracts.procurement_lot_id` の一意の索引）が防ぎ、
  全区画が成約のあいだは上の決まりが「販売済」に留める
- 「成約」は区画のステータスが `LotStatus::Sold` のもの（`syncStatusFromLots()` と同じ数え方）
- ⚠ 今戻せなくなっている形（成約でない区画があるのに「販売済」）は、「販売中」などへ戻せるようになる（直す前は断っていた）

### 断る文（入力チェックの文・一覧の小窓は 422 でそのまま出す）

- 成約でない区画があるのに「販売済」へ:
  「区画のある土地は、すべての区画が成約になると自動で「販売済」になります（成約でない区画が N 件あります）。」
- 全区画が成約なのに「販売済」以外へ:
  「すべての区画が成約のため、ステータスは「販売済」にしかできません。区画を成約から戻すと、自動で「販売中」に戻ります。」

## 作り方（こちらの判断）

- `ReProcurement::refusesStatus(string): bool` を `statusRefusal(string): ?string`（断る文か null）に替え、区画のある案件は上の決まり・無い案件は今の Bug #139 の判定を返す。
  呼ぶのは `ProcurementController::statusLockedByContract()` だけ（一覧の小窓 `updateStatus` と編集画面 `update` が使う）
- 画面は変えない（一覧の小窓の JS は 422 のサーバーの文を出す〈Bug #139〉・編集画面は入力エラーの帯に出る）
- テスト: 区画 2 つ・1 区画に契約の土地で、一覧の小窓と編集画面の両方から「販売済」が断られる／戻せなくなっていた形から「販売中」へ戻せる／全区画が成約なら「販売中」「不成約」が断られる／今と同じなら通る／区画の無い案件は今の Bug #139 のまま（今のテストが守る）
- 記録: `docs/RULES.md` に Bug #145（本番に出ている欠陥なので行を足す）・`CLAUDE.md` の件数・`docs/BACKLOG.md` に節と、土地の区画を複数にした節の「利用者に伝えること」の 2 つ目に → を書き足す
- 本番: DB 変更・新しいクラス・ルートの変更なし ＝ `./deploy.sh` だけ
