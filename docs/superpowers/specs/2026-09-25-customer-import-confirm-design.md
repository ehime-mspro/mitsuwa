## 1. 背景と依頼

顧客CSVインポート（サイドバーの「顧客CSVインポート」、`/admin/customers/import`、経営層のみ）の
「インポート実行」（確定）は、**最初のコミット 2046289d（2026-04-08）から一度も通っていない**。
プレビューまでは動くので、確定を押すまで気づけない。

さらに、確定の後の書き込みは一度も実行されたことがない。運び方だけ直すと、書き込みに潜んでいた問題
（黙った誤保存・1 行の誤りで全行が巻き戻る）が本番で初めて動き出す（§2.2）。

対話で決まったこと（2026-09-25）:

| 論点 | 決定 |
|---|---|
| 範囲 | **案 1**: 候補 1〜6 をすべて直す — 1 確定の運び方 ／ 2 取得日の検査 ／ 3 生年月日の検査 ／ 4 元号 ／ 5 人数・勤続年数・文字数 ／ 6 0 件のときの確定ボタン。CSV の中の重複など 6 件は BACKLOG へ（§6）|
| 運び方 | **案 A**: `csv_data`（base64）の hidden で運ぶ（§3）|
| 設計の 4 節 | ① 全体の形と確定までの流れ ② 1 行の検査と変換 ③ プレビュー画面 ④ テストと確かめ方、いずれも承認済み |

## 2. 調査で分かった事実（2026-09-25 実測・`13.x` = `94c534db`）

### 2.1 確定が通らない原因（再現済み）

- 確定のフォーム（`resources/views/admin/customers/import.blade.php:137-155`）が送るのは
  `_token`・`department`・`confirmed`・`csv_data`（base64）だけ。ファイルの欄も `enctype` も無い。
  重複候補があるときだけ `include_duplicates` のチェックボックスが付く
- コントローラは 28〜34 行で `csv_file` を**常に**必須にし、40〜41 行でファイルからしか読まない。
  `csv_data` を読む箇所は 0 件
- 画面が描いた確定のフォームをそのまま送り返すと、302 で `/admin/customers/import` に戻り
  「CSVファイルは必須です。」が出る。`buyers` は 0 件（使い捨てのテストで再現）
- 確定まで送るテストは 0 本。`ImportValidationFeedbackTest` は不正なファイル、
  `ImportPreviewRenderTest` はテンプレート（＋空欄の行）のプレビューしか見ていない

### 2.2 確定の後の書き込みで起きること

前のセッション（2026-09-25）が、ファイルを確定の送信にも付けて運び方を迂回し、SQLite のテストで測った。

| 行 | プレビュー | 確定の結果 |
|---|---|---|
| A 全項目が正しい | 正常 1 | 成功。買主・部署（取得日・ランク C）・アンケート（分譲地は前方一致、担当者は部分一致）・回答まで入る |
| B 生年月日 `19800102` | 正常 1 | 成功するが、生年月日は `1970-08-18 04:01:42`（date キャストが数字だけの文字列を Unix 時刻として読む）|
| C 1 行目は正しく、2 行目の生年月日が `昭和55年1月2日` | 正常 2・エラー 0 | **全行が巻き戻る**（「インポートに失敗しました: Could not parse '昭和55年1月2日' …」）|
| D 取得日 `2026-02-30` | 正常 1（`strtotime` が通す）| 成功するが、取得日とアンケートの日付が `2026-03-02`（date キャストの繰り上げ）|
| E 取得日 `2026/9/1` | エラー（正規表現が 2 桁を要求）| 「0件のインポートが完了しました。」|

- 正しい行が 0 件でも「インポート実行（0件）」のボタンが出る。
  テナント・賃貸マンションの取込は `@if($validCount > 0)` で隠し、
  「インポート可能なデータがありません。CSVを修正してください。」を出している
- 重複候補は、プレビューでは「正常」の件数に含まれない（プレビューの送信に `include_duplicates` が無いので
  飛ばされる）。確定のボタンの件数も「正常」だけで、チェックを入れても増えない

### 2.3 画面の登録との違い

- 画面（`CustomerController::store`）がサーバで見るのは、`last_name`・`first_name` の `max:50` と
  `acquired_date` の `date` だけ。人数・勤続年数はブラウザの number 入力（`min="0"`）に頼っている
- 元号: 画面のセレクトは 空・`S`・`H`・`R`。JavaScript が元号の年を西暦に直して `birth_date` に入れる
  （S +1925・H +1988・R +2018）。詳細画面は `Buyer::getBirthDateDisplayAttribute()` が同じ差で元号の年に戻し、
  「S.55年 1月 2日」と出す（元号が空なら「1980年 1月 2日」）。取込は書かれた文字のまま保存するので、
  「昭和」なら「昭和.1980年 1月 2日」と崩れる
- アンケートの回答: 画面は複数選択を JSON の配列で保存するが、取込は `A,B` のまま保存する
  （回答はアンケートの編集画面の初期値にしか使われない）→ 範囲外（§6）

## 3. 方針（運び方の比較）

| 案 | やり方 | 良い点 | 気になる点 |
|---|---|---|---|
| **A（採用）** | プレビューで読んだ CSV を `csv_data` の hidden で運ぶ。確定ではファイル必須の検査を外し、`csv_data` から読み直して同じ検査を最初からやり直す | 動いている取込 4 本と同じ形。hidden は既にあるので、直すのはコントローラだけ。ブラウザから届いた値は信用せず、確定でも全部検査し直す | CSV 全体がブラウザとサーバを往復する（他の取込と同じ条件）|
| B | サーバのセッションに置き、確定ではそこから読む | hidden が大きくならない。書き換えられる心配がない | 本番のセッションはファイル保存で、個人情報を含む CSV がそのファイルに残る。タブを 2 つ開くと後の方で上書きされる。この形の取込は 0 本 |
| C | 確定の画面でファイルをもう一度選んでもらう | 入力チェックはほぼ今のまま | プレビューと違うファイルを選べてしまい、見た結果と違う内容が保存されうる。利用者の手間が増える |

入力チェックは、テナント・ZEAL と同じく確定かどうかで分け、try で包む。`Rule::excludeIf()` で 1 回の
`validate()` にまとめる形は、アプリに使用例が 0 件で、走査テストも try で包む形を前提にしているので採らない。

### 4.2 コントローラの流れ（`execute`）

1. **部署を検査する。** `validate(['department' => 'required|in:housing,realestate'], [], ['department' => 'インポート先部署'])`
   を try で包み、`catch (ValidationException $e) { throw $e->redirectTo(route('admin.customers.import')); }`
2. **CSV を読む**（private の `loadCsv()`。テナント・ZEAL と同じ形）:
   - 確定（`confirmed`）: `(string) base64_decode($request->input('csv_data', ''))`。
     プレビューが渡すのは UTF-8 にそろえ BOM を除いた後の内容なので、変換し直さない。壊れていても無くても空文字になり、3 で止まる
   - プレビュー: `validate(['csv_file' => 'required|file|mimes:csv,txt|max:10240'])` を 1 と同じ形で包み、
     `CsvImportReader::decode(file_get_contents(...))`
3. **データの行が無ければ**、`redirect()->route('admin.customers.import')->with('error', 'CSVファイルにデータがありません。')`
4. **見出しと列の対応づけ**は今のまま（見出しは `BuyerCsvRow::COLUMNS` を引く）
5. **1 行ずつ** `BuyerCsvRow::from()` にかける:
   - エラーがあれば `rowErrors` に 1 件（`['row' => 行番号, 'message' => 1 行のエラーを「／」でつないだ文]`）積んで次の行へ
   - エラーが無ければ、今と同じく DB と比べて重複を確かめる（姓・名・都道府県・市区町村）。
     重複なら `dupeRows` に積み、`include_duplicates` が無ければ飛ばす
   - 残った行を「取り込む行」に積む（`BuyerCsvRow` と、設問の回答を読むための生の列）
6. **プレビュー**: 今と同じ view（`preview`・`department`・`totalRows`・`validCount`・`rowErrors`・`dupeRows`・`csvData`）
7. **確定**:
   - 取り込む行が 0 件なら書き込まず、取込の画面へ戻して理由を出す。
     重複候補を飛ばした結果 0 件なら「取り込む行がありません。重複候補を取り込むときは『重複候補もインポートする』にチェックを入れてください。」、
     それ以外は「インポート可能なデータがありません。CSVを修正してください。」
     → 「0件のインポートが完了しました。」に到達する道はなくなる
   - 1 件以上なら、今と同じくトランザクションの中で書く。買主は `BuyerCsvRow` の保存する値、部署とアンケートの日付は
     変換後の取得日、アンケートの分譲地と担当者は今の探し方のまま
   - 例外が出たら巻き戻して、`redirect()->route('admin.customers.import')->with('error', 'インポートに失敗しました: …')`

確定でも、部署・行の検査・重複の確認をすべてやり直す（`csv_data` や `department` が書き換えられていても、
プレビューで通らないものは入らない）。

### 4.3 1 行の検査と変換（`BuyerCsvRow`）

**形**（`HacomonoMemberMapper` → `MappedMember` に倣う）:

- `public const COLUMNS`: CSV の見出し → 内部のキー（今の `$baseColumns` と同じ 21 列・同じ順）
- `public static function from(array $values): self` — 内部のキー → セルの値（列が無ければ空文字）を受け取る。前後の空白は `from()` が除く
- 読み取り専用の値: `buyer`（`buyers` に入れる値。空欄の項目は入れない）・`acquiredDate`（`Y-m-d`。誤りなら null）・
  `projectName`・`staffName`・`errors`（CSV の列の順）
- `hasErrors(): bool`・`errorMessage(): string`（`errors` を「／」でつなぐ）

**列ごとの検査と保存する値**（CSV の列の順に検査し、誤りはすべて集める）:

| 列 | 検査 | 保存する値 |
|---|---|---|
| 姓・名 | 必須（「姓が未入力です」「名が未入力です」は今の文言のまま）。50 文字以内 | そのまま |
| セイ・メイ | 50 文字以内 | そのまま |
| 生年月日 | 空欄は可。`CsvDate::normalize()` で読めなければ誤り（`19800102`・`昭和55年1月2日`・`1980-02-30`）| `Y-m-d` |
| 元号 | 空欄は可。`mb_convert_kana('a')` と大文字化のあとで `S`・`H`・`R`、または `昭和`・`平成`・`令和` なら受け付け、それ以外は誤り。生年月日も正しく読めた行では、その年が元号の範囲にあるか（昭和 1926〜1989・平成 1989〜2019・令和 2019〜）| `S`・`H`・`R` |
| 大人人数・子供人数 | 空欄は可。`mb_convert_kana('n')` で全角の数字を半角にし、0〜255 の整数でなければ誤り（`2人`・`-1`・`1.5`・桁あふれするほど長い数字）。先頭の 0 は可 | 整数 |
| 郵便番号 10・都道府県 10・市区町村 50・住所詳細 255・建物名 255・電話番号 20・メールアドレス 255・職業 50・勤務先 100 | 文字数（`mb_strlen`）| そのまま |
| 勤続年数 | 空欄は可。0〜65535 の整数（人数と同じ扱い）| 整数 |
| 取得日 | 必須（「取得日が未入力です」は今の文言のまま）。`CsvDate::normalize()` で読めなければ誤り（`2026-02-30`）。`2026/9/1`・`1970-01-01` は通る | `Y-m-d`（アンケートの日付にも使う）|
| 来場分譲地名 | 検査しない（保存せず、分譲地を探すのに使うだけ）| — |
| 担当者名 | 50 文字以内（`buyer_surveys.staff_name` の大きさ）。回答が空欄でアンケートを作らない行でも見る（行によって規則が変わらないように）| そのまま |

**文言**（列の名前は `COLUMNS` の見出しから取る）:

- 日付: `生年月日「19800102」は日付として正しくありません（例: 2026-09-01 か 2026/9/1）`
- 元号の値: `元号「明治」は S・H・R（昭和・平成・令和）で入力してください`
- 元号の範囲: `元号「S」と生年月日「2000-01-01」が合いません（昭和は1926〜1989年）`（令和は「令和は2019年から」）
- 整数: `大人人数「2人」は0〜255の整数で入力してください`
- 文字数: `市区町村は50文字以内で入力してください（51文字）`

**決めたこと**:

- **1 行の誤りはすべて集め、1 件のエラーとして出す。** 今は最初の 1 つしか出ず、直して上げ直すと次の誤りが出る。
  件数は今と同じく行の数なので、「全 N 件」＝正常＋エラー＋重複候補 の関係は変わらない
- **元号の範囲の確認だけは画面より 1 歩厳しい。** 画面は元号の年を打つので食い違いが起きにくいが、CSV は元号と生年月日が
  別の列で、「S と 2000 年」のような食い違いが起きやすい（そのままだと詳細画面に「S.75年」と出る）。
  範囲は詳細画面の計算と同じ年の差で決める（昭和 1〜64 年・平成 1〜31 年・令和 1 年〜）
- **元号だけあって生年月日が空欄の行は、元号を保存する**（画面と同じ。表示は空欄）
- 生年月日が未来の日付か・メールアドレスの形式・郵便番号の形式は見ない（画面も見ていない）

### 4.4 プレビュー画面

**確定の欄**（V＝取り込める行の数、D＝重複候補の数）:

| 場合 | 出すもの |
|---|---|
| V > 0、D = 0 | 今と同じ（「インポート実行（V件）」のボタン）|
| V > 0、D > 0 | チェックボックス「重複候補もインポートする」とボタン。**ボタンの件数はチェックに合わせて変わる**（入れると V＋D 件）|
| V = 0、D > 0 | チェックボックスを出す。**チェックを入れるまでボタンを出さず**、代わりに「重複候補だけです。取り込むときは、上のチェックを入れてください。」|
| V = 0、D = 0 | 確定のフォームを出さず、テナント・賃貸マンションと同じ文言と色で「インポート可能なデータがありません。CSVを修正してください。」|

- 押せないボタンは `disabled` にせず隠す（`disabled` の要素の `title` はホバーで出ない。Top trap #12）。理由は文字で出す
- サーバにも同じ歯止めがある（§4.2 の 7）。JavaScript が動かずボタンが出たままでも、0 件の確定は断る
- Alpine は今の `csvImport()` を広げる: `validCount`・`dupeCount`（サーバが埋める）・`includeDupes`・`importCount()`。
  関数は `<script>` の中に書く（属性にアロー関数を書かない。Top trap #4）。チェックボックスに `x-model="includeDupes"`
- ボタンとその説明は、それぞれを包む要素に `x-show` を付けて出し分ける（ボタン自身の `style=` に触らない。Top trap #5・Bug #32）。
  最初に描く状態はサーバが決める（V = 0 ならボタンを包む要素を `display: none` で描く）ので、開いた直後に一瞬出て消えることがない
- ボタンの文字は「インポート実行（」で始まる形のまま（件数の部分だけ `x-text` で入れ替える）
- 変えないもの: 件数の行（全・正常・エラー・重複候補）、エラー行と重複候補の一覧、チェックボックスの文言、「← やり直す」

### 5.1 Feature テスト（`tests/Feature/Admin/CustomerImportTest.php`）

**往復のやり方**: プレビューが描いた確定のフォームを `ParsesForms::parseForm()`（`action="…"` で探す。プレビューの画面には
このフォーム 1 つだけ）で分解し、そのまま送り返す。`confirmed` と `_token` が描かれていることもアサートする（Bug #47）。
送信は `from('/admin/customers/import')` で行い、転送をたどって**着いた画面で**文言を見る（Bug #63）。
チェックボックスは、フォームに描かれていることを確かめてから値を足す（利用者がチェックを入れるのと同じ）。

**場面**:

1. 正しい 2 行 → 2 人入り、部署（取得日・ランク C）も入り、「2件のインポートが完了しました。」
2. 値の変換: `1980/1/2` → 1980-01-02 ／ `昭和` → `S` ／ `２` → 2 ／ `2026/9/1` → 2026-09-01
3. **正しい行の後ろに誤った行**（`昭和55年1月2日`・`2人`・`2026-02-30`・`19800102`）→ プレビューでは誤った行だけが
   エラーになり、確定では正しい行だけが入る。エラーは役割（`viewData('rowErrors')` の行番号と文言）と
   画面の表示（「⚠ 行N: …」）を別々に見る（Bug #54 ④）
4. アンケート: 設問の列・来場分譲地名・担当者名 → アンケート（日付・分譲地・担当者）と回答が入る
5. 取り込める行が 0 件 → 確定のフォームが無く（`csv_data` の hidden も無い）、文言が出る
6. 重複候補だけ → 最初はボタンが隠れている。チェックなしの確定は断られ（理由が出て 0 件）、チェックありなら入る
7. 正しい行と重複候補 → チェックの有無で入る件数が変わる
8. `csv_data` が無い・壊れている → 取込の画面に「CSVファイルにデータがありません。」、0 件
9. 確定の送信で `department` を書き換える → 取込の画面に戻り、理由が出る
10. `csv_data` を書き換えて誤った行を混ぜる → 確定でもその行は入らない
11. 書き込みの途中で失敗させる（**2 行目**で失敗させる。1 行目だと巻き戻しを消しても 0 件のままで緑になる。Bug #64 で踏んだ形）
    → 1 行目も巻き戻り、取込の画面に「インポートに失敗しました」
12. テンプレート（住宅・不動産）の見出しで、設問の列（Q…）以外はすべて `BuyerCsvRow::COLUMNS` にある

## 6. やらないこと（BACKLOG に書く）

- CSV の中の同じ人の 2 行（両方とも登録される。§2.2 の G）
- 重複の確認で、都道府県・市区町村が空欄の行は既存の顧客と照合されない可能性が高い
  （空欄は NULL で保存されるのに、確認は空文字と比べる。コードからの推測で未実測）
- 複数選択の回答の保存形式（画面は JSON の配列・取込は `A,B`）
- 分譲地名（前方一致）・担当者名（部分一致）のあいまいな照合
- 設問の列（Q1:…）が並び順で設問と結びつくこと
- 引用符の中の改行（行を `explode("\n")` で分けるので壊れる）
- テンプレートに記入例が無いこと
- 断られると確認画面の内容が消えて取込の画面に戻ること（今と同じ。BACKLOG の既存の範囲外）
- 確定で例外が出たときの文言が英語のまま（`$e->getMessage()`）
