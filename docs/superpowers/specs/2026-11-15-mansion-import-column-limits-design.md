# 賃貸マンションの CSV 取込で、本番の列に入らない値をその行の誤りにする — 設計（短）

日付: 2026-11-15 ／ 利用者の承認: 2026-11-15（「このとおり」）
前の作業: docs/RULES.md Bug #131 の範囲外「賃貸マンションの取込は総戸数・階数・部屋の階・構造・間取りの上限を見ない」

## なぜ

賃貸マンションの取込（`/admin/mansion-import`・`Admin\MansionImportController`）は、本番の列に入らない値を行の検査で断らない。
本番の MySQL は strict なので、確定で例外になり、`importFailed()` の総称の文（「行N まで進んだところでデータベースのエラーが起きました。1件も登録していません。…」）で
**全行が取り消される**。どの値が悪いかは画面に出ない。テストの SQLite は長さも範囲も見ないので、今までのテストでは原理的に見えない（Bug #40 / #54 / #72 と同じ形）。
画面（`Mansion\*Controller`）の入力チェックはもう列に合わせてある。取込だけが外れている。

## 数えたこと（2026-11-15・コードと `database/sql/create_mansion_tables.sql` の突き合わせ）

列に入らない値を通す列は 24 列。

| タブ | 列（本番の上限） | 今の取込 |
|---|---|---|
| 物件 | オーナー名 100・郵便番号 10・構造 50 文字 | 長さを見ない |
| 物件 | 総戸数 0〜65535（SMALLINT UNSIGNED）・階数 0〜255（TINYINT UNSIGNED） | 0 以上の整数だけ |
| 部屋 | 階 0〜255・間取り 20 文字・面積 0〜999999.99（DECIMAL(8,2)） | 上限・長さを見ない |
| 部屋 | 家賃・共益費・敷金・礼金（INT UNSIGNED＝0〜4294967295） | `is_numeric` で 0 以上だけ |
| 駐車場 | 月額料金 | 同上 |
| 入居者 | 電話番号・緊急連絡先電話 20・勤務先・緊急連絡先氏名 100・続柄 50 文字 | 長さを見ない |
| 部屋契約 | 家賃・共益費・敷金・礼金 | 同上 |
| 駐車場契約 | 月額料金・敷金 | 同上 |

あわせて見つけたこと: 金額の検査が `is_numeric` なので、`55000.9` は黙って 55000 で保存され、`1e10` も通る（画面の検査は `integer`）。
本番の `ms_rooms`・`ms_parkings`・`ms_tenants`・契約の表は 0 行（2026-11-13 の読み取り）＝部屋から後のタブは先回りの直し。

## 決めたこと（利用者の決定 2026-11-15）

1. 範囲は 6 タブの 24 列すべて（上限は画面の入力チェックと同じ値）
2. 構造・間取りは長さだけ見る（選択肢に限らない。Bug #131 で、編集画面は選択肢に無い値も残す形にした）
3. テナントの取込（`TenantImportController`。長さの検査が 0 件・同じ形の列が約 25 列）は別の作業にする
4. 金額は整数だけを通す（`55,000` のカンマはこれまでどおり通す）

範囲の外: 備考・メモ（TEXT・65,535 バイト。画面も長さを見ていない）・物件の `total_units` を部屋の取込の後に数え直す処理（部屋が 65,536 件を超えないと起きない）。

## 方針

- 誤りはその行のエラーにし、ほかの行は取り込む（既存の行の検査と同じ形。ZEAL 会員の取込の Bug #72 の B と同じ考え方）。確定でも同じ検査をやり直す（今と同じ）
- 長さは `mb_strlen`（MySQL の utf8mb4 の VARCHAR は文字数で数える）。文は既存の形「{見出し}は{上限}文字以内で入力してください」
- 数の上限を超えたときの文は画面の入力チェックと同じ言い方「{見出し}「{値}」は{上限}以下の値にしてください」
- 形の誤り（数でない・小数・負）の文は今の文のまま（部屋・部屋契約・敷金は「…は不正な値です」・月額料金と総戸数・階数・階は「…は0以上の整数で入力してください」・面積は「…は不正な値です」）
- 金額の読み方は 1 か所の部品にまとめる（カンマを除いて `ctype_digit`・上限は基底 `Controller::MAX_UNSIGNED_INT_COLUMN`）
- 検査の位置: 部屋契約・駐車場契約は今の「日付 → CSV 内の重複 → 照合 → 金額」の順を保つ（登録済みの行は金額に誤りがあってもスキップ）。物件・入居者の新しい長さの検査は登録済みのスキップより後ろ（登録済みの行はスキップのまま）
- オーナー名は、自社所有で保存しない行でも長さを見る（画面の入力チェックと同じ。こちらの判断）

## 守ること

- テストは上限ちょうど（文字は全角で埋める＝`strlen` に戻す変異を捕まえる）と 1 つ超えの対。超えた行がその行の誤りになり、確定で書かれないことを件数で見る（SQLite は長さを見ない）
- 変異で効いていることを確かめる（docs/RULES.md Bug #44 の作法）
