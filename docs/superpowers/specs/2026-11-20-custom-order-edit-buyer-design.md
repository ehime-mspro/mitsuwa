# 住宅事業: 注文住宅の編集画面でも買主を選ぶ（設計・短）

日付: 2026-11-20 ／ 利用者の決定: 2026-11-20（判断待ち ⑥ を「案のとおり」で進める）

## なぜ

注文住宅の**編集画面だけ**、顧客名が自由入力のまま残っている。しかも検索先は**テナントの顧客**
（`/api/tenant/customers/search`。住宅事業の買主とは別の表）で、住宅事業だけの人は 403 になる。
保存は `customer_id` を受け取らない（`exclude`）ので、顧客名だけが変わり、紐付く買主と**食い違う**。
登録画面・契約の編集画面（契約一覧から）はすでに買主を選ぶ形なので、編集画面だけが穴になっている。

前例: 建売の契約の編集画面（物件詳細から）の同じ形を `91368c05` で直した（`PropertyContractEditBuyerTest`）。

## 今（2026-11-20 にコードを読んだ）

| 画面・経路 | 顧客の扱い |
|---|---|
| 注文住宅の登録（`CustomOrderController::store`） | 買主を選ぶ（`housing/contracts/_buyer-select`）・買主は必須・顧客名は買主の名前で上書き |
| **注文住宅の編集（`CustomOrderController::update`）** | **顧客名の自由入力＋テナントの顧客の検索・`customer_id` は `exclude`** |
| 注文住宅の契約の編集（`HsContractListController::updateCustomOrder`） | 買主を選ぶ・必須・上書き（住宅事業の買主＋今の買主〈削除済みも〉を並べる） |
| 買主のランク | `HsCustomOrder` の saved フックが、契約以降の案件で `customer_id` が変わったら新しい買主を「成約」にする（もうある） |

## 本番（2026-11-20 に読み取りで数えた。件数だけ）

- 注文住宅 4 件（4 件とも契約以降）
- **買主が紐付いていないもの 1 件**（契約以降）
- 紐付いている 3 件: 買主の行が無い 0・削除済みの買主 0・住宅事業にいない買主 0・**顧客名が買主の名前と違う 0**
- 住宅事業の買主 9 人 ／ `laravel.log` は Nov 18 01:45 のまま

## 目標・目標でないこと

- 目標: 編集画面でも買主を選ばせ、保存で顧客名と買主を必ず一致させる。テナントの顧客の検索をこの画面から外す
- 目標でないこと: 前の買主のランクを戻すこと（成約のまま＝設計書の決定）／買主の選択の部品そのものの見直し／
  建売・注文住宅のほかの画面
- 失敗とみなすこと: 買主が紐付いている案件を何も変えずに保存して断られる（Bug #130 の形）・
  削除した買主が選択肢から消えて保存で別の人に変わる（Bug #58・#113 の形）

## 進め方（案）

| 案 | 中身 | 採否 |
|---|---|---|
| **A** | 登録と同じ買主の選択を編集画面にも出す。保存は買主を必須にし、顧客名は買主の名前で置き換える | **採用（利用者の決定）**。登録・契約の編集・前例とそろう |
| B | 編集画面では買主を変えさせず、顧客名を読み取り専用で出す（変えるのは契約の編集画面だけ） | 買主の無い 1 件をこの画面から直せない。画面ごとに扱いが分かれる |
| C | 自由入力のまま、検索先を住宅事業の買主に替える | 自由に打てる限り、顧客名と買主の食い違いが残る |

## 決めたこと

1. 編集画面の顧客情報は登録画面と同じ部品（`_buyer-select`）。今の買主が選ばれた状態で開く。
   選択肢は住宅事業の買主＋今の買主（削除済みなら「（削除済み）」で残す。契約の編集画面と同じ）。「新規顧客を登録」も使える
2. 自由入力・テナントの顧客の検索・「顧客登録」（テナントの顧客の登録画面へのリンク）は外す
3. 保存は買主を必須にし、顧客名は選んだ買主の名前で置き換える（`store`・`updateCustomOrder` と同じ）
4. 契約済みの案件で買主を変えたら、新しい買主が「成約」になる（今ある saved フックのまま。前の買主は成約のまま）

## 本番への影響

- 買主の無い 1 件は、次に編集画面で保存するとき買主を選ぶ必要がある（契約の編集画面はもう必須）。
  選ぶと、その買主が住宅事業で「成約」になる
- 顧客名が買主の名前と違う案件は 0 件＝紐付いている 3 件は、保存しても顧客名は変わらない

## 実装の側に任せたこと（私の判断）

- 編集の選択肢の組み立ては、今ある 3 か所（建売の契約の編集 2・注文住宅の契約の編集）と同じ書き方にする
- `customer_name` の入力チェックは今のまま（`required`。登録と同じ）。保存する値は買主の名前で置き換える
- 画面の JS から顧客の検索の関数と状態（`searchCustomer`・`selectCustomer`・`customerResults`・`customerError`・`customerName`）を外す。
  それを動かしていたテスト（`Housing\Screens\GetAjaxFailureTest` の注文住宅の顧客の検索）は外し、GET の Ajax の走査の下限が足りるかを数え直す
- テストの土台の `customOrder()` は買主なしで作るので、編集画面から送るテストは買主を付けて作る形に直す
  （`JsEmbeddingTest` の難しい顧客名は、買主の名前の側で見る）
- 回帰テストは前例と同じ組み: 画面が買主の選択を描きテナントの検索を持たない・描いたフォームの往復で
  買主と顧客名が両方変わる・買主が無い送信を断る・契約済みで買主を変えると新しい買主が成約・
  削除済みの今の買主が選ばれたまま保存できる・買主の無い案件の編集画面は未選択で開き、選んで保存できる
