## 1. 目的と範囲

**目的**: 紙の押印と決裁申請書の保管・台帳づけを、システムの印・PDF・決裁台帳に置き換える。

**できたと言える状態**（利用者と確かめた）
- 申請の詳細・PDF・台帳のどれでも、見られる人にだけ見られる申請が出る（7 章）
- PDF を印刷すると、紙の決裁申請書の代わりとして回覧・保管に使える
- 使い始める前の本番では、見た目は何も変わらない（⑦ の「印に使う文字」だけは先に整えられる）

### 1.1 作り方（D2）

段階2・3 と同じく、**設計書はこの 1 本、作るのは 2 回**に分ける。それぞれ、できたら本番へ出す（使い始めるまで、申請の画面・PDF・台帳は誰にも見えない。§5.2）。

| 回 | 中身 | 節 |
|---|---|---|
| **4a** | 電子印（申請の詳細）・PDF・⑦ の「印に使う文字」・PDF の出力の記録 | §5.3〜§5.7 |
| **4b** | 決裁台帳（⑤）・Excel 出力・Excel の出力の記録 | §5.8〜§5.10 |

- 金額の明細表・坪数・坪単価・担当者・契約予定日・紙の決裁（取り込んだ過去分）と、それに関わる台帳の列（工事原価・粗利益金額・粗利率・契約予定日・区分）は**段階5 で足す**（D1）
- 出力の記録を見る画面
- 後回しにしている 3 つ（決裁の小窓のキーボードの扱い・基幹のほかの一覧 31 か所のページ番号・二度押し止めの部品が 2 つある件）は段階4 の範囲に入れない（2026-10-03 に利用者は段階4 の設計を選び、これらは別の選択肢として残った。BACKLOG の 2b の節）

| D4 | 差戻しのあと出し直した申請の PDF | **今の回だけ**を載せる。「2 回目の提出」のように回数を添え、前の回のやり取りは画面の履歴で見る |

| D14 | PDF の紙面 | 紙の様式（`決裁申請書.xls`）の枠を使い、使わない欄（決裁区分・項目番号・関連部門）を外す。題の下に「状態」と「何回目の提出か」。部門長のコメントは承認の欄の印の下。条可は決裁者コメントが条件で、確かめたあとは「条件確認: 日時」。添付は件数とファイル名 |
| D15 | PDF の中身 | 申請の詳細と同じ（`RequestContent::for`。申請者以外には最後に提出した中身）。決裁の前は決裁No・決裁日・判断の○が空欄。部門長確認を飛ばした申請は承認の欄に「申請者が部門長のため省略」 |
| D16 | PDF の書体 | 題と枠の文字は明朝、中身はゴシック（どちらも IPAex） |
| D17 | PDF を出せる申請 | 提出したことのある申請（見られる人ならいつでも）。**下書きは出さない**（まだ誰にも回っていない） |
| D18 | PDF の出し方 | ブラウザでそのまま開く（スマホでも見られ、保存・印刷はブラウザから）。ファイル名は「決裁申請書_R8-J-021.pdf」、番号の前は「決裁申請書_申請 123.pdf」の形。作れなかったときは「PDF を作れませんでした。」と出し、laravel.log に残す |
| D19 | 台帳の中身 | 申請者本人以外には**最後に提出した中身**を出し、キーワード・部門の絞り込みもその中身で行う（差戻し中の直しかけを検索に掛けない） |
| D20 | 台帳の年度 | 決裁No の付いた申請はその番号の年度、付いていない申請は発信日の年度（どちらも申請部門の会社の期） |
| D21 | 台帳の申請者 | 名前の一部で探す（段階5 の紙の決裁は名字だけなので、それとも合う） |
| D22 | 台帳の並びと見た目 | 決裁日の新しい順（同じ日は決裁No の順。番号の無い申請は発信日）。1 ページ 50 件・ページ番号は今のページの前後だけ。列は「決裁No・決裁日・判断・件名・申請部門・申請者・金額・状態」。スマホは 1 件 1 枚のカード（14.4）。行から申請の詳細へ |

| D24 | Excel の形 | 絞り込んだ結果を全件。日付は Excel の日付、金額は数。見出しの行を固定し、見出しに絞り込みのボタン。文字の欄は**式にしない**（「=」などで始まっても文字として入れる）。ファイル名「決裁台帳_2026-10-05.xlsx」。件数に上限を設け、超えたら「絞り込んでから出してください」（数は計画で測って決める） |

## 4. 調べて分かった事実（2026-10-03 に実物で確認。13.x `27635bb0`）

### 4.1 無いもの・あるもの

- **PDF を作る部品は無い**（`composer.json`）。Excel は `phpoffice/phpspreadsheet` 5.9 があるが、**書き出しに使った前例は無い**（取込の読み込みだけ。`app` に Writer の呼び出しが無い）。PhpSpreadsheet は `ext-gd`・`ext-zip` などを要る＝本番にはある（無ければ Composer の起動時の確かめで止まっている）。手元は PHP 8.3.35・gd・zip・mbstring あり・`memory_limit` 128M
- **`approval_members` に「印に使う文字」の列は無い**（`can_view_all`・`is_admin` だけ）
- **`approval_download_logs` は `request_id` が必須**（`kind` のコメントは「attachment（段階4 で pdf / excel）」）。モデル `ApprovalDownloadLog` は追記のみ（`AppendOnly`）
- 部門の略称は `approval_departments.short_name`（6 文字まで・「データ印の上段に入るので」）
- 和暦の部品は `ApprovalFiscalYear::eraLabel()` だが**期（年度）の和暦**。印の日付は暦の年の和暦なので別に要る

### 4.2 判断の記録と中身の出し分け

- 判断を書くのは `Workflow::finishStep()` の 1 か所（`status`・`acted_at`・`actor_user_id`・`result`・`comment`）。押し間違いの取り消しで戻すのは `Workflow::reopenStep()` の 1 か所 → 印の控えもここで書き・消す
- 段階（`approval_steps`）は 1 回の提出で 3 行。`department_id` は部門長の段階は申請部門・審査の段階は審査部門の控え。部門長確認を飛ばした段階は `status = skipped`
- 中身の出し分けは `RequestContent::for()`（申請者以外には最後に提出した控え `approval_revisions` の今の回）。⑩ の一覧も控えの `snapshot` から件名を出している（`AdminRequestController`）
- 見られる範囲は `RequestVisibility`（1 件は `canView`、一覧は `apply`。規則は 1 か所）
- 申請の詳細の「回る順番」は `approvals/requests/_steps.blade.php`（コメントに「データ印は段階4」）

### 4.3 本番と反映

- `deploy.sh` は `vendor` ごと送る。`docs`・`tests`・`README*`（大文字）・`*.log`・`/storage/` は送らない
- 本番の決裁の表は 0 行（使い始める前。2026-10-02 の 3b の反映で確かめた）＝既にある判断の印の控えを作り直す必要は無い
- 本番の `memory_limit` と PHP の拡張は、まだ読み取っていない（計画の段で利用者の了承を取って読み取る）

## 5. 設計

### 5.1 全体の構成

```
申請の詳細（③）── 回る順番に印 ─────────┐
       └─ 「PDF」ボタン → PdfController ─┤
                                           ├─ 印を描く部品（SVG・1 つ）
PDF の紙面（Blade）→ mPDF ＋ IPAex ───────┘
決裁台帳（⑤）── 絞り込み（台帳の問い合わせ 1 つ）── 一覧（50 件）
       └─ 「Excel」ボタン → 同じ問い合わせで全件 → PhpSpreadsheet
出力の記録 → approval_download_logs（pdf ／ excel）
```

- 名前は仮（計画で決める）: 印を描く部品・印の文字を決める部品（既定と控え）・PDF の紙面と出力・台帳の問い合わせ（画面と Excel で共有）・Excel の書き出し

### 5.2 使い始めるまで（段階2 の D1 と同じ考え）

- PDF・台帳・Excel のルートは `approval.launched` を付ける（使い始める前は決裁のホームへ）。入口（サイドバー・ホームのリンク）も出さない
- ⑦ の「印に使う文字」は、⑦ そのものが使い始める前から開いているので、そのまま使える（D13）

### 5.3 表

| 表 | 回 | 変更 |
|---|---|---|
| `approval_members` | 4a | 「印に使う文字」（4 文字まで・空でもよい＝氏名からの既定）。行の無い利用者は、直したときに行を作る |
| `approval_steps` | 4a | 印の上段・下段の控え（判断したときに書く。取り消しで空に戻す）。下段は氏名全体が入りうるので氏名と同じ長さまで |
| `approval_download_logs` | 4b | `request_id` を空でもよくする・絞り込みの条件と件数を控える列（JSON）を足す。`kind` に `pdf`（4a から）・`excel` |

- 本番は SQL ファイル（`database/sql/`）で先に流し、テストは同じ形のマイグレーション（既存の方式）
- 控えの無い判断（4a より前の判断。本番には無い）は、今の設定から描く

### 5.4 電子印（4a）

- 押す場面: 部門長の承認・差戻し／審査担当者の可・保留・否／社長の可・条可・差戻し・否。飛ばした部門長確認は印の代わりに「申請者が部門長のため省略」
- 中身: 上段（D6）・中段（D7）・下段（D8）。判断した瞬間に上段と下段を控える（D3）。中段は判断の日時（`acted_at`）から描く
- 描き方: 赤い丸の中を 3 段に分ける（要件 9.1 の図）。部品は 1 つで、申請の詳細と PDF で同じ SVG を使う（D12）。下段の文字数で文字の大きさを変える
- 申請の詳細: 「回る順番」の判断した段階の横に印を出す（今の回）

### 5.5 「印に使う文字」（4a・⑦）

- ⑦ の編集の小窓に「印に使う文字」（4 文字まで・空なら氏名から。D9）。氏名・社員番号を直せない利用者（基幹を使う人・社長などに指定された人）でも、この欄と所属部門は直せる（D10）
- 変えたら設定の記録（`SettingLogger`）に前と後を残す
- 一覧に各人の印の見本を小さく出す（D11。日付は今日）

### 5.6 PDF（4a）

- 部品: mPDF ＋ IPAex ゴシック・明朝（TrueType）。フォントはリポジトリに同梱し、IPA フォントのライセンスの文書を一緒に置く（再配布の条件）
- 紙面（A4 縦・D14〜D16。見本は設計の対話で利用者に見せた形）:
  - 題「決裁申請書」・状態と回数
  - 決裁No・決裁日・発信日（最後の提出日）・受付日（今の回の審査部門に届いた日）
  - 決裁（可・条可・差戻・否の○）・社長の印・決裁者コメント ／ 申請部門・申請者名 ／ 承認（部門長の印・コメント）
  - 件名 ／ 金額・実施時期・関連する決裁No ／ 重点ポイント（5W2H。長ければ次のページへ）／ 添付の件数とファイル名
  - 審査部門（部門名・コメント・可・保留・否の○・審査担当者の印）
  - 各ページの下: 「決裁申請システムから出力 日時（出力者: 氏名）」とページ番号
- 出せる人・申請: その申請を見られる人（`RequestVisibility::canView`）・提出したことのある申請（D17）
- 出し方: ブラウザでそのまま開く（D18）。作れなかったときは画面に出して laravel.log に残す
- 測ること（計画の段）: いちばん重い申請（本文 20,000 文字・添付 20 件・コメント 2,000 文字）の時間とメモリ。本番の `memory_limit`・拡張（gd・mbstring）を読み取りで確かめる

### 5.7 出力の記録（PDF は 4a・Excel は 4b）

- PDF: 出力のたびに 1 行（`kind = pdf`・申請・人・IP・ブラウザ）。作れなかったときは記録しない
- Excel: 出力のたびに 1 行（`kind = excel`・申請は空・絞り込みの条件と件数）
- 記録を見る画面は作らない（D25）

### 5.8 決裁台帳（4b・⑤）

- 見られる範囲: `RequestVisibility::apply` で絞る（7 章の規則は 1 か所）。下書きは出さない
- 中身: 申請者本人以外には最後に提出した控えの件名・部門・金額などを出し、キーワードと部門もそれで絞る（D19）
- 絞り込み（要件 10）: 年度（D20）・部門・申請の種類・申請者（D21）・決裁日の期間・状態（既定は決裁No の付いたもの＝決裁済み・条件確認待ち・否決・番号のあと取り下げた欠番。進行中・取り下げも選べる）・判断（可・条可・否）・キーワード（件名・本文）
- 並びと見た目: D22
- 入口: サイドバー（決裁のみ利用者・基幹の PC とスマホの 4 か所）とホームのリンクの行に「決裁台帳」。使い始めるまでは出さない

### 5.9 Excel 出力（4b）

- 台帳の問い合わせをそのまま使い、全件（D24）
- 列: 決裁No・決裁日・判断・件名・申請の種類・申請部門・申請者・金額（税抜）・実施時期・関連する決裁No・提出日・審査の意見・審査のコメント・条件（条可のコメント）・状態（D23。段階5 の列は §8）
- 中身は台帳と同じ出し分け（D19）

### 5.10 Excel の記録（4b）

§5.7 のとおり。

## 9. 実装計画で決めること

1. mPDF の版と、フォントの置き場所（リポジトリの中・ライセンスの文書と一緒）・mPDF の一時ファイルの置き場所（`storage` の中）
2. 時間とメモリの実測（§5.6）と、本番の `memory_limit` の読み取り → 足りなければ利用者に相談（D5）
3. 印の SVG を mPDF で描けるか（描けなければ PDF だけ別の描き方にする。見た目は同じに）・下段の文字数ごとの大きさ
4. 印の控えの列の名前と長さ・`approval_members` の行の作り方
5. PDF の紙面の細部（列の幅・コメントが長いときの伸び方・ページの下の文字）と、テストで PDF の中の文字を確かめる方法
6. ファイル名の付け方（日本語のファイル名をブラウザに渡す形。添付の `AttachmentDelivery` に倣う）
7. 台帳の問い合わせ（控えの今の回を結ぶ形・並び・年度の数え方を SQL で）と、ページの部品（`_pager`・前後だけ）
8. Excel の件数の上限（メモリを測って）・列の幅・日付と数の書式・式にしない書き方
9. 出力の記録の条件の JSON の形
10. ルートの名前・入口の 4 か所・走査テストの登録（§4.4）

## 10. 実装の順番（案）

**4a**: 表（印に使う文字・印の控え）→ 印の文字を決める部品と控え（`finishStep`・`reopenStep`）→ 印を描く部品と申請の詳細 → ⑦ → PDF の部品とフォント → PDF の紙面と出力・記録 → 全件・変異・ブラウザ → ドキュメント → 本番反映
