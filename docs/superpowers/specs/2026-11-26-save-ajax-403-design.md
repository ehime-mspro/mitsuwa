# 保存の Ajax の 403 に日本語の理由を出す・一般担当にランクを押させない（設計メモ・短）

2026-11-26。利用者の依頼は「候補 1（番号だけを出す 8 か所で、403 のときにサーバーの日本語の理由を出す）で進めて」。
会話で決めたこと: 買主一覧のランクのバッジは案 A（一般担当には見せるだけ）・作り方は 1（共通の部品にまとめる）。

## なぜ

Bug #137 の直しで、保存の Ajax の 419・401 は日本語の理由を出すようになった。ところが 8 か所は 403 のときに
「ランクを変更できませんでした（403）」のような番号だけを出す。サーバー（ミドルウェア）は日本語の理由つきの JSON を返している。

| 403 を返すもの | 文 |
|---|---|
| 役割（`CheckRole`） | このページへのアクセス権限がありません。 |
| 部署（`CheckDepartmentAccess`） | この部門のデータへのアクセス権限がありません。 |
| 決裁のみの門番（`RestrictApprovalOnlyUsers`） | 決裁以外の画面は使えません。 |

8 か所のうち 7 か所は、ボタンを経営層・管理者にだけ出しているので、403 になるのは画面を開いたあとで役割か部署が変わったときだけ（まれ）。
**買主一覧（住宅事業・不動産で共用）のランクのバッジだけは一般担当にも押せる形で出ていて**、一覧は一般担当も開けるのに
ランク変更のルートは `role:executive,manager` なので、一般担当がランクを選ぶと普段の操作で必ず 403 になる（Bug #96 と同じ形）。

## 作り方（会話で決めた）

| 作り方 | 中身 | 引き換え |
|---|---|---|
| **1（選んだ）** 共通の部品にまとめる | 新しい部品 `resources/views/_partials/_ajax_save_failure.blade.php` に関数 `ajaxSaveFailureMessage(status, body, failed, fallback)` を 1 つ置き、8 か所が呼ぶ | 決まりが 1 か所に集まる（取得の部品 `_ajax_get_failure` と同じ形）。今動いている 419・401 の読み方も書き換える（#137 のテストが各か所にある） |
| 2 その場で足す | 8 か所の今の条件式に 403 の枝を 1 つずつ足す | 差分は小さいが、1 行が長くなり同じ判定が 6〜7 か所に並ぶ |

`ajaxSaveFailureMessage(status, body, failed, fallback)` の決まり（`failed` は「ランクを変更できませんでした。」の形の 1 文）:

1. 419・401 で本文の `message` が空でない文字 → その `message` だけ（今と同じ。サーバーの文は「…送れませんでした。画面を開き直して…」のように 1 文で完結している）
2. 403 で本文の `message` に日本語（ASCII 以外の文字）がある → `failed` ＋その `message`（判定は取得の部品・原価のカードと同じ）
3. ほか → `fallback`（呼ぶ側の今の番号つきの文）

- XHR の部品 `buyers/_xhr_failure_message` の `xhrFailureMessage` は、本文を JSON として読み（読めなければ本文なし）、中でこの関数を呼ぶ。引数に `failed` を足す（呼ぶ側 2 か所も直す）
- 仕入れ案件の小窓の 422（Bug #139 の理由）は今のまま先に見る
- 仕入れ先の簡易登録の 419 の独自の文（「セッションが切れました。ページを再読込してください。」）は変えない。401・403 とほかの番号はこの関数を通す

## 一般担当のランクのバッジ（案 A・会話で決めた）

- 買主一覧で、ランクを変えられる人（経営層・管理者＝ルートと同じ `isManagerOrAbove()`）にだけ、バッジを押せる形（`onclick`・`cursor: pointer`）で出し、ランクの小窓の要素と script を描く
- 一般担当にはバッジを見せるだけ（同じ色・`cursor: default`・`onclick` なし）。小窓と script は描かない
- 退けた案: B（押せるまま、断られたら理由を出すだけ＝一般担当は毎回断られる）・C（一般担当にもランクの変更を許す＝権限を広げる業務の判断）

## やらないこと

- サーバーの応答（403 の文・ミドルウェア）は変えない
- 8 か所のほかの番号（404・422・500 など）の文は変えない
- 決裁の画面・GET の Ajax・原価のカード（もう 403 の理由を出している）は触らない
- 一般担当に押せるのに断られるボタンがほかにも無いかの全件の洗い出しは、この作業ではしない（気づいたら記録する）
