- 作業場所: worktree `.claude/worktrees/route-coverage`・枝 `survey-question-admin`（13.x = `6ba8ed07` から）

## 1. 何のために作るか

買主のご来場アンケート（住宅事業・不動産で共用。設問は部署ごと）の設問を、経営層が画面で直せるようにする。

今の画面（2026-11-02 にコードで確かめた）は、追加と削除しかできない。

- 「編集」ボタンは一覧を開き直すだけ（`_question_item.blade.php` の 28〜29 行目）
- 「ドラッグ＆ドロップで並び替えできます」と書いてあり行に ☰ があるが、画面から並び替えを呼ぶ所が無い（サーバーの `update`・`reorder` のルートだけある）
- そのため、設問の文の言い直しや「選択肢を 1 つ足す」が画面からできない。回答がある設問は、無効にして別の設問として足し直すしかなく、回答が 2 つの設問に分かれる。無効にした設問は画面から有効に戻せない
- 選択肢は自由入力の JSON の欄でしか入れられず、スライダーの範囲（`settings`）を入れる欄が無い

成功の形: 経営層が、JSON を書かずに、設問の文・選択肢・種類ごとの設定・有効／無効・並び順を画面で直せる。直しても過去の回答は消えない。

## 2. 目標・やらないこと・失敗の形

### 目標
- 設問の追加と編集を、別の画面（ふつうのフォームの送信）で行う
- 設問の並び替えと、設問の中の選択肢の並び替えを ↑↓ のボタンで行う
- 回答がある設問の種類を変えさせない
- 選択肢の名前を変える・外すときに、その選択肢を選んだ回答の件数を出す
- 引き継ぎで挙がった今の不具合（§6）を、作り直しの中でなくす
- 並び替え・有効／無効・設問の文を変えたあと、前の顧客の CSV テンプレートの列が黙って別の設問に入らないようにする（D8）

### やらないこと
- 過去の回答を新しい選択肢の名前へ書き換えること（D3。過去の回答は元の名前のまま残す）
- 回答の集計の画面・買主の詳細に回答を出すこと
- 部署をまたいだ設問の移動（編集で部署は変えない）
- 設問の控え（`buyer_survey_answers.question_snapshot`）を読む画面（今もどこからも読んでいない。保存はそのまま続ける）
- 決裁の画面（`approvals/`。「社内決裁申請」の会話の担当）

### 失敗の形（動いても失敗とみなすもの）
- 設問や選択肢を直したことで、過去の回答が消える・別の値に変わる
- 回答がある設問の種類が変わり、前の形の回答が読めなくなる（Bug #120 の範囲外に書いた形）
- 入力エラーで戻ったとき、足した選択肢の行や入れた値が消える（Bug #86 の形）
- 手で組んだ送信で 500 になる（Bug #121・#92 の形）
- JSON を手で書かないと作れない設問が残る

## 4. 画面（承認された見本を文で写したもの）

### 4.1 一覧（`GET /admin/survey-questions`。今の画面を作り直す）
- 部署のタブは今のまま（`?department=`。決まった値だけ通す今の処理も残す）
- 各行: 左に ↑↓、真ん中に「番号. 設問の文」（番号は有効な設問だけの通し番号。CSV の `Q` の番号・アンケートの画面の並びとそろう。無効の設問には番号を出さない）・種類のバッジ・選択肢の数（スライダーは範囲の説明）・有効／無効・**回答 N件**（回答があるときだけ）、右に「編集」「削除」
- ↑↓ は押すたびに保存して一覧を開き直す。先頭の ↑・末尾の ↓ は押せない（押せない理由はボタンを包む要素で出す。Top trap #12）
- ☰ と「ドラッグ＆ドロップで並び替えできます」は外す
- 上の案内文を今の動きに合わせて書き直す: 「選択肢の名前を変えても、過去の回答は元の名前のまま残ります（アンケートの編集画面では「（選択肢に無い値）」と出ます）。回答がある設問は、種類を変えられません。」
- 「＋ 設問を追加」は別の画面（追加の画面）へのリンク。今の小窓は外す
- 「削除」は今と同じ意味（回答があれば無効にするだけ・無ければ消す）。確かめの小窓のあと、ふつうのフォームで送る
- 無効の設問は今どおり一覧に出す（行を薄くする）

### 4.2 追加の画面・編集の画面（同じフォームの部品を使う）
- 部署は表示だけ（追加は一覧で開いていたタブの部署・編集は変えられない）
- 設問の文（必須）
- 種類（7 種類）。追加の画面では選ぶと下の欄が切り替わる。編集の画面で回答がある設問は押せない形にし、「回答が N件あるため、種類は変えられません。」を出す（押せないフォームの欄は送られないので、サーバーは今の種類を使う。Bug #38 / #43）
- 状態: 「有効（アンケートの画面に出す）」のチェック
- 種類ごとの欄（§4.3）
- 保存の帯は `x-form-actions`（キャンセルは一覧のそのタブへ）
- 入力エラーは画面の上の赤い帯に 1 件ずつ出し、行も値も入れたまま描き直す
- 編集の画面で、回答がある選択肢の行には「この選択肢を選んだ回答が N件あります。名前を変えると、その回答は元の名前「…」のまま残ります。」を出す。行を × で外したときも、その回答は残る

### 4.3 種類ごとの欄
| 種類 | 欄 |
|---|---|
| 単一選択・複数選択 | 選択肢の行（↑↓・名前・×）。行を足す |
| 選択肢＋付随テキスト | 選択肢の行ごとに「文字も入れる」のチェックと、その欄の見出し（任意） |
| 条件分岐付き選択 | 設問の「付随の欄の見出し」（任意。D7）。選択肢の行ごとに「この選択肢を選んだときに出す欄」の行（見出し・文字か数・×）。欄を足す |
| テキスト入力 | 入力欄の見本の文字（任意） |
| 数値入力 | 下限・上限・単位（どれも任意） |
| スライダー | 下限・上限・刻み（必須）・単位（任意） |

### 4.4 顧客の CSV 取込（D8）
- 今の結びつけ方: 見出しの `Q{n}:` の n だけで「その部署の有効な設問を並び順に並べた n 番目」に結びつけ、`:` の後ろの文は見ていない（`Admin\CustomerImportController` の 87〜101 行目）。テンプレート（同 289〜292 行目）は有効な設問を並び順に `Q1:設問の文` と書き出す
- 変えること: `Q{n}:` の後ろの文（前後の空白を除いたもの）が、n 番目の設問の今の文と違う列が 1 つでもあれば、プレビューでファイルごと断る。文は「Q2 の列の設問「（見出しの文）」が、今の Q2「（今の設問の文）」と違います。設問の並びや文が変わっています。テンプレートをダウンロードし直してください。」の形（違う列はすべて並べる）。確定でも同じ検査をやり直す（確定は CSV を読み直す今の作り）
- n 番目の設問が無い列（`Q9:` で有効な設問が 6 問など）も同じく断る（今は黙って捨てている）
- 並び替え・有効／無効の変更・設問の文の変更のあとは、前のテンプレートが断られる。ダウンロードし直せば使える（取込の画面と一覧の案内文にその旨を書く）

## 5. 保存の形（今の形を変えない）

`survey_questions` の列は変えない（DB 変更なし）。`options`・`settings` の JSON の形は、今の読み手（`App\Support\SurveyAnswers`・`buyers/_survey_form.blade.php`）がすでに読んでいる形に合わせて書く。

| 種類 | `options` | `settings` |
|---|---|---|
| 単一選択・複数選択 | `["持ち家", "賃貸マンション"]` | null |
| 選択肢＋付随テキスト | `[{"value": "ご紹介", "has_text": true, "text_label": "ご紹介者"}, {"value": "チラシ", "has_text": false}]`（`has_text` はどの選択肢にも書く。本番の書き方。2026-11-02 の読み取り） | null |
| 条件分岐付き選択 | `[{"value": "建売住宅の購入", "sub_fields": [{"key": "city", "label": "希望の市", "type": "text"}, …]}, {"value": "リフォーム", "sub_fields": []}, …]`（`sub_fields` はどの選択肢にも書く。本番の書き方） | `{"sub_heading": "希望エリア"}`（新しいキー。D7） |
| テキスト入力 | null | `{"placeholder": "例: 3LDK"}` |
| 数値入力 | null | `{"min": …, "max": …, "unit": "坪"}`（入れたキーだけ） |
| スライダー | null | `{"min": 2000, "max": 6000, "step": 100, "unit": "万円"}` |

- 付随の欄のキー（`key`）: 今ある欄のキーは、見出しを変えても変えない（過去の回答の `sub` がそのキーで残っているため）。新しく足した欄には、その設問の中で使われていないキーを自動で付ける。キーは画面に出さない（D5）。今の本番の設問は、選択肢をまたいで同じキー（`city` など）を使っている — 編集で壊さない
- 選択肢の値は、画面に出す名前そのもの（今の仕組み。D3 で名前を変えると過去の回答と結びつかなくなる理由）
- 種類を変えたとき（回答が無い設問だけ）は、その種類で使わない `options`・`settings` を空にする

## 6. 一緒になくす今の不具合（引き継ぎの 3〜9。直す前に実測する）

| # | 今（コードからの推測を含む） | 作り直しのあと |
|---|---|---|
| 3 | 追加の XHR に `X-Requested-With` が無く、転送先の GET でフラッシュを使い切るので「設問を追加しました。」が出ない可能性が高い。422 は「追加に失敗しました」だけ | ふつうのフォームの送信になり、完了の文は一覧に出る。誤りは理由を出す |

| 6 | 追加の小窓の要素に静的な `style`（`display:none` と `display:flex`）と `x-show` が同じ要素に付いている（Bug #32 の形） | 小窓を外す |

| 8 | `reorder` は部署も id の実在も確かめない。`update` は回答があっても種類を変えられる | ↑↓ は 1 つの設問を同じ部署の隣と入れ替える。種類は D2 |
| 9 | 削除の XHR は 200 以外のとき何も知らせない | ふつうのフォームの送信になり、結果は一覧に出る |

## 7. 守ること（このアプリの決まり）

- Top traps（CLAUDE.md）: `Js::from` で JS に値を渡す（#76・`JsStringEchoScanTest`・`JsEchoClassificationTest`）、`<option>` を `x-for` で作らない（#3）、`x-data` にアロー関数を書かない（#4）、`style` と `:style` を併せない（#5・Bug #32）、日本語の欄の Enter に `$event.isComposing ||`（#6）、押せないボタンの理由は包む要素で（#12）、view データに `errors` を渡さない（#14）
- 入力チェックの和名（Bug #37・#110・#112）: 行の欄は「選択肢 2 行目の名前」のように `:position` で。走査 `JapaneseValidationMessagesTest` が読める書き方で
- 配列の形（Bug #121）: 行の配列には `array` の規則を置く。画面が `old('x')` で描く欄は、その画面のフォームの送り先すべてに規則を置く（`OldInputRuleCoverageTest`）
- 欄そのものが無い送信で 500 にしない（Bug #92）
- 入力エラーのあと、行を `old()` から描き直す（Bug #86。空の行も含めて同じ並び＝エラーの「N 行目」と画面の行がそろう）
- 長い値の折り返し（Bug #115・`LongUnbrokenValueWrapTest`）、絞り込みの行・2 列の 375px（Bug #114・#116・`MobileLayoutTest`）、削除の欄と保存の帯の重なり（Bug #108・`DeleteZoneBelowSaveBarTest`）
- テストは描いた画面のフォームから送る（Bug #47）。Alpine の行は `DrivesAlpineFetch::browserForm()` で組む

## 9. 作る人に任せたこと（設計の会話で私が決めたもの・違えば直す）

- 削除は一覧にだけ置く（編集の画面には置かない）
- 一覧の「番号.」は有効な設問だけの通し番号にし、無効の設問には番号を出さない（今は `sort_order` を出していて無効の設問も数える。CSV の `Q` の番号とそろえる。点検役の指摘・2026-11-02）
- 選択肢を × で外しても、その選択肢を選んだ過去の回答は残す（今の Bug #120 の読み戻しの動き）
- スライダーは下限 < 上限・刻み > 0・（上限 − 下限）が刻みで割り切れる、を求める。値は整数（Bug #120 の範囲外に書いた「小数の設定」を作らせない）
- スライダーの最初の位置（`SurveyAnswers::sliderState()` の「真ん中の値」。今は `(int) (($min + $max) / 2)`）を、下限から数えて刻みの上に寄せる（下へ切り捨て）。刻みの数が奇数の設定（例: 0〜300・刻み 100 で真ん中が 150）で、「回答しない」を外して動かさずに保存すると `checkSlider()` に断られる形をなくす（点検役の指摘・2026-11-02。本番の 2000〜6000・刻み 100 は 40 刻みで、今の値も変わらない）
- 部署は編集で変えない
- 並び替えは押すたびに保存（↑↓ ごとにフォームを送る）。新しいルートを足すか今の `reorder` を作り直すかは計画で決める。画面から呼ばれない今の `reorder` と XHR の JSON の応答は、使わなくなるなら外す（外すならルートの削除＝計画に書く）
- 選択肢の名前の長さ・選択肢の数・付随の欄の数の上限は、計画で決める（今の回答の検査の上限 `SurveyAnswers::TEXT_MAX`＝255・`SUB_TEXT_MAX`＝100 とそろえる）
- 同じ設問の中で同じ名前の選択肢は断る
- 選択肢ごとの回答の件数は、回答を `SurveyAnswers` の読み方で読んで数える（種類ごとに保存の形が違う）
- 一覧の「回答 N件」は `withCount('answers')`
- 数値入力の下限・上限を狭めると、アンケートの画面の数の欄（`type="number"` の `min`・`max`）が保存済みの範囲の外の値を持つ回答の送信をブラウザで止める（Bug #120 の範囲外に書いた形。今は本番に数値入力の設問が無いので起きない）。サーバーが検査するので、アンケートの画面の `min`・`max` の属性は外すか、範囲の外の保存済みの値があるときだけ外す（計画で決める）
