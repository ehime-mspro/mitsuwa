## 1. 目的と範囲

**目的**: 本番で、実際に役を受け持つ数人だけが申請を回して確かめ（受け入れ確認）、試しの申請を片付けてから、決裁の管理者が「使い始める」を押して全社で使い始められるようにする。

**できたと言える状態**
- 決裁の管理者が ⑬ で試す人を選ぶと、その人たちにだけ申請を回す画面が見え、お知らせ・メール・催促も試す人にだけ届く。ほかの人には今の「準備中」のまま
- 試す人が、スマホで申請から社長の決裁・差戻し・取り下げまで一通り回し、添付・PDF・台帳と Excel まで確かめられる
- 決裁の管理者が ⑬ で試しの申請を片付けると、申請と関わるものがすべて消え、決裁No の次の番号が試しの前に戻る
- 試しの申請が 0 件のとき、決裁の管理者が ⑬ で「使い始める」を押すと、全員に申請を回す画面が見える
- 試す人に配る「受け入れ確認の手引き」（写真付きの読みやすい版も）がある

### 1.1 使い始めるまでの流れ（D12）

| 順 | 段 | だれが | 段階6 で作るもの |
|---|---|---|---|
| 1 | 準備（部門・申請の種類・役の人・催促を送らない日の登録。要件 16.3） | 決裁の管理者・基幹の管理者 | なし（今ある画面） |
| 2 | 試す期間（試す人を選び、本番で申請を回す） | 試す人 | ⑬ の試す人・試しの印・知らせの絞り込み・提出の確かめ |
| 3 | 試しの申請の片付け | 決裁の管理者 | ⑬ の片付け |
| 4 | 社員の一括登録・ログイン案内 | 決裁の管理者 | なし（今ある画面） |
| 5 | 紙の台帳の取り込み（使い始める直前に 1 回。運用手順書 `docs/運用_過去の決裁の取り込み.md`） | 決裁の管理者 | なし（今ある ⑪） |
| 6 | 使い始める（切り替え日） | 決裁の管理者 | ⑬ の「使い始める」 |

- 3 のあとも試す期間は続く（試す人を外さない限り）。5 のあとに、紙の行を含む件数の多い台帳の Excel を試す人の決裁の管理者が本番で 1 回出して確かめられる（§5.10）
- 切り替え日はまだ決めない。試す期間の様子を見てから決める（D14）

### 1.2 段階6 でやらないこと（§8 に詳細）

一部の部門だけ先に本物の申請を回す運用・試しの申請を残すこと・使い始めたあと準備中に戻すこと・本番の php.ini を開発側で直すこと。

## 2. 決定事項（2026-10-26 の対話で確定）

D1〜D4・D11〜D15 は利用者が選択式で選んだ。D5〜D10 は流れの図と ⑬ の画面の見本に添えて開発側の案として示し、利用者が「このままでよい」と承認した。

| # | 論点 | 決定 |
|---|---|---|
| D1 | 試す期間の形 | **試す人（数人）だけ**が本番で試しの申請を回す。ほかの社員には見えない。試しの申請は使い始める前に消す（要件 16.2 の 3。段階2 の D1「試しのデータを本番に残さない」） |
| D2 | 試す人の役 | **本物の役の人**（社長は社長本人、部門長はその部門の部門長本人、審査は審査の担当本人）。試しのあいだの設定（部門・申請の種類・役・催促を送らない日・利用者）を**そのまま使い始めに持ち越す** |
| D3 | 確かめること | **一通りすべて**（スマホでの判断・メールと催促が届くか・添付と PDF と台帳・申請から社長の決裁、差戻し・取り下げまで） |
| D4 | 試す期間の知らせ | お知らせ・メール・催促は**試す人にだけ**届く |
| D5 | 試しの印 | 試す期間は、申請を回す画面のいちばん上に「試しの期間です。ここで出した申請は使い始める前に消えます」の帯を出す。**メールの件名に【試し】**を付ける。**PDF の上の余白に小さく「試し」**と出す（社長の印の付いた試しの PDF が本物に見えないように） |
| D6 | 試せる部門・種類 | 試しの申請を出せるのは、回る先の人（部門長〈飛ばす場合を除く〉・審査の担当の 1 人以上・社長）が**みな試す人に入っているときだけ**。⑬ に試せる部門・種類と、足りない人を出す |
| D7 | 試しの決裁No | 試しの申請にも、社長の判断で**本物と同じ形の番号**（R8-J-001 など）が付く |
| D8 | 片付け | 試しの申請と関わるものを**すべて消し**、決裁No の**次の番号を試しの前に戻す**。試す期間なら**何度でも**できる（試す → 直す → もう一度試す）。押す前に、消えるものの件数を出す確認の画面を挟む |
| D9 | 持ち越すもの | 部門・会社・申請の種類・役（部門長・審査の担当・社長・全件閲覧者・決裁の管理者）・印に使う文字・催促を送らない日・許可するメールのドメイン・利用者・紙の決裁・設定変更の記録は**消さない** |
| D10 | 使い始める | **試しの申請が 0 件のときだけ**押せる。**一度押すと戻せない**（本物の申請が見えなくなるのを防ぐ） |
| D11 | ⑬ を操作する人 | **決裁の管理者**（部門・申請の種類・紙の台帳の取り込みと同じ人たち） |
| D12 | 順番 | 試す → 片付け → 社員の一括登録 → 紙の台帳の取り込み → 使い始める（§1.1）。紙の台帳は片付けのあと（試しの申請が番号を使ったままだと、取り込みが断られたり、次の番号が食い違ったりするため） |
| D13 | 受け入れ確認の手引き | **作る**。運用手順書（`docs/` の Markdown）と、写真付きの読みやすい版（取り込みの運用手順書と同じ形）。役ごとにスマホで試すことと、本番でしか確かめられないこと（§5.10）を載せる |
| D14 | 切り替え日 | まだ決めない（試す期間の様子を見てから） |
| D15 | 夜間バックアップに残る試しのデータ | **残ってよい**。夜間バックアップは添付のファイルを保管先から消さず（`BackupRunner`）、DB の書き出しは 30 日分残す（`RetentionPolicy`）ので、片付けたあとも試しの添付はずっと、試しの申請の DB の行は最長 30 日、暗号化した形で保管先に残る。バックアップには手を入れず、手引きと要件 v1.16 に「バックアップには残る」と書き、**試す期間には本物の大事な書類を添付しない**よう手引きで頼む（2026-10-26 の設計書の点検で分かり、利用者が選んだ） |

## 4. 調べて分かった事実（2026-10-26 に WT approval-phase3 `018dfd95` のコードで確認）

### 4.1 使い始めたかの判定（段階2 §5.2・段階3 §5.2）

- `approval_settings.launched_at`（1 行だけ・id=1）。`ApprovalSetting::current()->isLaunched()` と、行を作らずに読む `ApprovalSetting::launchedForMenu()`（基幹の画面用）
- 判定を読んでいる所（どれも「使い始めたか」だけを見ていて、人によって変わらない）
  - 門番 `EnsureApprovalLaunched`（`approval.launched`）: 準備中は画面を開く GET・HEAD をホームへ、それ以外は 404。`SubstituteBindings` より前（存在しない ID でも同じ応答）
  - `HomeController`（準備中の画面 ／ `home-launched`）・`sidebar_approval.blade.php`（`current()->isLaunched()`）
  - `ApprovalMenu`（基幹のメニューの件数とベル。`launchedForMenu()`）・`HolidayController`（⑫ の表示）
  - `Notifier::send()`: 使い始める前は何もしない（`launchedForMenu()`）。宛先ごとに「操作した本人でない・削除していない・有効・担当の番を申請者本人に出さない」で絞る（`receives()`）
  - `ApprovalRemindCommand`: 使い始める前は「使い始める前なので送りません。」と記録して何もしない。宛先は `PendingWork::everyone()` の対応待ちの人
- 準備中も使えるルート（`approvals.home`・利用者・組織・申請の種類・催促の設定・紙の決裁の管理）と止めるルートは、全件分類のテストで分けてある（段階2 §5.2）

### 4.2 決裁No（段階2・段階5 §5.11）

- `approval_number_sequences`（部門 × 年度）に `next_number`（次に付く番号）と `last_issued`（使ったいちばん大きい番号）。社長の判断で `ApprovalNumber::issue()` が `next_number` を使って 1 進める
- 部門の管理の「今年度の次の番号」（`setNext()`）は、`last_issued` 以下と、今年度の紙の番号以下を断る
- 紙の決裁を足すと `advancePast()` が `next_number` を「紙の番号＋1」まで進める（戻さない）。取り込みの確定は、システムの申請がすでに使った番号とぶつかると断る（`d9cff2a3`）
- 紙の取り込みの取り消し（`PaperImportController::undo`）と紙の 1 件の削除も、次の番号を**戻さない**（部門の管理の開始番号で戻す）。⇒ 「開始番号と紙の番号＋1 の大きいほう」は、試しの前の次の番号と一致しないことがある（取り込み → 取り消し のあとなど）
- ⇒ 試しの申請が番号を使うと `last_issued` が上がり、片付けで申請を消しても**開始番号を元の数に戻せなくなる**（`setNext()` が断る）。片付けで連番の行も戻す必要がある

### 4.3 申請と関わる表（片付けの対象）

| 表 | 申請との結び付き | 片付け |
|---|---|---|
| `approval_requests` | — | 消す |
| `approval_steps` | 外部キー・ON DELETE CASCADE | 消す |
| `approval_attachments` | CASCADE。**ファイルの本体は `Storage::disk('local')` の `stored_path`** | 行とファイルを消す |
| `approval_revisions` | RESTRICT | 消す（申請より先に） |
| `approval_histories` | RESTRICT。要件 14.2 で「変更・削除不可」 | 消す（§3 の 14.2 の例外） |
| `approval_download_logs` | 添付・PDF は申請を指す（RESTRICT）。台帳の Excel は申請を指さない | **申請を指す行（添付・PDF）だけ消す**。台帳の Excel の行は残す（要件 14.2 の持ち出しの記録。紙の台帳を取り込んだあとの Excel は実物の紙の決裁を含む） |
| `notifications`（`type = 'approval'`） | `approval_request_id`（RESTRICT） | 決裁のお知らせをすべて消す（使い始める前は作られないので、すべて試しのもの） |
| `approval_reminder_runs` | 申請を指さない | 試す期間の行を消す（⑫ の「前回の催促」に試しの分を出さない） |
| `approval_number_sequences` | 申請を指さない | 試しの前の状態に戻す（§5.7） |
| `jobs`（メールの送信待ち） | 申請を指さない。**基幹と共用** | 触らない（§5.7） |

- 消さない表: `approval_settings`（`launched_at` 以外の値も）・`approval_setting_logs`・`approval_members`・部門・会社・種類・`approval_type_department`・`approval_holidays`・`approval_mail_domains`・`approval_paper_records`・`approval_paper_imports`・`users`

### 4.4 本番（2026-10-13 の読み取り。段階5b の BACKLOG）

- 部門 2・申請 0・連番の行 0・`launched_at=NULL`
- `memory_limit=128M`・`upload_max_filesize=5M`・`post_max_size=8M` は CLI で読んだ値。Web の値は読んでいない（`phpinfo` を本番に置かない）。公開フォルダの上の `~/www/php.ini` は `upload_max_filesize = 512M`・`post_max_size = 512M`（2026-09-27 の読み取り）で、Web のアップロードには 512M が効く見込み。メモリの上限は 128M と見ている。⇒ 10MB の添付・重い PDF・件数の多い Excel が本番の Web で通るかは、試す期間に実物で確かめる（§5.10）

## 5. 設計

### 5.1 3 つの状態

| 状態 | 条件 | 申請を回す画面が見える人 | 知らせ |
|---|---|---|---|
| 準備中 | `launched_at` が空で、試す人が 0 人 | だれも見えない（今のまま） | 出さない（今のまま） |
| 試す期間 | `launched_at` が空で、試す人が 1 人以上 | **試す人だけ** | **試す人にだけ** |
| 使い始めた | `launched_at` が入っている | 全員（今の「使い始めた」と同じ） | 全員（今のまま） |

- 判定は **1 か所**にまとめる（例: 「この人に申請を回す画面を見せるか」「この人に知らせを出すか」「今は試す期間か」）。§4.1 の読んでいる所をすべてそれに置き換える。人を指さない所（催促のコマンドの最初の判定など）は「試す期間か使い始めたか」で分ける
- 試す人を全員外すと準備中に戻る（試しの申請は残る。片付けは別の操作）

### 5.2 門番・ホーム・メニュー

- 門番 `approval.launched`: 試す期間は、**試す人なら通す**。試す人でない人は、準備中と同じ応答（画面を開く GET・HEAD はホームへ、それ以外は 404。存在しない ID でも同じ）
- ホーム・決裁のサイドバー・基幹のメニューの件数とベル: 試す人には「使い始めた」の形、ほかの人には今の「準備中」の形
- 全件分類のテストは、止める側のルートを「試す期間に試す人は通る・試す人でない人は準備中と同じ」で確かめるように広げる。⑬ のルートは「準備中も使える」（管理）に入れる
- ⚠ 基幹の画面では今の `launchedForMenu()` と同じく、設定の行を作らずに読む（問い合わせの本数を見るテスト PropertyListSortTest。段階2b で実測）。試す人の判定も基幹の画面で問い合わせを増やしすぎない（§10）

### 5.3 試す人

- 持ち方は利用者ごとの印（例: `approval_members` に列を 1 つ足す。表を足すかは §10）。本番は SQL で列を足し、テストは同じ構造の migration
- 試す人にできるのは**有効な利用者**だけ（決裁のみ利用者でも基幹を使う人でもよい）。無効にした人・削除した人は、試す人のままでも見えない・届かない（今の `receives()` と同じ）
- 出し入れは ⑬ で 1 人ずつ。設定変更の記録（`approval_setting_logs`）に残す
- 試す人から外した人は見えなくなる。その人の試しの申請は片付けまで残る（回る先の人が外れたら、その申請は止まる）
- 使い始めたあとは、試す人の印は使わない（消すか残すかは §10。画面には出さない）

### 5.4 試せる部門・種類と、提出の確かめ（D6）

- 試す期間の**提出・出し直し**で、回る先の人を確かめる: 申請の部門の部門長（申請者が部門長なら飛ばすので見ない。要件 4.3）・種類の審査部門の審査の担当の 1 人以上・社長。だれかが試す人でなければ断り、足りない人の名前と役を出す（例: 「試す期間は、回る先の人がみな試す人のときだけ出せます。ミツワ不動産の部門長（田中 次郎）が試す人に入っていません。」）
- ⑬ に、部門ごとと種類ごとに試せるか（○ ／ × と足りない人）を出す。種類に使える部門の限り（5.5.1）がある種類は、その部門だけで見る（細部は §10）
- 提出のあとの担当の入れ替わり（付け替え・部門長の交代・社長の交代・審査の担当の変更）は断らない。新しい担当が試す人でなければ、その申請は止まる（知らせは出ない。§5.5）。止まった申請は片付けで消える
- 審査の担当が複数いて一部だけ試す人のときは、試す人の担当にだけ届く（誰か 1 人が入れれば次へ進む今の決まりのまま）

### 5.5 知らせと催促（D4・D5）

- `Notifier`: 試す期間は、今の絞り込み（`receives()`）に「**試す人であること**」を足す。お知らせもメールも同じ。使い始めたあとは今のまま
- メールの件名: 試す期間は先頭に【試し】（お知らせのメール・催促のまとめメールとも）。今は件名を 2 か所で別々に組んでいる（`ApprovalNoticeMail.php:33`「【決裁】…」・`ApprovalReminderMail.php:33`）ので、【試し】を付ける所を 1 か所にまとめる。付けるかどうかはキューに積む時点で決めてメールに持たせる（キューの中で設定を読まない今の決まり）
- 催促のコマンド: 試す期間は、対応待ちの人のうち試す人にだけ送る。送らない日・1 日 1 回・20 件までの決まりは今のまま。記録の言葉は今の形に合わせる（例: 「試す期間なので試す人にだけ送りました（2 人・3 件）。」の細部は §10）
- 段階3 §5.2 の申し送り（Notifier と催促の「使い始めたか」の判定の見直し）はこれで閉じる

### 5.6 試しの印（D5）

- 帯: 試す期間に、申請を回す画面と決裁の管理の画面（決裁のみ利用者の画面・基幹の画面のどちらの枠でも）のいちばん上に出す。文言「試しの期間です。ここで出した申請は使い始める前に消えます。」。目立つが操作を邪魔しない色（警告の色）。スマホの幅でも 1〜2 行
- PDF: 試す期間に作る PDF の上の余白に小さく「試し」。本文・印の位置は変えない（紙と同じに見えるかを確かめるため）
- 台帳の Excel: ファイル名の先頭に「試し_」を付ける（中身は変えない）
- 片付けのあとも試す期間なら印は出る（D8 の「もう一度試す」のため）。使い始めたら出ない

### 5.7 片付け（D8）

- ⑬ の「試しの申請を片付ける」→ 確認の画面（消えるものの件数: 申請・番号を付けた申請・添付・お知らせ・出力の記録・催促の記録、と「戻す次の番号」の部門ごとの一覧）→ 「片付ける」で確定
- できるのは試す期間（と準備中）だけ。**使い始めたあとはできない**（ルートごと断る）
- 消すもの・残すものは §4.3 の表のとおり。DB の行は 1 つのトランザクションで消し、添付のファイルは commit のあとで消す（ファイルが消えなくても DB は戻さない。消せなかった数を画面に出す）
- **決裁No の次の番号**: 片付けのあと、試しの申請が付けた番号のある連番の行（部門 × 年度）ごとに、`last_issued` を 0 に、`next_number` を**「試しの申請が無かったら付いていた番号」**に戻す。そのために、連番の行ごとに「試しの採番だけを除いた次の番号」を覚えておく（**部門の管理の開始番号〈`setNext()`〉と紙の番号〈`advancePast()`〉では動き、社長の判断の採番〈`issue()`〉では動かない値**。例: 連番の行に列を 1 つ足す。持ち方は §10）
  - ⚠ 「開始番号と紙の番号＋1 の大きいほう」で計算し直す形にはしない（§4.2: 取り込み → 取り消し のあとに 1 へ戻り、実物の紙の番号と同じ番号をシステムが付けるおそれがある。要件 6.4 が防ぎたいこと）
  - ⚠ 試しの申請の最小の番号から割り出す形にもしない（試す期間に開始番号を上げると食い違う）
- 試す期間に年度が変わったとき（ミツワは 5 月）も、行ごとに戻す
- 片付けの最中に試す人が操作したとき（提出や社長の判断と重なる）の扱いは §10（例: 設定の行をロックして順番に並べる）
- `jobs` の送信待ちのメールは触らない（基幹と共用のため）。片付けの前に送られた試しのメールのリンクは、片付けのあとは開けない（今の「無い申請」と同じ応答）
- 片付けたこと（だれが・いつ・消した件数・戻した番号）を設定変更の記録に残す

### 5.8 使い始める（D10・D11）

- ⑬ の「使い始める」→ 確認の画面 → 「使い始める」で `launched_at` に今の時刻を入れる。設定変更の記録に残す
- 押せるのは、**試しの申請が 0 件**のときだけ。0 件でなければ、片付けを先にと断る
- 押す前の確かめとして、⑬ に次の様子を出す（押すのを止めるのは試しの申請だけ。ほかは知らせるだけ）: 社長が指定されているか・部門と申請の種類が 1 つ以上あるか・紙の決裁の件数
- **戻す画面は作らない**（`launched_at` を空に戻す操作は無い）
- 使い始めたあとの ⑬ は、使い始めた日時と押した人だけを出す

### 5.9 ⑬ 使い始め（D11）

- 決裁の管理の画面の 1 枚。門番は `approval.admin`（決裁の管理者）だけ。準備中・試す期間・使い始めたあとのどれでも開ける
- 管理の画面へのリンクを出している所（決裁のサイドバー `sidebar_approval`・基幹のサイドバー `sidebar`・決裁のホーム `home`／`home-launched`）に、ほかの管理の画面と並べてリンクを足す
- 上から 4 つの欄: 1 試す人（一覧と外す・利用者を選んで足す）／ 2 試せる部門と種類（○ ／ × と足りない人）／ 3 試しの申請（件数と「片付ける」）／ 4 使い始める（状態の表示と「使い始める」）。見出しの横に今の状態（準備中 ／ 試す期間 ／ 使い始めた）
- 利用者を選ぶ欄は、利用者が 100 人を超えても選べる形にする（既存の部門長の選び方は一覧から選ぶ `<select>`。合わせるか、探しやすい形にするかは §10）

## 6. テスト

- 3 つの状態（§5.1）× 人（試す人 ／ 試す人でない ／ 決裁の管理者 ／ 基幹の管理者）で、門番・ホーム・サイドバー・基幹のメニューの件数とベルが表のとおりになること。全件分類のテストを広げ、止める側のすべてのルートで、試す期間に試す人でない人が準備中と同じ応答（存在しない ID でも同じ）になること
- 知らせ: 試す期間に、試す人でない担当・申請者には、お知らせもメールも出ないこと。メールの件名の【試し】の有無（試す期間 ／ 使い始めた）
- 催促: 試す期間に、試す人でない人の対応待ちを送らないこと。準備中は今のまま送らないこと
- 提出の確かめ: 部門長・審査の担当・社長のそれぞれが欠けたときに断ること、申請者が部門長のときは部門長を見ないこと、審査の担当の 1 人が試す人なら通ること
- 片付け: §4.3 の消す表がすべて 0 件になり（出力の記録は申請を指す行だけ）、残す表が変わらないこと（台帳の Excel の出力の記録を含む）。**`approval_` の表と `approval_requests` を指す外部キーを機械的に列挙し、「消す」「残す」のどちらかに分類されていない表があれば落とす**（表が増えたときに片付けの漏れに気づく。全件分類のテストと同じ考え）。添付のファイルが消えること
- 次の番号: 開始番号を設定した部門 ／ 設定していない部門 ／ 今年度の紙の決裁がある部門 ／ **紙を取り込んで取り消した部門** ／ 試す期間に開始番号を上げた部門 ／ 試す期間に紙を足した部門 ／ 年度をまたいだ試しの申請、のそれぞれで、片付けのあと §5.7 の「試しの申請が無かったら付いていた番号」に戻り、部門の管理で開始番号を入れ直せること
- 使い始める: 試しの申請が残っていると断ること・使い始めたあとは片付けと試す人の出し入れが断られること・戻す操作が無いこと
- ⑬ の操作が決裁の管理者だけであること（決裁の管理者でない基幹の管理者も断る）
- PDF の「試し」・Excel のファイル名（試す期間 ／ 使い始めた）
- 基幹の既存のテストがすべて通ること（基幹の画面の問い合わせの本数を見るテストを含む）
- 手元のブラウザでの確認（使い捨ての SQLite ＋ `artisan serve`・Playwright）: スマホの幅で、試す人と試す人でない人のホーム・帯・⑬・片付けの確認の画面。写真を手引きの読みやすい版に使う

## 8. やらないこと

| もの | 理由 |
|---|---|
| 一部の部門だけ先に本物の申請を回す運用 | 要件 16.2 の 5「切り替え日から全社で使い始める」。試す期間は試しだけ（D1） |
| 試しの申請を残す・本物に移す | 段階2 の D1「試しのデータを本番に残さない」（D8） |
| 使い始めたあと準備中に戻す | 本物の申請が見えなくなる（D10） |
| 片付けを申請ごとに選ぶ | 試しの申請はすべて消す（D8）。1 件ずつ消したいときは今の取り下げ・削除で足りる |
| 本番の php.ini を開発側で直す | 要件 16.3 の 15（コントロールパネルで利用者が設定。手順は手引きに書く） |
| バックアップの保管先から試しのデータを消す | D15（残ってよい。段階0 のバックアップには手を入れない） |
| 試す期間の長さや終わりの日を画面で決める | 片付けと使い始めるを押すのは決裁の管理者（D14） |
| BACKLOG の「5b の残したもの」12 件 | 段階6 とは別に直す（⑬ で同じ形の穴を作らないことだけ §5.9 で守る） |

## 10. 実装計画で決めること

- 試す人の持ち方（`approval_members` の列か別の表か）と、使い始めたあと印を消すか
- §5.1 の判定の 1 か所の形（名前・どこに置くか）と、基幹の画面で問い合わせを増やさない読み方
- ⑬ の試せる部門と種類の出し方（種類に使える部門の限りとの組み合わせ）と、利用者を選ぶ欄の形
- 「試しの採番だけを除いた次の番号」の持ち方（§5.7。例: 連番の行に列を足す）と、使い始めたあとその値をどうするか
- 片付けと試す人の操作が重なったときの扱い（ロックの取り方）
- 催促の記録の言葉・帯の文言の細部・手引きのファイル名
- 作り方を 1 回にするか 2 回に分けるか（例: 6a ＝ 試す人・門番・知らせ・試しの印・提出の確かめ ／ 6b ＝ 片付け・使い始める・手引き）。試す期間を始めるのに片付けは要らないので、6a だけ先に出して試し始める形もとれる
- 要件定義書 v1.16 の書き方（§3）と、読みやすい版（artifact）の更新
