# CSV 取込の金額と面積で、カンマの位置が崩れた値をその行の誤りにする — 設計（短）

日付: 2026-11-16 ／ 利用者の承認: 2026-11-16（「このとおり」）
前の作業: 賃貸マンション・テナントの取込で列に入らない値を断った直し（docs/RULES.md Bug #132・#133）。その最後の点検で「金額の桁区切りの位置を見ない（`5,5000` も通る。直す前から同じ）」を後回しにした件

## なぜ

賃貸マンション（`Admin\MansionImportController`）とテナント（`Admin\TenantImportController`）の取込は、金額と面積を**カンマを全部取り除いてから**数として読む。
そのため打ち間違いが黙って別の値で入る。

| セル | 今の取込 |
|---|---|
| `5,5000` | 55000 で保存 |
| `5,,000` | 5000 で保存 |
| `5,50` | 550 で保存（5,500 のつもりかもしれない） |
| `,5000`・`5000,` | 5000 で保存 |

Excel が書き出す CSV は表示どおりの正しい区切り（`55,000`）なので、崩れた区切りは人が打ち間違えたときにだけ入る。

## 今どこで読んでいるか

| 列 | 読み方 |
|---|---|
| 金額（賃貸マンションの部屋・駐車場・部屋契約・駐車場契約、テナントの区画・契約・過去契約） | 共通の部品 `CsvImportLimits::readUnsignedInt()` の `str_replace(',', '', $raw)` |
| 賃貸マンションの部屋の専有面積（`area_sqm`） | コントローラの中で `str_replace(',', '', …)` のあと `is_numeric` |
| テナントの区画の面積（`area_tsubo`） | 同上 |

総戸数・階数・階はカンマを通さない（`allowCommas: false`。Bug #132 の最後の点検で決めた）ので今回は関係ない。

## 方針の候補（利用者が選んだもの: B）

| 案 | 中身 | 取引 |
|---|---|---|
| A | 金額だけを直す | 部品 1 か所で 2 つの取込の金額がそろうが、面積に同じ穴が残る |
| **B（選んだ）** | 金額と面積の 2 列を同じ決まりで読む | 取込でカンマを通す列がすべて同じ決まりになる。触る所は部品と 2 つの面積の読み方 |
| （採らない）今のまま | 記録だけ | 打ち間違いが黙って入り続ける |

## 決まり（こちらの判断）

- カンマが無い値は今までどおり読む
- カンマがある値は、**整数の部分が 3 桁ごとの正しい区切り**（先頭は 1〜3 桁・後ろは `,` と 3 桁の繰り返し）のときだけカンマを除いて読む。面積の小数の部分（`.` より後ろ）にカンマがあれば崩れているとみなす
  - 通る: `55,000`・`1,000,000`・`4,294,967,295`・`1,234.56`
  - 断る: `5,5000`・`5,,000`・`5,50`・`,5000`・`5000,`・`1,234.5,6`
- 崩れた値は、**今の形の誤りの文**でその行を誤りにする（新しい文は作らない。どの文も値を「」でそのまま見せる）
  - 金額: 「家賃「5,5000」は不正な値です」など（呼ぶ側が渡している今の文）
  - 面積: 「面積「5,5000」は不正な値です」
- 決まりは `App\Support\CsvImportLimits` に 1 つの部品（カンマを除いた文字を返し、崩れていれば null）として置き、`readUnsignedInt()` と 2 つの面積の読み方が使う（3 か所に同じ正規表現を書かない）
- 検査の順・上限・ほかの文は変えない

## 範囲の外

- 面積の `is_numeric` が通すほかの形（`1e3`・`+5` など）— カンマと関係しない。今のまま
- ZEAL 会員の取込（`HacomonoMemberMapper`。hacomono の書き出しで、カンマは機械が付ける）・アンケートの数の回答（`SurveyAnswers`）
- 全角のカンマ（`，`）— 今も断っている（`ctype_digit` と `is_numeric` が通さない）。今のまま
- 取込の画面の案内文
- 本番のデータの書き換え（崩れた区切りで入った値があるかは、上げた CSV が本番に残らないので確かめられない）

## 確かめ方

- 部品の単体テスト（通る形・断る形の両方）と、2 つの取込を画面から送る往復のテスト（金額と面積の崩れた区切りがその行の誤りになり、確定で書かれない。正しい区切りは今までどおり入る）
- 変異テスト（決まりを外す・緩める・面積の片方だけ戻す など）
- DB 変更・ルート変更・画面の変更・新しいクラスは無い（本番への反映は `./deploy.sh` だけ）
