# ANDPAD 工程表の取込 — 設計書

**作成日**: 2026-09-01
**対象**: 建売物件（`HsProperty`）の工程表
**前提**: 工程表機能（`schedule_steps`）は 2026-09-01 に本番稼働済み
（設計書 `2026-08-31-realestate-schedule-gantt-design.md`）

---

## 1. 背景

建売の工程管理は **ANDPAD** で行っている。ANDPAD の書き出しを本システムへ取り込んで、
工程表を自動で作りたい、という依頼。

---

## 2. 実測でわかったこと（2026-09-01。ここが設計の土台）

### 2.1 書き出し形式は 2 種類あり、**使えるのは片方だけ**

利用者に 2 通り出してもらって両方を解析した。

| 書き出し | ファイル例 | 判定 |
|---|---|---|
| **工程表（ガント）** | `【ANDPAD工程表】…_20260831_2313.xlsx` | ❌ **使えない** |
| **一覧（今回採用）** | `andpad_25941203_20260901.xlsx` | ✅ **必要な情報が全部ある** |

⚠ **ガント形式には終了日が存在しない。** ANDPAD 画面のガントを
「開始日の列に工程名を置いた表」へ平坦化したもので、棒の長さが失われている。
置き場所を全部つぶして確認した（セル値 / セル結合 57 個は工種ラベルのみ /
塗りは土日の網掛け `F2F2F2` のみ / 罫線は単なるグリッド / 図形はロゴ 1 個 / 条件付き書式 0）。

⚠ **「次の工程の直前まで」と推測して補ってはいけない。** 実データが否定している:
`足場組立 9/3` → `足場解体 10/26` を繋ぐと「足場組立が 53 日間」になるが、実際はどちらも 1 日。
推測で埋めると**もっともらしい嘘の工程表**ができる。

⚠ **CSV 書き出しは無い**（利用者確認済み）。よって Excel を解析するしかない。

### 2.2 一覧形式の中身

見出しは 3 行目。

| 列 | A | B | C | D | E | F | G | H | I | J | K | L |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| | 大工程名 | 工程名 | 担当会社 | 担当者 | 施工開始日 | (曜日) | 開始時間 | 施工完了日 | (曜日) | 完了時間 | 期間 | 状態 |

実測（`andpad_25941203_20260901.xlsx`）:

- **65 工程 / 20 大工程**、2026-07-23 〜 2026-12-25
- 欠損は **担当会社の 5 件だけ**。大工程名・工程名・開始日・完了日・状態は全件あり
- ⚠ **`期間 = 完了日 − 開始日 + 1` が 65 件すべてで一致** ——
  本システムの `GanttScale::width()` の「両端を含む +1」と同じ規約
- 状態: `作業前` 53 / `責任者承認済` 11 / `作業完了` 1
- ヘッダーに 現場名 / 住所 / 工事期間 / 工事担当 / 営業担当 がある

⚠ **シートが 2 枚あり、Sheet2 は続き**（60 + 5 件、重複 0）。印刷ページの分割。
**1 枚目だけ読むと 5 件落ちる。**

### 2.3 ⚠ SheetJS では読めない（方式が変わる理由）

アプリの既存取込はすべて**クライアント側 SheetJS**（5 画面で稼働）。
だが **ANDPAD の xlsx は SheetJS 0.18.5 がクラッシュする**（Node・ブラウザの両方で実測）。

原因は ANDPAD の xlsx が 3 点で行儀が悪いこと:

| 問題 | 影響 |
|---|---|
| ロゴ画像に**拡張子が無い**（`xl/media/…_brand_output_filename`。一覧形式では 2 個） | SheetJS が種類を判別できずバイナリを文字列展開しようとして落ちる。`xlsx.js:23059` がシートの drawing を辿って読みに行く |
| **ZIP64**（47KB のファイルなのに）。ローカルヘッダのサイズが `0xFFFFFFFF` | 素朴な zip 処理が 4GB 確保しようとする（自作の除去処理で実測・メモリ枯渇） |
| `styles.xml` に規格外の `<u val="">` | Python の openpyxl は**読めない** |

**切り分けの実測**: media エントリを**削除**または**拡張子 `.png` を付けるだけ**で SheetJS は読めた
（252 行 / 151ms）。原因は確定している。

⚠ ブラウザ側で自前に回避するには **ZIP64 対応の zip 再構成**が要り、割に合わない。

### 2.4 サーバ側なら読める（実測）

| 方式 | 結果 |
|---|---|
| クライアント側 SheetJS | ❌ |
| PHP `ZipArchive` | ✅ 23 エントリを開けた |
| **PhpSpreadsheet** | ✅ **2 シートとも完璧**（見出し・データとも一致） |

**本番の PHP 8.3.32 に必要な拡張は全部入っている**（実測: zip / xml / xmlreader / xmlwriter /
simplexml / mbstring / gd / zlib / dom / iconv / fileinfo）。`ZipArchive` クラスもある。

⚠ 本番の `upload_max_filesize` は **5M**、`post_max_size` は **8M**、`memory_limit` は **128M**。
ANDPAD のファイルは 47KB なので余裕だが、**画面の上限案内はこの実値に合わせること**。

### 2.5 ⚠ 現場名では物件を特定できない

ANDPAD の現場名 `JG保免中3号地 分譲住宅新築工事様邸` に対し、
**本番の建売物件 7 件に「保免中」を含むものは 0 件**（実測）。

つまり **名前で自動紐付けすると、存在しない物件を静かに取り違える**。
一方で命名規則は共通している（ANDPAD `JG保免中3号地 …` / 本システム `JG西長戸1号地`）ので、
**候補の提示には使えるが、確定には使えない**。

## 3. 確定した事項（利用者回答 2026-09-01）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 解析をどこでやるか | **サーバ側 PhpSpreadsheet を導入** | §2.3 のとおり SheetJS では読めない。CSV も無い |
| 2 | 大工程名の扱い | **工程名に含める**（`電気工事 / 器具取付`） | 落とすと区別できない。実データで `器具取付` が電気工事と給排水設備工事の 2 件 |
| 3 | 再取込の扱い | **ANDPAD 由来を入れ替える** | ANDPAD が正本のままなので、食い違いを残さない |

### 3.1 設計側で決めたこと（利用者に聞くまでもない/根拠がある）

| # | 決定 | 理由 |
|---|---|---|
| A | **取込は予定（`planned_start` / `planned_end`）にだけ入れる。実績は触らない** | ANDPAD の日付は予定であって「実際にその日にやった」記録ではない。`状態` から実績を推測するのは §2.1 と同じ「もっともらしい嘘」 |
| B | **取込は建売物件の詳細ページから行う**（物件を画面で特定した状態で上げる） | §2.5 のとおり名前で確定できない。親が一意に決まる入口にすれば取り違えが原理的に起きない |
| C | **ファイルの現場名・住所・工事期間を画面に出して確認させる** | B だけだと「正しい画面に間違ったファイルを上げた」を防げない。⚠ 名前が一致しないときは**警告を出すが、止めはしない**（本番に該当物件が無い実例があるため） |
| D | **`schedule_steps` に `source` 列を足す**（`null` = 手入力 / `'import'` = 取込） | 決定 3「ANDPAD 由来を入れ替える」を実現する唯一の手段。手で足した工程を巻き添えにしない |
| E | **全シートを読んで連結する** | §2.2 のとおり Sheet2 は続き。1 枚目だけだと 5 件落ちる |
| F | **担当会社・担当者・状態は `notes` に入れる** | 工程表の表示項目ではないが、捨てると ANDPAD を見に行くことになる |
| G | **カテゴリ（色）は大工程名から機械的に寄せる** | 20 種 → 5 色。`検査`/`申請` 系 → permit、`測量`/`登記` → survey、それ以外の `工事` → work、残り → other |

## 4. データ構造

### 4.1 `schedule_steps` への列追加

```sql
ALTER TABLE `schedule_steps`
  ADD COLUMN `source` VARCHAR(20) NULL COMMENT '取込元。NULL=手入力 / andpad=ANDPAD 取込' AFTER `notes`,
  ADD KEY `idx_sched_source` (`schedulable_type`, `schedulable_id`, `source`);
```

⚠ **`database/sql/` の DDL と `tests/Concerns/CreatesRealEstateSchema.php` の両方に足す。**
片方を忘れると「テストは緑なのに本番で `Unknown column`」になる
（`ScheduleSchemaTest` が列の一致を固定しているので、忘れると赤くなる）。

⚠ **既存行は `NULL`（手入力扱い）**。工程表は 2026-09-01 に本番稼働したばかりで
実データ 0 件なので移行は不要。

### 4.2 取り込む値の対応

| ANDPAD | `schedule_steps` |
|---|---|
| 大工程名 + 工程名 | `name` = `"{大工程名} / {工程名}"`（100 文字で切る。実測の最長は 15 文字なので余裕） |
| 施工開始日 | `planned_start` |
| 施工完了日 | `planned_end` |
| 大工程名 | `category`（§3.1 G の対応表で 5 色へ） |
| 担当会社 / 担当者 / 状態 | `notes`（255 文字で切る） |
| （行の並び） | `sort_order` |
| — | `source` = `'import'` |
| — | `actual_start` / `actual_end` は **触らない**（決定 A） |

## 5. 画面

### 5.1 入口

建売物件の詳細ページ、工程表カードの中に **「ANDPAD 取込」** ボタン（`role:executive,manager`）。
押すと取込画面 `/housing/properties/{property}/schedule-import` へ。

### 5.2 取込画面（2 段）

**① ファイルを選ぶ → プレビュー**

- ファイルの**現場名・住所・工事期間**と、取込先の**物件コード・物件名**を並べて出す
  （⚠ 名前が食い違うときは警告。止めはしない）
- 読み取った工程を全件表示（大工程名 / 工程名 / 開始 / 終了 / 期間 / 状態）
- **警告行**を出す: 日付が読めない / 完了日 < 開始日 / 工程名が空 / 100 文字超で切った
- **入れ替えの予告**を出す: 「ANDPAD 由来の既存 N 件を消して M 件を登録します。
  手で足した K 件は残ります」

**② 確定**

- ⚠ **画面が描いたフォーム（`action` と全 hidden）をそのまま送り返す形にする**（Bug #47 / #54 ②）
- トランザクションで「ANDPAD 由来を削除 → 新規を登録」

⚠ **プレビューの view データに `'errors'` キーを渡さない**（Blade の `$errors` を壊す。Bug #53）。
行エラーは `rowErrors` にする。

## 6. 検証（テストで押さえること）

- **実ファイルを固定資産として置く**（`tests/fixtures/schedule-import/`）。⚠ ANDPAD の xlsx は
  行儀が悪く、**手で作った正常な xlsx では §2.3 の問題を再現できない**
- 65 工程が全部入ること。⚠ **Sheet2 の 5 件が落ちていないこと**を単独で固定する
- `期間 = 終了 − 開始 + 1` が全件で成り立つこと（読み違えの検出）
- 再取込で **ANDPAD 由来だけが入れ替わり、手入力が残る**こと
- 100 文字超の工程名が切られること / 日付欠損行が警告になること
- ⚠ **ガント形式のファイルを上げたときに、黙って 0 件にせず「この書き出しは使えない」と言うこと**
  （見出し行が違うので判別できる）

## 7. やらないこと

| 項目 | 理由 |
|---|---|
| ANDPAD の API 連携 | 書き出しファイルで足りる。API は契約・認証の話が別途要る |
| 現場名からの自動紐付け | §2.5 のとおり確定できない。取り違えのほうが高くつく |
| 実績（`actual_*`）の自動設定 | 決定 A |
| 注文住宅・不動産への展開 | 建売の運用が回ってから判断する |
| ANDPAD へ書き戻す | 一方向に限る |
