# 土地（旧「仲介土地」）の区画登録と、分譲地への変更 — 設計書

日付: 2026-11-20
作業場所: `.claude/worktrees/land-lot`（枝 `land-lot`。13.x = `c557ef26` から）

## 1. なぜ作るか

不動産管理の仕入れ案件のうち、物件種別「仲介土地」は区画を登録できない。区画を持てるのは分譲地（`re_projects` と `re_project_lots`）だけで、仕入れ案件の一覧の「区画」ボタンも分譲地の行にしか出ない。

利用者の言葉（2026-11-20）:

- 「仲介土地は基本 1 区画なので登録しない仕様になっていますが、仲介土地も区画登録をして広さなどを確認できるようにしたい。契約にも絡むので仕様をよく確認して」
- 「1 つの土地（仕入れ案件）を 2 区画以上に分けて、別々の買主に売ることはある。当初は 1 区画で売るつもりが区画を増やす場合もあるので、当初は土地で登録していても分譲地に変えられるようにしてほしい」
- 「区画が 1 つでも建売・注文住宅になることはある」
- 「契約、または建売・注文住宅の紐付けがある土地も（分譲地に）変えられる必要はない」
- 表記の「仲介土地」は「土地」にする

あわせて分かったこと: 「仲介土地」でも取引種別は「自社買取」のものがあり、名前と中身が食い違っている（取引種別「仲介」・契約種別「仲介」は別の概念）。

## 2. 目標・目標でないこと・失敗とみなすこと

### 目標

1. 物件種別の表記「仲介土地」を「土地」にする（不動産管理の画面すべて）
2. 物件種別が土地の仕入れ案件に、区画を 1 つ登録・編集・削除できる
3. 区画の広さ（面積・坪数）・販売価格・坪単価・ステータスを、仕入れ案件の詳細・一覧・契約・住宅事業の画面で見られる
4. 土地の区画のステータスが、土地の契約（不動産）と、土地の上の建売・注文住宅の契約に合わせて動く（分譲地の区画と同じ動き）
5. 土地の仕入れ案件を「分譲地に変える」ことができる。中身（基本情報・価格・原価・区画・工程・添付・仕入れ先）は失われず、新しい分譲地へ移る

### 目標でないこと

- 土地のまま 2 つ以上の区画を持つこと（2 つ目を足すときは分譲地に変える）
- 分譲地から土地へ戻すこと
- 契約・建売・注文住宅の紐付けがある土地を分譲地に変えること（断る）
- 住宅事業で、仕入れ案件の代わりに土地の区画を選ぶこと（今どおり仕入れ案件を選ぶ）
- 土地の区画に原価を割り振ること・区画ごとの粗利（分譲地の区画一覧にある「原価額」「粗利額」）
- 土地の区画図面（分譲地には図面があるが、土地には作らない）
- 内部の値 `brokerage_land` の変更・契約種別「仕入れ土地販売」「仲介」・取引種別「仲介」の表記の変更
- 建売・注文住宅が契約になったときに、土地の仕入れ案件のステータスを動かすこと（今も動かない。§8 の範囲外を参照）

### 失敗とみなすこと（動いても失敗）

- 分譲地に変えたときに、原価・工程・添付のどれかが消える、または元の仕入れ案件と新しい分譲地の両方に残る
- 変更の途中で止まり、半分だけ移った状態が残る
- 分譲地の区画・住宅事業の区画まわり（契約・建売・注文住宅・削除の歯止め・原価の割り振り）の動きが変わる・500 になる
- 一覧で、変えた案件が 2 行（仕入れ案件と分譲地）に出る

## 3. 制約

- 本番の表は raw SQL で管理する（`database/sql/` に SQL を置き、テスト用は `tests/Concerns/CreatesRealEstateSchema.php` に同じ形を足す）。本番反映は **DB が先・`./deploy.sh` が後**
- 新しい PHP クラスを足すので、本番反映では main repo の cwd で `composer dump-autoload --no-dev --optimize` が要る
- 坪数は `AreaConverter::sqmToTsubo()`（切り捨て）、坪単価は `TsuboPrice`（切り上げ・丸めは 1 回だけ）を通す（Bug #33・#34）
- 土地は消費税なし（建物が無いので）
- 入力の上限は本番の列に合わせる（Bug #73）。テスト用スキーマは本番の定義と同じにする（Bug #40・#60）
- 同じ値を 2 か所で計算しない。画面とサーバで判定を分けない（Bug #41）

## 4. 作り方の候補（利用者が B を選んだ）

| | A: 分譲地の区画と同じ表に持つ | **B: 土地の区画用の小さな表を新しく作る（採用）** | C: 仕入れ案件の項目として持つ |
|---|---|---|---|
| 中身 | `re_project_lots` を仕入れ案件にも付けられるようにする | `re_procurement_lots`（1 つの仕入れ案件に 1 行まで）。項目は分譲地の区画と同じ | 号地・区画面積などの列を `re_procurements` に足す |
| 分譲地に変えるとき | 区画の付け先を変えるだけ | 区画の行を `re_project_lots` へ写す | 列の値から分譲地の区画を 1 つ作る |
| 影響 | 分譲地の区画を読む所（契約・建売・注文住宅・削除の歯止め・原価の割り振り）を全部見直す必要があり、見直し漏れが 500 になる | 分譲地・住宅事業の今の仕組みはそのまま。足すのは土地の区画の画面と、状態の連動 | いちばん小さい |
| 弱いところ | 上の見直しの漏れ | 区画の画面と保存の処理を土地用にもう 1 組作る（計算の部品は共用） | 「1 区画まで」が仕組みに焼き付く。区画の値と土地面積・想定販売価格が 2 組並ぶ |

B を選んだ理由（利用者の選択・2026-11-20）: 土地の区画は 1 つまでで、建売・注文住宅は今どおり仕入れ案件を選ぶので、分譲地の区画を読む仕組みと切り離せる。分譲地に変えられるのは紐付けの無い土地だけなので、区画の行を写しても困ることはない。

## 5. 決まったこと

### 5.1 表記（利用者の決定）

- `RealEstatePropertyType::BrokerageLand` の表記を「仲介土地」→「土地」。値 `brokerage_land` は変えない
- 仕入れ案件の登録・編集の注記「※ 物件種別が「仲介土地」の場合は不要」も「土地」にする
- コード中のコメント・テストの注記の「仲介土地」も「土地」にそろえる（動きには関係しない）
- 住宅事業の画面に「仲介土地」の表記は無い（2026-11-20 に確かめた）。住宅事業の「仕入れ案件」「仕入れ土地」の語は変えない

### 5.2 土地の区画（利用者の決定と、提案して異論の無かったもの）

- 区画を持てるのは、物件種別が土地の仕入れ案件だけ。取引種別（自社買取・仲介）は問わない
- 土地の区画は 1 つまで。2 つ目を足したいときは「分譲地に変える」へ案内する
- 項目は分譲地の区画と同じ: 号地番号・面積（㎡）・販売価格・ステータス（未販売・販売中・商談中・成約）・備考。坪数と坪単価は画面で計算して出す（保存しない）
- 最初の区画は、仕入れ案件の土地面積と想定販売価格（土地）を最初から入れた状態で開く（号地番号は 1）

### 5.3 区画のステータスの連動（利用者の決定と、提案して異論の無かったもの）

分譲地の区画と同じ動きにする。

| 起きたこと | 土地の区画 |
|---|---|
| 不動産の契約（仕入れ案件に紐づく契約）を登録した | 成約 |
| その契約を消した | 販売中 |
| 契約の紐づけ先の仕入れ案件を付け替えた | 旧の区画を販売中・新の区画を成約 |
| 土地の上の建売に契約を登録した（`Housing\ContractController`） | 成約 |
| その建売の契約を消した | 販売中 |
| 土地の上の注文住宅のステータスが「契約」をまたいだ（`CustomOrderController::syncLotStatus`）・契約以降で消した（`releaseLot`） | 成約 ／ 販売中 |

- 契約の種別ではなく「紐づく仕入れ案件が土地の区画を持つか」で判定する（建物のある種別の仕入れ案件は区画を持たないので、自然に対象外になる）
- 区画が無い土地では何もしない
- 契約一覧から開く注文住宅の契約の編集（`HsContractListController`）は、分譲地の区画でも状態を動かしていない。土地の区画も同じく動かさない（今の分譲地の動きに合わせる）

### 5.4 区画を見せる場所（提案して異論の無かったもの）

- 仕入れ案件の詳細: 土地のとき「区画」の欄を出す（区画が無ければ登録のフォーム、あれば表示と編集・削除。分譲地に変えるボタンもここ）
- 仕入れ案件の一覧: 土地の行に「区画」ボタン（詳細の区画の欄へ飛ぶ）と、物件名の下の「区画 成約数 / 区画数」（分譲地と同じ形。土地なので 0 / 0・0 / 1・1 / 1 のどれか）
- 不動産の契約: 紐づく仕入れ案件が区画を持つとき、契約の登録・編集・詳細に区画（号地・面積・坪数・販売価格）を出す
- 住宅事業: 土地元が仕入れ案件のとき、土地元の表示に区画の面積・坪数も出す。住宅事業の参考の土地価格は今どおり仕入れ案件の想定販売価格（土地）を使う

### 5.5 分譲地に変える（利用者の決定と、提案して異論の無かったもの）

**変えられる条件**（すべて満たすとき）:

1. 物件種別が土地
2. 取引種別が自社買取（分譲地には取引種別の項目が無く、仲介の土地は自社の土地ではないため）
3. 契約・建売・注文住宅の紐付けが無い。判定は削除の歯止めと同じ `DeletionBlockers`（`$procurement->deletionBlockers()`）を使う。紐付けがあれば、削除と同じ形で理由を出して断る

**変えたあと**:

- その案件は分譲地に置き換わる。一覧には分譲地として 1 行で出る
- 案件番号は分譲地の番号（`RE-PRJ-…`）に変わる。元の番号は分譲地の備考の末尾に残す（例: 「元の仕入れ案件: RE-PRC-019（2026/11/20 に分譲地へ変更）」）
- 元の仕入れ案件は消える
- 戻せない（変える前の確認で、番号が変わることと戻せないことを伝える）

**移すもの**:

| 仕入れ案件 | 分譲地 |
|---|---|
| 物件名 | 分譲地名（`project_name`） |
| 郵便番号・所在地・緯度経度・土地面積・用途地域・建蔽率・容積率・仕入れ先・情報入手日・契約日・決済日 | 同じ項目 |
| 査定価格（土地）・購入価格（土地）・想定販売価格（土地） | 査定価格・購入価格・想定販売価格 |
| 備考 | 備考（末尾に元の番号を足す） |
| ステータス | 同じステータス（下の表） |
| 原価（`re_procurement_costs`） | 原価（`re_project_costs`）。物件購入費の行は分譲地の自動の同期に任せる（どちらも査定価格→見込み額・購入価格→確定額で同じ値になる） |
| 土地の区画（`re_procurement_lots`） | 分譲地の区画（`re_project_lots`）。坪数・坪単価は分譲地の区画の登録と同じ計算で入れる |
| 工程（`schedule_steps`） | 持ち主を分譲地に付け替える |
| 添付（`attachments`） | 持ち主を分譲地に付け替える（ファイルの置き場所は変えない） |

| 仕入れ案件のステータス | 分譲地のステータス |
|---|---|
| 情報入手 | 情報入手 |
| 現地調査 | 検討（分譲地に「現地調査」は無い。§7 の私の判断） |
| 査定・検討 | 検討 |
| 交渉中・契約・決済完了・販売中 | 同じもの |
| 販売済 | 販売済 |
| 不成約 | 不成立 |

- 移らないもの: 取引種別（自社買取しか変えられない）・建物の項目（土地には無い）・消費税率
- 全部を 1 つのトランザクションで行い、途中で失敗したら何も変えない
- 変えたあとは新しい分譲地の詳細へ移り、「分譲地「RE-PRJ-…」に変えました（元の番号 RE-PRC-… は備考に残しました）。」を出す

### 5.6 物件種別を土地から変えるとき（私の判断）

区画がある土地の物件種別を、ほかの種別（中古戸建など）に変える保存は、入力エラーで断る（「区画が登録されているため、物件種別を変えられません。先に区画を削除してください。」）。黙って区画を消すと、登録した広さが失われるため。

## 6. 表（新しく作る）

`re_procurement_lots`（本番は `database/sql/2026-11-20-create-re-procurement-lots.sql`）:

| 列 | 型 | 説明 |
|---|---|---|
| id | bigint unsigned | |
| procurement_id | bigint unsigned NOT NULL・**一意** | 仕入れ案件。外部キー `ON DELETE CASCADE`（仕入れ案件を消すと区画も消える） |
| lot_number | int NOT NULL | 号地番号（分譲地の区画と同じ型） |
| area_sqm | decimal(10,2) NOT NULL | 面積（㎡）。分譲地の区画が NOT NULL なので、変えるときに写せるように必須 |
| selling_price | int NULL | 販売価格 |
| status | varchar(30) NOT NULL | `LotStatus` |
| notes | varchar(200) NULL | 備考 |
| created_at・updated_at | timestamp | |

- 坪数・坪単価は保存しない（Bug #34 の「保存した派生の値が古くなる」を避ける）。分譲地に写すときに計算して入れる
- 入力の上限は分譲地の区画の登録（`ProjectController::storeLot`）と同じ

## 7. 作る人に任せること・私の判断として決めたこと

**私の判断**（利用者に確認していない。読んで違えば直してもらう）:

- 現地調査 → 検討（§5.5）
- 物件種別の変更を断る（§5.6）
- 区画の登録・編集は経営層・管理者、削除は経営層（分譲地の区画と同じ）
- 区画の欄は詳細画面の中に置く（分譲地のような別の画面は作らない。区画が 1 つまでなので）。保存はふつうのフォームの送信（入力エラーは画面に理由を出して戻す）
- 分譲地に変える操作は経営層・管理者（仕入れ案件を編集できる人と同じ。データは消えずに移るだけなので）
- 分譲地の `created_by` は元の仕入れ案件の登録者、`updated_by` は変えた人

**作る人に任せること**:

- 区画の欄・一覧の表示の細かい見た目（既存の分譲地の区画一覧・仕入れ案件の詳細のカードの作りに合わせる）
- クラスの分け方（モデル `ReProcurementLot`、変える処理を置く場所など）
- 一覧の「区画」ボタンの飛び先（詳細の区画の欄へのアンカー）
- 変える処理のロックのかけ方（仕入れ案件の行を `lockForUpdate()` して条件を確かめ直す）

## 8. 範囲外（気づいたが今回は直さない）

- 建売・注文住宅が契約になっても、土地の仕入れ案件のステータスは販売中のまま。そのため、建売で売れた土地にも、不動産の契約（仕入れ土地販売）を登録できてしまう（今もそう）
- 仕入れ案件を消しても添付の行が残る（今もそう）

## 9. 確かめ方

- 自動テスト: 区画の登録・編集・削除（描いた画面のフォームを送る往復）・上限・1 つまで・種別の変更の断り・状態の連動（不動産の契約 3 経路・建売 2 経路・注文住宅 3 経路）・一覧と詳細と契約と住宅事業の表示・分譲地に変える（移すものすべて・断る条件 3 つ・途中で失敗したら何も変わらない・一覧が 1 行）・表記
- 変異テスト（docs/RULES.md Bug #44 の作法）
- 実ブラウザ（使い捨ての環境）: 区画の登録から分譲地に変えるまで・375px と 1440px
- 本番反映の前に、本番の土地の仕入れ案件の数・紐付けの数を読み取りで数える（利用者の承認のうえ）
