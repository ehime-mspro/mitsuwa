# テナントの CSV 取込で、本番の列に入らない値をその行の誤りにする — 設計（短）

日付: 2026-11-15 ／ 利用者の承認: 2026-11-15（「このとおり」）
前の作業: 賃貸マンションの取込の同じ直し（docs/RULES.md Bug #132・設計 `2026-11-15-mansion-import-column-limits-design.md`）。そのとき「テナントの取込は別の作業」と決めた件

## なぜ

テナントの取込（`/admin/tenant-import`・`Admin\TenantImportController`・5 タブ）は、長さの検査が 1 つも無く、金額も「0 以上の数」しか見ない。
本番の MySQL は strict なので、列に入らない値が 1 行でもあると確定で例外になり、全行が取り消され、どの値が悪いかは出ない。金額は `is_numeric` で読むので `55000.9` が黙って 55000 で保存される。
テナントは本番で実際に使われている取込（顧客 113・区画 158・契約あり）。

## 数えたこと（2026-11-15。本番の `SHOW CREATE TABLE` を読み取りで確かめ、テスト用の写しと同じ大きさだった）

| タブ | 見ていない列（本番の列＝画面の上限） |
|---|---|
| 物件 | 物件名 200・郵便番号 10・住所 500・構造 50・オーナー名 200 文字 |
| 区画 | 部屋番号 20 文字・面積（DECIMAL(8,2)。画面は 9999.99）・募集家賃／共益費／敷金／ゴミ代／駆除代（INT＝0〜2147483647） |
| 顧客 | テナント名・テナントカナ 200・代表者名・担当者 100・電話番号 20・メールアドレス 255・郵便番号 10・住所 500 文字 |
| 契約 | 家賃・共益費・敷金・ゴミ代・駆除代・屋号 200 文字 |
| 過去契約 | 同じ金額 5 つ・屋号 200・テナント名 200 文字（自動で作る顧客の名前） |

計 33 列。あわせて、契約・過去契約の備考（TEXT）は画面が 5,000 文字までなので、取込で超えて入ると編集画面で保存できない（Bug #130 の形）。
本番の読み取り（件数だけ）: 面積が 9,999.99 坪を超える区画 0・備考が 5,000 文字を超える契約 0。

## 決めたこと（利用者の決定 2026-11-15）

1. 範囲は 33 列＋契約・過去契約の備考 5,000 文字
2. 区画の面積の上限は画面と同じ 9,999.99 坪（列は 999,999.99 まで入るが、超えた区画は編集画面で断られる）
3. 金額は賃貸マンションと同じく整数だけ（カンマは通す）
4. 本番の列の定義を読み取りで確かめた（上）

## 方針（賃貸マンションと同じ。こちらの判断）

- 部品 `tooLongMessage()`・`readUnsignedInt()` を `App\Support\CsvImportLimits`（新しいクラス・static）へ移し、賃貸マンションとテナントの両方の取込で使う（本番への反映で `composer dump-autoload` が要る）
- 文は賃貸マンションと同じ形。見出しは CSV の見出し（オーナー名・担当者・テナント名・屋号・備考 など）。形の誤りは今の文のまま（区画・契約・過去契約の金額「…は不正な値です」・面積「…は不正な値です」）
- 検査の順は変えない: 契約・過去契約は「日付 → CSV 内の重複 → 照合 → （新しい文字の検査）→ 金額」。物件・顧客の新しい長さの検査は登録済みのスキップより後ろ。区画の部屋番号は区画の重複の検査の後ろ
- オーナー名は「オーナー」でなく保存しない行でも長さを見る（画面と同じ）
- 備考の 5,000 文字は、取込が残す改行（LF）を 1 文字と数える

範囲の外: 物件・区画・顧客の備考（取込は書かない）・取込の画面の文言・過去契約の「顧客 N件を自動作成」の数え方（前から）。
