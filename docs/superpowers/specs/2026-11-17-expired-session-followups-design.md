# Bug #137 の後回し 4 つ（短い設計メモ）

日付: 2026-11-17 ／ 利用者の承認: 2026-11-17（「この内容で進めてください」）
元: docs/BACKLOG.md の「ログインが切れたとき（419）に日本語の理由を出す（Bug #137）」の節の範囲外・点検の Minor

## なぜ

Bug #137 で 419（ログインが切れた）の理由を出すようにしたが、最後の点検で 4 つを後回しにした。
本番で使い始める前に片付けておく。いちばん利用者が困るのは 1（通信が切れると何も出ない）。

## やること

| # | 今 | 直したあと |
|---|---|---|
| 1 | 買主一覧のランク変更・登録画面の「この部署に取り込む」（XMLHttpRequest）に `onerror` が無く、通信そのものが失敗すると何も出ない | 理由を出す（下の文言） |
| 2 | 419 の本文を読む処理が `buyers/index` の `xhrFailureMessage()` と `buyers/_form` のインラインに 2 回書いてある | 1 か所の部品にして 2 画面から読む |
| 3 | 419 の画面のタブ名がアプリ名だけで、ログイン画面と区別がつかない | 「画面の有効期限が切れました - アプリ名」 |
| 4 | 保存の Ajax の走査（`AjaxFetchSessionGuardTest`）の見落としが書かれていない | docblock に書き、見本で今の動きを固定する |

## 決めたこと

- **1 の文言**（通信が失敗したときは、サーバーに届いて保存された可能性もある。「変わっていません」とは言わない。原価の表の「画面を開き直して、保存されたか確かめてください」と同じ言い方）
  - ランク:「通信エラーが発生しました。画面を開き直して、ランクが変わったか確かめてください。」
  - 取り込み:「通信エラーが発生しました。顧客の一覧で、この部署に取り込まれたか確かめてください。」
- **2 の置き場所**: 新しい部品 `resources/views/buyers/_xhr_failure_message.blade.php`（`<script>` と `@once`）に `xhrFailureMessage(xhr, fallback)` を置き、`buyers/index` と `buyers/_form` が `@include` する。動き（419 は本文の `message`、ほかは `fallback`）は今と同じ
- **3**: `components/guest-layout.blade.php` に任意の `title`（`@props(['title' => null])`）を足し、`<title>` を「title - アプリ名」（無ければ今と同じアプリ名だけ）にする。ほかの画面の `layouts/app` と同じ形。419 の画面だけが渡す。ログイン画面は変えない
- **4 の見落とし**（2026-11-17 に `resources/views` を数え、どれも実物は 0 件）
  - fetch の呼び出しの中の JS コメントに書いた `'Accept': 'application/json'` も、求めているとみなす（見落とす向き）
  - オプションを変数で渡す `fetch(url, opts)` は GET とみなして数えない（見落とす向き）
  - `xhr.open(変数, …)` は数えない（見落とす向き）
  - `'Accept': 'application/json, text/plain'` は求めていないとみなす（厳しすぎる向き＝断る）
- テストの道具（`tests/Concerns/DrivesAlpineFetch.php`）は、偽の XMLHttpRequest が通信の失敗（`onerror`）を起こせない。応答の形に通信の失敗を足す（今ある応答の形と使い方は変えない）

## 採らなかった案

- 2 を `resources/js/app.js` に置く: 画面の JS を node で動かすテストは `app.js` を読まないので、関数が見えなくなる
- 2 を部品にせず、`<script>` の中へ JS だけを `@include` する: テストは変えずに済むが、走査（`JsStringEchoScanTest` など）が部品のファイルを JS の場所として読まない
- 4 で走査そのものを直す: 今は該当する画面が 0 件。見本で固定しておけば、書き方が増えたときに分かる
- 3 でログイン画面にも名前を付ける: 区別には 419 だけで足りる。ログイン画面の見た目は変えない

## 範囲外

- fetch の 5 か所（`body && body.message` の形）の 419 の読み方をそろえること
- GET の Ajax でログインが切れたときの「データの取得に失敗しました（401）」（約 15 か所）
- 419 の画面の「前の画面に戻る」で戻った画面は古い鍵のまま（文面で案内している）

## 検証

- 新しいテストは直す前に赤を確かめてから直す
- 全件テスト・変異（落ちたテストの組と理由まで）・コンパイル済みビューの lint・実ブラウザ（通信の失敗は使い捨ての環境でサーバーを止めて起こす）
