# 住宅事業: 土地原価の手動入力をやめたら紐付け先から計算し直す（設計・短）

日付: 2026-11-20 ／ 利用者の決定: 2026-11-20（判断待ち ⑤ を案 A で・すでにある行は案 b・本番の件数の読み取りも承認）

## なぜ

土地原価の「手動入力」のチェックを外して保存しても、前に手で入れた値が残る。
契約の編集画面では、その古い値が「（区画名）から自動参照」と表示される。
手で入れた値と紐付け先（区画・仕入れ案件）の値の区別がつかなくなり、粗利がずれたまま気づけない。

## 今（2026-11-20 にコードを読んだ）

土地原価（`hs_properties.land_cost`・`hs_custom_orders.land_cost`）は**保存した時点の値**を持つ。手動かどうかは `is_land_cost_manual`。

| 画面 | 手動 OFF で保存したとき |
|---|---|
| 1 建売の登録・編集（`housing/properties/_form`・`PropertyController`） | 欄の値（読み取り専用）をそのまま送り、サーバーはそれを保存する。JS は区画・仕入れ案件を選んだときだけ自動の値を入れ、チェックを外しても取り直さない |
| 2 注文住宅の登録・編集（`housing/custom-orders/_form`・`CustomOrderController`） | 1 と同じ。お客様の土地なら空 |
| 3 建売の契約の編集（`contracts/edit-building`・`HsContractListController::updateBuilding`） | 土地原価を送らず、サーバーも書かない＝保存済みの値が残る。表示は保存済みの値を「（区画名）から自動参照」 |
| 4 注文住宅の契約の編集（`contracts/edit-custom-order`・`updateCustomOrder`） | 3 と同じ。お客様の土地なら空 |

そのため、1・2 では「保存済みが OFF でも、チェックを入れて打つ → 外す」と打った値が OFF のまま保存される（⑤ と同じ形）。

自動の値の出どころ:
- 分譲地区画: 分譲地の原価の合計を区画の販売価格で按分した額（全区画に販売価格があるときだけ。無ければ計算できない）。`ReProject::housingLotOptions()` の `land_cost`
- 仕入れ案件: `ReProcurement::getEffectiveCostTotal()`（確定額があれば確定額、無ければ見込み額の合計）

本番（2026-11-20 に読み取りで数えた・件数だけ）:

| | 手動 | 件数 | 保存されている値と今の計算値 |
|---|---|---|---|
| 建売 13（全部分譲地区画） | OFF | 5 | 同じ 2・違う 3（3 件とも契約前） |
| | ON | 8 | 全部違う（うち契約あり 6） |
| 注文住宅 4 | ON | 2 | 違う（契約あり） |
| | お客様の土地 | 2 | 土地原価なし |

違う 3 件が「前の手入力の残り」か「保存したあとで分譲地の原価が変わった」かは、データからは見分けられない。

## 目標・目標でないこと

- 目標: 手動入力をやめて保存したら、サーバーが紐付け先から計算した値を保存する。画面にも、外した瞬間にその値を出す
- 目標: 手動 OFF の行で保存されている値が今の計算値と違うときは、それが分かるように出し、利用者が押したときだけ今の計算値に合わせられる
- 目標でないこと: 手動 ON の保存の動きを変えること／分譲地・仕入れ案件の原価が変わったときに自動で追いかけること／
  本番の 3 件の値をこちらで書き換えること／自動の値の計算式を変えること
- 失敗とみなすこと: **チェックに触らず保存しただけで、契約の原価が動く**（利用者の方針「古い契約の原価が勝手に動かないように」）／
  画面に出した値と保存される値が食い違う（Bug #41・#46 の形）

## 進め方（案）

⑤ の直し方:

| 案 | 中身 | 採否 |
|---|---|---|
| **A** | 手入力をやめて保存したら、サーバーが紐付け先から計算し直す。画面にも外した瞬間に出す | **採用（利用者の決定）** |
| B | 画面だけで取り直す（ブラウザの値を信じる） | 採らない |
| C | 値は残し、表示を「前に手入力した値」に直すだけ | 採らない |

すでにある行（手動 OFF で値が違う行）の扱い:

| 案 | 中身 | 採否 |
|---|---|---|
| a | 値は変えない。画面に今の計算値を添えるだけ | 採らない（合わせるには手入力しかない） |
| **b** | 「今の計算値（Y 円）にする」を出し、押して保存したときだけ更新 | **採用（利用者の決定）**。押したときだけ動く・契約の前でも後でも同じ決まり |
| d | 契約前なら手動 OFF は保存のたびに計算し直す | 採らない（備考を直しただけでも原価が動く・契約の時点で古い値で固まることがある） |

## 決めたこと

1. **保存するときの決まり（サーバー・4 画面とも）**

   | 送られた手動入力 | 条件 | 土地原価 |
   |---|---|---|
   | ON | — | 今どおり送られた値 |
   | OFF | 新規登録／保存済みが ON（＝手入力をやめた）／紐付け先（種別・区画・仕入れ案件）が保存済みと違う／「今の計算値にする」を押した | サーバーが紐付け先から計算した値（計算できなければ空） |
   | OFF | それ以外（チェックに触らず保存） | 保存済みの値のまま。**送られた値は使わない** |

   お客様の土地（注文住宅）は今どおり空。
2. **計算は 1 か所**（新しいクラス `App\Support\HousingLandCost`）。区画の按分は今の区画の一覧と同じ式を共用する（`ReProject` の式を切り出す）。仕入れ案件は原価の行が無ければ計算できない（空）
3. **画面**: ページに「今の紐付け先から計算した値」を入れておく
   - 手動 OFF のとき、保存される値（上の決まりと同じ）を出す。チェックを外した瞬間は計算値に替わる
   - 計算できないときは「紐付け先から計算できません（分譲地の全区画に販売価格が入っていない／仕入れ案件に原価が無い）。このまま保存すると空になります」
   - 保存されている値が今の計算値と違うときは、その旨と「今の計算値（Y 円）にする」を出す。押すと画面の値が替わり、保存したときだけ更新される
   - 契約の編集画面の「（区画名）から自動参照」は「（区画名）から取得した値」に直す
4. 本番のデータは書き換えない（違う 3 件も、利用者が画面で押したときだけ変わる）

## 実装の側に任せたこと（私の判断）

- 「今の計算値にする」は計算できるとき（値があるとき）だけ出す。計算できないときは理由の文だけ
- 仕入れ案件の自動の値は、原価の行が 1 つも無ければ「計算できない」とする（今の画面の JS は 0 を「取れなかった」と同じに扱っている）
- 登録・編集の画面（1・2）で紐付け先を選び直したときの計算値は、区画の一覧と仕入れ案件の情報の API が返す値を使う（どちらも同じ計算の部品を通す）。
  注文住宅の契約の編集（4）で紐付け先を変えたとき（契約前の注文住宅だけ。契約一覧からは開かない）は、金額は出さず「保存すると新しい紐付け先から計算します」とだけ出す
- 手動 OFF の欄の値はサーバーが使わないが、欄は今どおり読み取り専用で出す（見た目を変えない）
- 画面の JS とサーバーの決まりは二重になるので、画面の JS を動かすテストで同じ場面を突き合わせる（Bug #41）
