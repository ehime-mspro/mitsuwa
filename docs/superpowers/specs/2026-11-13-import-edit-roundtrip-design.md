# 取込で入った値を、編集画面からそのまま保存できるようにする（設計・短い版）

2026-11-13。利用者の依頼（Bug #130 の形の横展開）と決定（「おすすめで進めてください」）。
前提の調べ: docs/BACKLOG.md の「取込で入ったデータが編集画面で保存できないか（Bug #130 の形）を本番で数えた」の節。

## なぜ

取込（CSV）が入れる値と、編集画面（ブラウザの入力欄の制約・選択肢・サーバーの入力チェック）が受け付ける値が食い違っている。
食い違うと、取込で入ったレコードを編集画面で開いて**ほかの項目だけ直したいときも**、保存が止まるか、値が黙って空になる（Bug #130 で ZEAL 会員の 17 人が実際に踏んだ形）。
2026-11-13 の本番はどの画面も 0 件。賃貸マンションは部屋・駐車場・契約がまだ 0 件なので、取込を使い始める前に塞ぐ。

## 目標

- 取込が入れうる値のレコードを編集画面で開き、何も変えずに保存すると、そのまま保存できる（値は変わらない）
- 取込で入れるべきでない値は、取込のときに理由つきで断る（画面と同じ基準）

## しないこと

- 部屋契約の入居者が「駐車場のみ利用者」のとき（範囲外 D5・業務の判断が要る）
- テナントの顧客・賃貸マンションの入居者のメール（取込は `filter_var`、画面は `type="email"` とサーバーの `email`。違いは珍しい形だけなので触らない）
- 不動産の建蔽率・容積率の `step="10"`（取込との関係は未確認・今回の対象外）
- 本番のデータの書き換え（今は 0 件）

## 方法（項目ごとの決定）

| 項目 | 側 | 決めたこと |
|---|---|---|
| 賃貸マンションの金額の刻み（`step="1000"`・`step="500"`） | 画面 | 金額の欄から `step` を外す（1 円単位）。部屋・駐車場・部屋契約・駐車場契約の登録と編集、賃料改定・料金改定、解約の原状回復費・清掃費・差引の金額の 17 欄 |
| 部屋の階（画面 1〜50・サーバー 0〜255） | 画面 | 画面を `min="0" max="255"` に |
| 物件の総戸数・階数（画面 999・50／サーバー 65535・255） | 画面 | 画面の `max` をサーバーに合わせる |
| 選択肢に無い値（物件の構造・部屋の間取り・買主の職業と都道府県） | 画面 | 今の値が選択肢に無ければ「◯◯（選択肢に無い値）」として選んだまま描く（テナントの物件の構造 Bug #82 と同じ形）。サーバーは今も文字列で通す |
| 買主のメール（取込は形を見ない・画面は `type="email"`） | 画面 | `type="text" inputmode="email"`（Bug #89 で「買主のメールの形は見ない」と決めている。Bug #130 と同じ直し方） |
| テナントの物件の築年月（取込が `2010-4`・`2010-13` を入れる） | 取込 | 月を 2 桁にそろえ（`2010-04`）、月が 1〜12 でなければその行をエラー（賃貸マンションの取込と同じ） |
| テナントの物件の階数（取込は上限なし） | 取込 | 99 まで（画面とサーバーの上限） |
| 買主の生年月日（取込は未来の日も通す） | 取込 | 今日（日本の今日）より後ならその行のエラー（画面の Bug #90 と同じ基準） |

### 考えた別の方法

- **全部を取込の側で断る**: 65,500 円の家賃や「パート」の職業のような正当な値まで取込で断ることになり、利用者が CSV を直す手間が増える。画面の制約のほうが根拠が弱い（モックの名残の刻み・画面だけの上限）ので採らない
- **全部を画面の側で通す**: 未来の生年月日や `2010-13` のような誤りまで保存できるようにしてしまう。画面の基準（Bug #90）とそろえるほうがよいので、誤りは取込で断る

## 守り（テスト）

- 画面の側: 選択肢に無い値・刻みに乗らない金額・範囲の端の値を持つレコードの編集画面を描き、画面のフォームのまま送って値が変わらないこと（往復）。欄の属性（`step` が無い・`min`/`max` がサーバーと同じ・メールの欄の型）も構造で見る（PHP のテストはブラウザの制約を実行しないため）
- 刻みの走査: 画面の `step="…"` を全件分類する（新しく刻みを足すと、理由を書かないと落ちる。Top trap #13）
- 取込の側: 築年月・階数・生年月日の行が理由つきのエラーになり、正しい行は入ること（プレビュー → 確定の往復）
- 変異テストと、実ブラウザ（使い捨ての環境）で刻みと選択肢を確かめる

## 作る人に任せること

- 「（選択肢に無い値）」の書き方の細部（テナントの物件の構造の形に合わせる）
- テストの置き場所（既存の画面のテストの土台を使う）
