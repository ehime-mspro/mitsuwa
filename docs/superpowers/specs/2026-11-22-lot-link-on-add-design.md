# 区画を足すとき、区画を選んでいない契約などをその区画につなぐ（短い設計）

- 日付: 2026-11-22
- 依頼: 利用者（土地の区画を複数にした変更の「利用者に伝えること」の 1 つ目＝#21 の形を直す・案 A）
- 前提: 土地の区画を複数にした変更（`docs/superpowers/specs/2026-11-20-realestate-land-multi-lot-design.md`）・Bug #145

## なぜ

区画の無い土地に契約がある状態（本番の #21）で区画を足すと、追加のフォームの初期値で区画は「成約」で作られるが、契約とはつながらない。
区画が取られているかはステータスでなく紐付けで決めている（`ProcurementLotClaims`）ので、次の 2 つが起きる。

1. その区画を区画の表で「販売中」にすると、同じ土地に 2 件目の契約を登録できる（二重に売れる形）
2. その契約を消しても、区画は「成約」のまま残る（契約の削除は紐付けのある区画しか動かさない）

つなぐ道は、契約なら契約の編集画面で区画を選ぶことだけ。建売と契約以降の注文住宅は土地の欄が読み取り専用で、あとからはつなげない（Bug #142）。

本番（2026-11-21 の読み取り）: 区画を選んでいないものがある土地は #21 だけ（区画 0・契約 1）。仕入れ案件を土地元にした建売・注文住宅は 0 件。
区画があるのに区画を選んでいないものが残っている土地は 0 件 ＝ データの手直しは要らない。

## 言葉

- **区画を選んでいないもの**: その土地を土地元にしていて区画が空の、不動産の契約・建売（契約の前も）・契約以降の注文住宅。
  `ProcurementLotClaims` が「区画を取る」と数える顔ぶれと同じ。見積り以前の注文住宅は入れない（区画を取らない）

## 目標・目標でないこと

- 目標: 区画のある土地では、契約・建売・契約以降の注文住宅が必ずどれかの区画につながっている
- 目標: #21 に区画を足したとき、その区画は契約につながり、契約を消せば「販売中」に戻る
- 目標でない: 区画を足したあとで区画の表のステータスを手で変える道（紐付けがあれば取られたままなので害は無い）
- 目標でない: 本番のデータを書き換えること（#21 は区画 0 のまま。区画を足したときにつながる）

## 案（利用者が A を選んだ・2026-11-22）

| 案 | 中身 | 選ばなかった理由 |
|---|---|---|
| **A（選んだ）自動でつなぐ** | 区画を選んでいないものが 1 件なら、足す区画を自動でそれにつなぐ。2 件以上なら追加のフォームでどれにつなぐか選ぶ | — |
| B フォームでいつも選ぶ | 追加のフォームに「この区画に紐づける」の欄（1 件なら選んだ状態） | 「つながない」を選ぶと同じ穴が残り、別の歯止めが要る。手間が増える |
| C つながず、新しい契約を止める | 区画を選んでいないものが残る土地では新しい契約・建売を断り、契約の編集で区画を選ぶよう案内する | 建売・注文住宅にはつなぐ手段が無い。#21 は「販売中」に見えるのに断られる |

## 決まり

1. 区画を足すとき、その土地に区画を選んでいないものがあれば、足す区画にそのうち 1 つをつなぐ。
   - 1 件 → 自動でつなぐ。追加のフォームには「この区画は 契約「…」 に紐づけます」と出す
   - 2 件以上 → 追加のフォームの選択欄でどれにつなぐか選ぶ（必須。「つながない」は無い）
   - 区画を足すたびに 1 つずつつなぐので、区画が足りれば全部つながる。つながっていないものが残るあいだ、空いている区画はできない
2. つないだ区画のステータスは、つないだものに合わせる（サーバーが決める。フォームのステータスの欄は出さない）
   - 不動産の契約・契約のある建売・契約以降の注文住宅 → 成約
   - 契約の無い建売 → 販売中（建売の契約を登録したときに成約になる。今の動きと同じ）
3. 登録したときの文: 「区画を登録しました（契約「…」をこの区画に紐づけました）。」（名前の形は削除の歯止めと同じ `DeletionBlockers::assemble()`）
4. 区画を選んでいないものが無い土地のフォームは今のまま。ステータスの初期値は「販売中」
   （`ReProcurement::defaultLotStatus()` は要らなくなる。区画 0 の土地で成約を返すのは、区画を選んでいないものがあるときだけだったため）
5. 画面を開いたあとで顔ぶれが変わったら（ほかの画面で契約を消した・区画を選んだ・新しく作った など）、何も保存せず区画の欄に理由を出す。開き直して選び直してもらう
6. つなぐときに書くのは、契約・建売・注文住宅の区画の列だけ。土地原価・契約の原価・更新者・ステータスは変えない
7. （こちらの判断）区画のある土地で、区画を選んでいない見積りの注文住宅を「契約」へ進めるのを断る（一覧の小窓と編集画面）。
   理由: 進めると「区画を選んでいない契約以降の注文住宅」が新しくでき、同じ穴が開く。今は区画を選ばずに保存できる決まり（`requiresLot()` の #21 の形の例外）が、
   「契約」へ進める保存にも効いている。編集画面で区画を選べば進められる。本番で仕入れ案件を土地元にした注文住宅は 0 件

## つないだあとの動き（今の決まりのまま）

- 契約を消す → その区画は「販売中」・土地は区画から集約して「販売中」
- 契約の編集で区画を選び直す → 旧の区画は「販売中」・新の区画は「成約」
- つないだ区画は削除できない（紐づいているものがある区画の削除の歯止め）。外したいときは契約の編集で別の区画を選ぶ
- 2 区画以上の土地では、建売・注文住宅の土地原価の「今の計算値」が按分した額になり、編集画面に「保存されている値は…と違います」が出ることがある（保存値は変えない。Bug #143 の決まりのまま）

## 範囲外

- すでに区画があり、区画を選んでいないものも残っている土地（本番 0 件）の、空いている区画の扱い（次に区画を足したときにつながる）
- 区画の行の編集でつなぐこと（区画を足すときだけ）
- ほぼ同時の 2 つの保存（ロックは足さない。土地の区画を複数にした変更の決めたこと 10 のまま）

## 作る人に任せること

- 追加のフォームの見た目の細部（1 件のときの案内・2 件以上の選択欄・ステータスの欄の代わりの表示）
- 決まり 5 の判定の書き方と文
- 決まり 7 の断る文と、一覧の小窓・編集画面のどこで断るか
- テストの組み方
- 記録: `docs/RULES.md` に Bug の行を足す（本番に出ている形）・`CLAUDE.md` の件数・`docs/BACKLOG.md` に節と、土地の区画を複数にした節の「利用者に伝えること」の 1 つ目に → を書き足す
