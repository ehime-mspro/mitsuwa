# 原価管理の一覧入力（見込み額・確定額を表で入れる）— 設計書

- 日付: 2026-11-16
- 対象: 不動産の仕入れ案件・分譲地の原価管理（詳細画面と新規登録画面）
- モック: @docs/mockups/realestate/procurement-cost-grid.html（利用者が「モックの形で OK」と承認。2026-11-16）

## 1. なぜ作るのか

仕入れ案件の原価管理は、今は「＋ 費用追加」を押して 1 項目ずつ（項目を選ぶ → 見込み額 → 確定額 → 備考 → 追加）入れる。
1 案件あたり平均 8 行・多いと 14 行あり、毎回この操作を繰り返すのが手間になっている。

利用者の依頼は「Excel に入力するように、画面に一覧で出して金額を入力する」形にすること。
さらに利用者は「見込みと確定は別ボタンにしたい」と決めた（下の 4 章の案 A）。
見込み額は案件を検討するときにまとめて入れ、確定額は請求が来たときなどに後から入れるため、入れる時期が違う。

## 2. 今の作り

| 画面 | 今の動き |
|---|---|
| 仕入れ案件の詳細（`realestate/procurements/show.blade.php`） | 「＋ 費用追加」で 1 行ずつ Ajax で保存（`storeCost`）。行ごとの「編集」→「保存」（`updateCost`）。「削除」は経営層だけ（`destroyCost`・ルートが `role:executive`）。「📂 試算表 Excel 取込」（`bulkImportCosts`）あり |
| 分譲地の詳細（`realestate/projects/show.blade.php`） | 仕入れ案件と同じ形（`ProjectController` の同名のメソッド・同じ形のルート）。マークアップは仕入れ案件の写し |
| 新規登録（`realestate/_partials/_cost_section_form.blade.php`。仕入れ案件・分譲地で共用） | 同じ「＋ 費用追加」で行を足し、`costs[idx][...]` の hidden で登録ボタンと一緒に送る（`store()` が保存） |

- 原価の行: `re_procurement_costs` / `re_project_costs`（`cost_item_id`・`estimated_amount` 必須の整数・`actual_amount` 空欄可・`notes` 200 文字）。**(親, 費用項目) に一意の制約は無い**
- 費用項目のマスタ: `re_cost_items`（`sort_order` の順・`is_active`）
- 「物件購入費」の行は査定価格・購入価格から自動で入る（`syncPropertyPurchaseCost()`）。画面からは直せず、消せない
- 採用額（確定優先）= 確定額があれば確定額、無ければ見込み額

## 4. 考えた形（Approaches）

### 画面の形

| 案 | 中身 | 結果 |

### 詳細画面の保存の仕方（私の判断）

| 案 | 中身 | 結果 |
|---|---|---|
| まとめて保存する受け口を 1 本足す | 表の変更を 1 回の要求で送り、サーバーが 1 つのトランザクションで保存する | **採用**。1 行でも直すところがあれば何も保存しない（全部か無し）と言える |

## 5. 目標・やらないこと・失敗とみなすこと

- **目標**: 原価を Excel のように縦に並んだセルへ打てる。見込み額と確定額を別々の表で入れる。1 案件分をまとめて 1 回で保存できる
- **やらないこと**: 原価の行の作り（DB）を変える／費用項目のマスタを変える／試算表 Excel 取込の中身を変える／削除の権限を変える／見込み額・確定額以外の列（税など）を足す
- **失敗とみなすこと**（技術的に動いても）:
  - 保存した行が、利用者の気づかないうちに消える・書き換わる（例: 見込み額の表を保存しただけで確定額が消える、別の人の変更を黙って上書きする）
  - 管理者が、今は消せない保存済みの行を表から消せてしまう（⚠ 試算表 Excel 取込の「上書き」では、今も管理者が保存済みの行をまとめて消せる。この作業では変えない＝12 章）
  - 打ちかけの値が保存されずに消える（保存せずにページを離れるときの確認が無い）

   - 確定額の表にだけ「差額（確定 − 見込み）」の列を出す。見込みより高いと赤、低いと緑
   - Excel で列をコピーして 1 つのセルに貼り付けると、下の行へ順に入る（物件購入費の行は飛ばす）
   - 変えたセルを黄色にし、「保存していない変更 N 件」を出す。保存せずにページを離れようとしたら確かめる

5. 分譲地の詳細画面・新規登録画面も同じ形に変える
6. 試算表 Excel 取込は残す

## 7. 画面の動き（詳細画面）

### 7.1 ふだんの表示（見るだけの一覧）

- 今と同じ: 保存した行だけを並べる。列は 費用項目／見込み額／確定額（空なら「未定」）／備考／操作
- 操作の列: 物件購入費は「自動同期」、ほかの行は経営層にだけ「削除」（今の `destroyCost` をそのまま使う）。**「編集」は外す**
- 合計の行（見込み額・確定額・採用額合計）は今のまま
- カードの右上: 「📂 試算表 Excel 取込」「見込み額を入力」「確定額を入力」（管理者以上。今の「＋ 費用追加」と同じ権限）

### 7.2 入力の表（見込み額・確定額）

- 並べる行: マスタの順（`sort_order`）に、
  - その項目に保存済みの行があれば、その行（2 行以上あればそれぞれ 1 行ずつ。分譲地の「その他」2 行の 1 件のため）
  - 保存済みの行が無ければ、空の行を 1 つ
  - マスタで停止した項目（`is_active = 0`）は、保存済みの行があるときだけ出す（名前の横に「停止中」）
- 列:
  - 見込み額の表: 費用項目／見込み額（セル）／確定額（灰色の表示だけ）／備考（セル）
  - 確定額の表: 費用項目／見込み額（灰色の表示だけ。無ければ「—」）／確定額（セル・空なら「未定」）／差額（確定 − 見込み）／備考（セル）
- 物件購入費の行: どちらの表でも値の表示だけ。備考の欄に「査定価格・購入価格から自動で入ります」
- セル:
  - `inputmode="numeric"`（全角数字は既存の全体の仕組みで半角になる）。カンマ・空白・「円」を除いて読む。欄を離れるとカンマ付きに整える
  - Enter で下・Shift + Enter で上のセルへ（物件購入費の行は飛ばす）。上下の矢印キーも同じ。**日本語入力の確定の Enter では動かない**（`$event.isComposing ||`。Top trap #6）
  - 開いたときは最初の入力できるセルにカーソルを置く。セルに入ったら中身を選んだ状態にする
  - 貼り付け: 改行を含む文字を貼ると、そのセルから下へ 1 行に 1 つずつ入れる（Excel のタブ区切りは 1 列目だけ使う）。行が足りなければ残りは捨てる。**貼った列の空のセルは、その行を今の値のまま飛ばす**（私の判断。試算表の列に空きがあっても、保存済みの金額を貼り付けで消さないため。消すときはセルを手で空にする）。貼ったあとに「N 行に貼り付けました（空のセル M 個は今の値のまま）。まだ保存していません。」（M が 0 なら括弧を書かない）
  - 変えたセルは黄色。表の下に「保存していない変更 N 件」
- 合計の行: 入力中の値で計算し直す（確定額の表は差額の合計も）
- 表の下: 「取消」「見込み額を保存」（または「確定額を保存」）。取消は、変更があれば「保存していない変更が N 件あります。捨ててよいですか？」と確かめる
- 入力の表を開いているあいだは、カード右上の 3 つのボタンを隠す（2 つの表と Excel 取込を同時に開かない）
- 保存せずにページを離れようとしたら、ブラウザの確認を出す（`beforeunload`）

### 7.3 保存の決まり

送るのは**変えた行だけ**（金額か備考が変わった行）。サーバーは全部の行を確かめてから、1 つのトランザクションで保存する。1 行でも断るところがあれば何も保存しない。

見込み額の表（各行）:

| 見込み額のセル | 保存済みの行 | 結果 |
|---|---|---|
| 数 | 無い | 行を作る（確定額は空） |
| 数 | ある | 見込み額と備考を書き換える（確定額は触らない） |
| 空 | 無い | 何もしない。備考だけ書いてあれば断る（「見込み額を入力してください（備考だけでは保存できません）」） |
| 空 | ある・確定額あり | 断る（6 章の文） |
| 空 | ある・確定額なし | 経営層なら行を消す。それ以外は断る（6 章の文） |

確定額の表（各行）:

| 確定額のセル | 保存済みの行 | 結果 |
|---|---|---|
| 数 | 無い | 見込み額 0 円・この確定額で行を作る |
| 数 | ある | 確定額と備考を書き換える（見込み額は触らない） |
| 空 | 無い | 何もしない。備考だけ書いてあれば断る（「確定額を入力してください（備考だけでは保存できません）」） |
| 空 | ある | 確定額を空（未定）にする。備考も書き換える |

共通:

- 金額は 0 以上 `Controller::MAX_INT_COLUMN` 以下の整数（今と同じ。「2,147,483,647 以下で入力してください」）。数で読めなければ「金額は数字で入力してください」
- 備考は 200 文字まで（今と同じ）。前後の空白は落とす
- 物件購入費の行は送られても断る（今の `updateCost` と同じ理由）
- 送られた行の id は、その案件の行であること（今の `cost->procurement_id !== $procurement->id` と同じ確かめ）
- **ほかの人の変更を黙って上書きしない**（私の判断）: 送る行には、表を開いたときの値（見込み額・確定額・備考）も付ける。サーバーは今の DB の値と比べ、1 行でも違えば何も保存せずに「表を開いたあとで、ほかの人がこの原価を変えました。画面を開き直してから入れ直してください」で断る。保存済みの行が無い項目に行を作るときも、そのあいだに同じ項目の行ができていれば同じく断る
- **消える行があるときは、保存の前に確かめる**（私の判断。5 章の「気づかないうちに消える」を防ぐ）: 画面で行ごとの確かめが通り、消える行（見込み額の表で、保存済みの行を空にした行）が 1 件以上あれば、送る前に「次の N 件の行を削除します: 金利負担、その他。よろしいですか？」と項目名を挙げて確かめる。「キャンセル」なら何も送らず、表は開いたまま
- 断ったときは、どの行の何が悪いかを行ごとに返し、画面はその行を赤くして理由を出す。上に「保存できませんでした。赤い行を直してください（N 件）。何も保存していません。」
- 保存できたら、表を閉じて一覧を新しい内容にし、「見込み額を保存しました（追加 N 件・変更 N 件・削除 N 件）」（削除は 1 件以上のときだけ書く）。変更が 0 件なら「変更はありませんでした。」

### 7.4 権限

| 役割 | 見込み額・確定額を入力 | 保存済みの行を消す（見込み額を空にする・一覧の「削除」） |
|---|---|---|
| 経営層 | できる | できる |
| 管理者 | できる | できない（6 章の文で断る） |
| 一般担当 | ボタンを出さない・受け口もルートで断る | できない |

## 8. 新規登録画面

- 共用の部品（`_cost_section_form`）を同じ形に変える。仕入れ案件と分譲地の両方の新規登録が変わる
- 「📂 試算表 Excel 取込」「見込み額を入力」「確定額を入力」。表は 7.2 と同じ（物件購入費は出さない＝今と同じ。登録したあとに自動で入る）
- 表の下のボタンは「表を閉じる」（と「取消」）。サーバーには送らない。閉じると一覧に反映し、今と同じ `costs[idx][...]` の hidden に載る
- 新規登録では保存済みの行が無いので、権限の断りと削除の確かめは無い。見込み額を空にした行は一覧から外す。**ただし確定額が入っている行は、詳細画面と同じく「確定額が入っているので、見込み額は空にできません（0 は入れられます）」で断る**（私の判断。確定額を黙って捨てないため）。確定額だけ入れた行は見込み額 0 で載せる
- 一覧の行の「削除」は今どおり置く（まだ保存していない行を外すため）
- 入力の決まり（数・200 文字・備考だけの行）は 7.3 と同じ文を画面で出す。最後の確かめは今の `store()` の入力チェックのまま
- 入力エラーで戻ったときは今どおり `old('costs')` から一覧を戻す
- 表を開いたまま登録ボタンを押したとき: 開いている表の内容も一覧に入れてから送る、または表を閉じてから押すよう案内する — **どちらにするかはビルダーが決める**（打った値が黙って捨てられないこと）

## 11. 守る決まり（このプロジェクトの罠）

- `x-data` は名前付きの関数（Top trap #4）。Excel 取込の factory と合わせるときの `Object.assign` は getter を持つ側を先に（Top trap #8）
- 同じ要素で `style=` と `:style=` を並べない（Top trap #5）。`x-show` の要素の `:style` に `display` を書かない（Bug #32）
- 画面の JS に値を書くときは `Js::from` か `@json`（Bug #76。`JsEchoClassificationTest`）
- 自社への `fetch` には `X-Requested-With: XMLHttpRequest`（Top trap #9。保存は GET ではないが、そろえる）。`fetch` を持つビューは `AjaxErrorFeedbackTest` の分類に載せる
- 新しい入力チェックの項目には和名（Top trap #11。`JapaneseValidationMessagesTest`）。配列の形は `ShapeCheckingValidator` が見る
- 物件購入費の名前は `ReCostItem::PROPERTY_PURCHASE` を使う（直書きを増やさない）
