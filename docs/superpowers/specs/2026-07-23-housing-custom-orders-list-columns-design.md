# 注文住宅一覧 — 金額列（建物 / 土地）追加 設計書

- 日付: 2026-07-23
- 対象画面: `/housing/custom-orders`（注文住宅一覧）
- モック: `docs/mockups/housing/custom-orders-index.html`（v1: レイアウト3案）
  / `docs/mockups/housing/custom-orders-index-v2.html`（v2: 案A確定後の列の詰め方3案）

---

## 1. 背景と目的

注文住宅一覧は現在「案件番号 / 進捗 / 案件名 / 顧客名 / 請負金額 / 詳細」の 6 列で、
金額は建物の請負金額 1 つしか出ていない。一覧の段階で採算（建物・土地それぞれの
販売・原価・粗利）を把握できるようにする。あわせて案件番号列を廃止する。

**追加入力・DB 変更は不要。** 表示する値はすべて `hs_custom_orders` の既存カラムと、
`HsCustomOrder` の既存ヘルパーメソッドから得られる。

## 3. 画面仕様

### 3.1 列定義（全 12 列）

ヘッダーは 2 段。「進捗 / 案件名 / 顧客名 / 詳細」は `rowspan=2`、
「建物」「土地」は `colspan=4` のグループ見出しとする。

| # | グループ | 列名 | 値のソース | 配置 |
|---|---------|------|-----------|------|
| 1 | — | 進捗 | `status`（バッジ＋ステップバーポップオーバー。**現状維持**） | 中央 |
| 2 | — | 案件名 | `order_name`（**リンク → `housing.custom-orders.show`**）＋ `address` をサブ行 | 左 |
| 3 | — | 顧客名 | `customer_name` | 中央 |
| 4 | 建物 | 販売金額 | `building_contract_price`（税抜・主）＋ 税込をサブ行 | 右 |
| 5 | 建物 | 原価額 | `building_cost` | 右 |
| 6 | 建物 | 粗利額 | `getBuildingProfit()` | 右 |
| 7 | 建物 | 粗利率 | `getBuildingProfitRate()` | 右 |
| 8 | 土地 | 販売金額 | `land_selling_price` | 右 |
| 9 | 土地 | 原価額 | `land_cost` | 右 |
| 10 | 土地 | 粗利額 | `getLandProfit()` | 右 |
| 11 | 土地 | 粗利率 | `getLandProfitRate()` | 右 |
| 12 | — | 詳細 | 詳細ボタン（**現状維持**） | 中央 |

グループ見出しには消費税の扱いを添える:
建物 = 「建　物」＋小さく「消費税 10%」（`tax_rate` の値を出す）、
土地 = 「土　地」＋小さく「消費税 非課税」。

行ごとに「非課税」を繰り返さないための措置。

### 3.2 消費税

**課税されるのは建物のみ。土地は非課税**（詳細画面の収支サマリーでも土地の消費税欄は
「—」、税込価格＝販売価格になっている）。

- 消費税額 = `getBuildingTax()` = `round(building_contract_price × tax_rate ÷ 100)`
- 税込 = `building_contract_price + getBuildingTax()`
- `tax_rate` は案件ごとに保存される値（既定はシステム設定 `tax_rate`、現在 10.00）。
  将来税率が変わっても過去案件は当時の税率で計算される。
- `building_contract_price` が null のときは税込サブ行ごと出さない
  （`getBuildingTax()` は null 時 0 を返すため、ガードしないと「税込 0円」が出る）。

### 3.3 粗利額・粗利率は税抜ベース

`getBuildingProfit()` = `building_contract_price − building_cost` で、**税抜のまま**。
消費税は預り金であり利益ではないため、税込を粗利計算に混ぜない。詳細画面と同じ計算。

### 3.4 土地 4 列のガード

**`isCompanyLand()` が false（お客様所有土地・土地未選択）の場合、土地の 4 セルすべてを
「—」にする。** 生カラム `land_selling_price` / `land_cost` だけを見て表示しない。

理由: `getLandProfit()` / `getLandProfitRate()` は `isCompanyLand()` が false なら
無条件に null を返す。生カラムに値が残っている行があると「販売金額と原価額は出るのに
粗利だけ —」という読めない行になる。保存時には `clearLandFieldsForCustomerLand()` が
クリアしているはずだが、表示側でも土地種別を単一の判断軸にして不整合を作らない。

### 3.5 表示ルール

| 対象 | ルール |
|------|--------|
| 金額 | `number_format()` ＋ 末尾「円」、税抜（CLAUDE.md 規約） |
| 金額が null | `—`（`text-gray-300` 相当のグレー） |
| 粗利額・粗利率が 0 以上 | `color: #047857; font-weight: 700`（CLAUDE.md 規約。詳細画面と一致） |
| 粗利額・粗利率が負 | `color: #dc2626; font-weight: 700` |
| 粗利率のフォーマット | `number_format($rate, 1) . '%'` → **常に小数 1 桁**（`25.0%`） |
| 税込サブ行 | 11px・グレー・「税込 31,350,000円」 |
| 数値列 | すべて右揃え |

**⚠ 粗利率のフォーマットは既存画面から意図的に分岐する。**
既存の建売一覧・注文住宅詳細は `{{ $rate }}%` と書いており、`round(25.0, 1)` が
文字列化で `"25"` になるため `25%` と表示される（小数が出たり出なかったりする）。
今回は右揃えの率列が 2 つ並ぶため、桁を揃えたほうが読みやすい。既存画面を
合わせるかどうかは本件のスコープ外とする。

### 3.6 横幅

必要幅は実測 **1187px**。サイドバー込みの実画面フレームで計測した結果:

| モニタ幅 | 表に使える幅 | 結果 |
|---------|-------------|------|
| 1280px | 992px | 195px ぶん横スクロール |
| **1440px** | **1152px** | **35px ぶん横スクロール**（「詳細」列が切れる） |
| 1600px | 1312px | 横スクロールなしで収まる |

既存ビューの `<div style="overflow-x: auto;">` ラッパーがそのまま効くため、追加対応は不要。
1440px でもサイドバーを折りたためば収まる。

ユーザーはこのトレードオフを了解のうえ A-2 を選択している。
収めたくなった場合は A-1（粗利率をセル内併記・必要幅 1057px）へ戻せる。

### 3.7 ステップバーポップオーバー

進捗バッジのポップオーバーは `position: fixed` で、
`window.addEventListener('scroll', closePopover, true)`（キャプチャフェーズ）により
**横スクロールでも閉じる**。現状の実装のままで破綻しない。

### 3.8 案件番号の扱い

- **列としては削除する。**
- ただし進捗バッジの `data-code="{{ $ord->order_code }}"` 属性には**残る**
  （ステータス変更の確認ダイアログ「CO-2026-0005 のステータスを…」で使うため）。
  → HTML 全体からは `order_code` が消えないので、テストで
  `assertDontSee($order->order_code)` と書くと**必ず失敗する**。
- キーワード検索は `order_code` を対象に含めたまま。検索窓のプレースホルダ
  「案件番号・案件名・顧客名・住所」も変更しない。

### 3.9 空状態

`@empty` 行の `colspan` を **6 → 12** に変更する。

## 4. データ取得

**Controller・Model の変更は不要。追加クエリは発生しない。**

表示に使う値はすべて行自身のカラムか、行のカラムだけで完結する既存メソッド

`getLandProfit` / `getLandProfitRate` / `isCompanyLand`）から得られる。
リレーションを辿るメソッド（`getLandSourceDisplay()` 等）は使わない。

## 6. テスト方針

新規 `tests/Feature/Housing/CustomOrderIndexListColumnsTest.php`。
既存の `CustomOrderIndexFilterTest` は `order_name` でアサートしており**変更不要**。

テストスキーマ（`Tests\Concerns\CreatesRealEstateSchema`）には
`building_contract_price` / `building_cost` / `land_selling_price` / `land_cost` /
`tax_rate`(default 10.00) / `land_source_type` がすべて定義済みであることを確認済み。

| # | 検証内容 |
|---|---------|
| 1 | 列ヘッダー「案件番号」が消えている（`<th>` の生 HTML で判定。`assertDontSee($order->order_code)` は 3.8 の理由で使わない） |
| 2 | 2 段ヘッダーのグループ見出し「建物」「土地」が `colspan="4"` で出る |
| 3 | 自社土地の案件で、建物の 税抜 / 税込 / 原価 / 粗利 / 粗利率 が出る |
| 4 | 同じ行で土地の 販売 / 原価 / 粗利 / 粗利率 が出る |
| 5 | お客様所有土地の案件で、土地の 4 値が出ない（金額文字列を `assertDontSee`）。建物側は出る |
| 6 | 金額 null の案件で「税込 0円」が出ない（3.2 のガード） |
| 7 | 粗利が負の案件で `#dc2626` が付く／正なら `#047857` |
| 8 | 粗利率が `25.0%` 形式（常に小数 1 桁）で出る |
| 9 | 案件名が `housing.custom-orders.show` への `<a href>` になっている |

**⚠ `assertSee` の false-pass に注意。** 説明文・プレースホルダ・別の列の値に
偶然一致して通ってしまうため、金額はカンマ入りの完全な文字列で、
構造は生 HTML（`escape: false`）で判定する。

## 7. スコープ外

| 項目 | 理由 |
|------|------|
| 詳細画面の収支サマリーを「建物 → 土地」順に揃える | 一覧と詳細で順序が逆になる点はユーザーに報告済み。別途相談とする |
| 合計（建物＋土地）列 | 今回の依頼に含まれない。詳細画面に既にある |
| 建売一覧・注文住宅詳細の粗利率フォーマット統一 | 3.5 の分岐を既存画面へ波及させない |
| `index()` の未使用 eager load `with(['projectLot.project', 'procurement'])` の除去 | 本件と無関係な変更。触らない |
| 検索窓のプレースホルダ文言 | 案件番号検索は維持するため変更不要 |
